
# 目标
对前后端对象进行数据化，要求
- 建模
- 可计算
- 为后续测试服务

# 基本概念：

1. **状态**：可以稳定存在的数据
2. **事件**：由**操作**+**对象**组成的单次行为
3. **操作**：单次动作
4. **对象**：任意前端组件
5. **事务**：由**状态**+**事件**得到新的**状态**的完整流程
6. **触发源**：能触发状态变换的源头，包括主动触发源（用户触发，比如点击按钮），被动触发源（程序触发，比如用户点击按钮后，前端发送请求给后端）

# 原则：
1. 事件原子原则：一次明确的行为，包括操作+对象，整体算作一次事件。
```
点击 + 评论按钮
输入 + 评论输入框
请求 + 登录接口
修改 + 用户权限
```
2. 事务完整性原则：由一个状态，通过事件，到新状态的流程，整体算作一次事务。
```
用户点击发送评论按钮
 -> 前端发送请求
 -> 后端处理评论
 -> 数据库写入评论
 -> 后端返回结果
 -> 前端刷新评论列表
 -> 系统进入稳定状态
```
3. 全局状态数据化原则：状态应该包含全局的状态，若全局状态数据过多，应至少包含哪些模块的数据发生了变化，以及变化的内容。
4. 1+1=2原则：状态1+事件得到状态2，事件由操作和对象组成。
5. 对象存在原则：事件中的对象，必须是当前状态中存在的，可以进行交互的组件
