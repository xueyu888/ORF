
# 目标: 

UI状态路径感知
状态识别和记录

> 可以参考 Crawljax 这类状态图爬虫

前端抽象: 
Web应用本质是一个UI状态机

基础状态S0 -> 操作A0 -> 状态S1 -> 操作A1 -> 状态S2 -> 操作A2 -> 状态S3

核心闭环: 
```
当前状态
  -> 发现候选交互元素
  -> 生成候选动作
  -> 选择一个动作
  -> 执行动作
  -> 等待页面稳定
  -> 抽象新状态
  -> 更新状态图
  -> 继续探索
```

# 基础概念
**路径**: 由某个状态通过n个操作到另一个状态的完整流程
**感知**: 获取当前前端中存在哪些可互动组件
**状态**: 针对前端界面的UI的状态，后面需要详细定义如何判断两个状态是否相同（重要）
**初始状态**: 运行程序后，进入到前端的默认状态。
**记录**: 每次操作，都需要记录当前状态，执行的操作，以及操作后的状态，以及是否成功等信息。
**随机种子**: 由种子进行随机
**事件**: [数据化V2.md](../数据化V2.md)

# 执行流程
1. 测试准备: 运行前后端和环境，达到**初始状态**
2. **感知**: 获取当前前端中存在哪些可互动组件，并对组件进行分类
3. 随机选择组件: 根据**随机种子**，随机选择一个组件，作为被操作的对象
4. 随机选择操作: 根据组件类别、操作建模随机生成一个操作
5. 执行动作: 在当前状态，根据随机选择的组件和操作执行动作
6. 等待页面稳定: 
7. 记录当前状态
8. 判定当前状态是否已存在
9. 更新状态图
10. 跳转到`2. 感知`步骤
