## 1. 测试目标

验证：在系统已经存在可评论计划数据的基准状态下，已登录的 ORF 管理员可以在计划页面打开挑战树中任意一个自己可见目标的评论窗口，并新增一条外层评论；评论会立即显示在评论窗口中，并持久化到后端评论数据表，重新从计划页数据接口读取时仍能看到该评论。

边界：

- 本用例只验证计划页面目标的外层评论新增；评论目标必须是 `objective`，不覆盖指标 `result`、任务 `task` 或子任务 `subtask`。
- 本用例不验证回复、编辑、删除、解决状态、跨用户协作或越权管理。
- 本用例的 B 必须已经具备可评论的计划数据；Setup 不负责构造或重建目标、指标、行动项等业务计划数据。
- 本用例的 Action 只包含提交一条新评论，不包含登录、构造计划数据、清理评论或清理测试用户。

## 2. 状态模型

- B：测试开始前和 Clean 后都必须满足的基准状态。该状态不是空系统，而是已经允许目标评论功能开测的稳定业务状态：测试管理员、登录凭据和至少一个当前用户可见的目标都已存在，但当前浏览器未登录，且本用例评论数据不存在。
  - [api] 前端和后端服务已正常启动，健康检查或等价探测通过。
  - [prisma] ORF 数据库连接正常，schema 已迁移到当前测试版本。
  - [api] Ory/Kratos 服务可访问，Admin/Public API 对测试环境可用。
  - [api] Ory/Kratos 中已存在本用例使用的测试身份，并具备可用密码凭据。
  - [prisma] ORF 中已存在本用例使用的测试用户和 `team_members` 记录，用户状态为可登录状态，角色为 `admin`。
  - [prisma] 测试用户所属团队已存在，且该团队中存在至少一个当前测试管理员可见的目标。
  - [api] 使用测试管理员身份查询 `GET /api/my-challenges?scope=all` 时，返回的 `objectives` 中至少有一个标题非空、可作为评论目标的目标对象。
  - [prisma] 不存在本用例独占评论数据，例如 `comment_messages.body` 以 `E2E-PLAN-COMMENT:` 开头。
  - [api] `/api/auth/session` 返回 `authenticated: false`。
  - [playwright] 当前浏览器上下文不存在 `orf_ory_session` cookie。
  - [playwright] localStorage/sessionStorage 不包含登录态。

- Setup：如何从 B 构造 S0？
  - [playwright] 创建全新的浏览器上下文，或清空当前上下文的 cookies/localStorage/sessionStorage。
  - [playwright] 打开 `/auth`，使用 B 中已经存在的测试管理员邮箱和密码登录。
  - [playwright] 登录成功后打开 `/tasks`。
  - [api] 读取 `GET /api/my-challenges?scope=all`，从返回的 `objectives` 中选择一个标题非空的可见目标并记录为 `runtime.commentTarget`；`runtime.commentTarget.type` 固定为 `objective`，不依赖固定标题或固定 ID。
  - [playwright] 在计划页挑战树中定位 `runtime.commentTarget.title` 对应的目标行，通过目标行块菜单点击 `评论`，打开该目标的评论窗口。

- S0：Action 前必须满足什么条件？用于确认 Setup 成功。
  - [api] `/api/auth/session` 返回 `authenticated: true`，且用户角色为 `admin`。
  - [api] `GET /api/my-challenges?scope=all` 返回 `runtime.commentTarget` 对应的目标对象。
  - [playwright] `page` URL 为 `/tasks`。
  - [playwright] 计划页面中 `runtime.commentTarget.title` 对应的目标行可见。
  - [playwright] 评论窗口可见，窗口标题与 `runtime.commentTarget.title` 一致。
  - [playwright] 评论输入框可见，placeholder 为 `添加评论...`。
  - [playwright] `page.getByRole("button", { name: "发送评论" })` 存在且在输入为空时不可点击。
  - [prisma] `comment_threads` 和 `comment_messages` 中不存在本用例的测试评论正文。

- Action：本次测试唯一要验证的业务动作是什么？
  - [playwright] 在评论输入框中输入 `E2E-PLAN-COMMENT: 需要补充边界样例覆盖情况`。
  - [playwright] 点击 `page.getByRole("button", { name: "发送评论" })` 提交评论，或在输入框中使用 `Ctrl / Cmd + Enter` 提交。

- S1：Action 后系统应该变成什么状态？用于确认业务动作正确。
  - [api] `POST /api/comments` 响应成功，返回 `ok: true`，且 `commentThread.targetType`、`commentThread.targetId`、`commentThread.targetTitle` 与 `runtime.commentTarget` 一致。
  - [playwright] 评论窗口中显示当前测试管理员名称。
  - [playwright] 评论窗口中显示正文 `E2E-PLAN-COMMENT: 需要补充边界样例覆盖情况`。
  - [playwright] 评论输入框提交后清空，并回到默认 `添加评论...` 状态。
  - [playwright] 关闭评论窗口后，计划页面该目标显示评论数量入口；再次打开后仍能看到该评论。
  - [api] `GET /api/my-challenges?scope=all` 返回 `runtime.commentTarget` 对应的评论线程，线程包含一条 `parentMessageId` 为空的消息，消息作者和正文符合测试数据。
  - [prisma] `comment_threads` 中存在一条 `status = "open"`、`target_type = "objective"`、`target_id` 与 `runtime.commentTarget.id` 一致的线程。
  - [prisma] `comment_messages` 中存在一条关联该线程的消息，`author_user_id` 为当前测试用户，`body` 为 `E2E-PLAN-COMMENT: 需要补充边界样例覆盖情况`，`parent_message_id`、`reply_to_message_id`、`reply_to_author` 均为空。

- Clean：如何清理并恢复到 B？
  - [prisma] 删除 `comment_messages.body` 以 `E2E-PLAN-COMMENT:` 开头的测试消息。
  - [prisma] 若删除消息后对应测试评论线程已无消息，删除 `runtime.commentTarget` 对应的空评论线程。
  - [playwright] 若评论窗口仍打开，点击 `关闭评论窗口`。
  - [api] 在当前浏览器上下文中调用 `/api/auth/logout`，撤销本次登录产生的 Ory session。
  - [playwright] 清空当前浏览器上下文的 cookies/localStorage/sessionStorage。
  - [prisma] 确认 B 中用于开测的可见目标数据、测试管理员和成员关系仍然存在；Clean 不删除这些基准测试数据。
  - [api] 确认测试 Ory 身份仍然存在；Clean 不删除该 B 状态身份。
