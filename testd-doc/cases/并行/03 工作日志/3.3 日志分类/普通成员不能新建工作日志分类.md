# 普通成员不能新建工作日志分类

## 1. 测试目标

验证：角色为 `member`、状态为 `active` 的普通成员进入工作日志页面后，不能在 "日志归类" 控件中新建工作日志分类；普通成员直接提交带新分类名称的当天工作日志保存请求时，后端应拒绝保存，且页面、接口数据和数据库数据均不产生本次新分类工作日志或新的工作日志分类。

## 2. 状态-动作模型

- B：基准状态。
  - [B-1] [api] 前端服务 应可用。
  - [B-2] [api] 后端服务 应可用。
  - [B-3] [prisma] ORF 数据库 应可连接。
  - [B-4] [api] 当前会话 应为 未登录。
  - [B-5] [playwright] 当前浏览器 应不保留本地登录态。

- Setup：构造 S0。
  - [Setup-1] [prisma] 删除 本用例残留的工作日志正文标记 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 对应的工作日志。
  - [Setup-2] [prisma] 删除 本用例残留的工作日志分类 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`。
  - [Setup-3] [api] 准备邮箱为 `orf-member-new-category-work-log-e2e@orf.local`、使用固定测试密码的成员登录身份。
  - [Setup-4] [prisma] 准备 角色为 `member`、状态为 `active`、名称为 `ORF Member New Category Work Log E2E` 的本用例成员用户。
  - [Setup-5] [playwright] 使用 本用例成员账号 登录 ORF。
  - [Setup-6] [playwright] 打开 工作日志页面的当天日志视图。

- S0：Action 前状态。
  - [S0-1] [api] 当前会话 应为 已登录。
  - [S0-2] [api] 当前会话用户邮箱 应为 `orf-member-new-category-work-log-e2e@orf.local`。
  - [S0-3] [api] 当前会话用户角色 应为 `member`。
  - [S0-4] [api] 当前会话用户状态 应为 `active`。
  - [S0-5] [api] 当前会话用户名称 应为 `ORF Member New Category Work Log E2E`。
  - [S0-6] [api] 工作日志可选分类 应包含内置分类 `请假`。
  - [S0-7] [api] 工作日志可选分类 应不包含分类 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`。
  - [S0-8] [api] 当天工作日志数据 应不包含正文标记 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY`。
  - [S0-9] [prisma] 应不存在 本用例成员在测试执行当天提交的正文标记为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 的工作日志。
  - [S0-10] [prisma] 应不存在 名称为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN` 的工作日志分类。
  - [S0-11] [playwright] 页面 应进入 工作日志。
  - [S0-12] [playwright] "日志" 视图 应处于选中状态。
  - [S0-13] [playwright] "我的日志" 面板 应可见。
  - [S0-14] [playwright] "日志归类" 控件 应可见。
  - [S0-15] [playwright] "提交日志" 操作 应不可点击。

- Action：被测业务动作。
  - [Action-1] [playwright] 打开 "日志归类" 控件。
  - [Action-2] [playwright] 在 "日志归类" 控件的搜索输入框输入 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`。
  - [Action-3] [api] 提交 带新分类名称 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`、正文标记为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 的当天工作日志保存请求。

- S1：Action 后状态。
  - [S1-1] [playwright] "日志归类" 控件的搜索结果 应不显示 "新建分类" 操作。
  - [S1-2] [playwright] "日志归类" 控件的搜索结果 应不显示新分类 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`。
  - [S1-3] [playwright] "新建日志分类名称" 输入框 应不可见。
  - [S1-4] [api] 当天工作日志保存请求结果状态 应为 `400`。
  - [S1-5] [api] 当天工作日志保存请求错误信息 应为 `当前账号不能使用该工作日志分类`。
  - [S1-6] [api] 当天工作日志数据 应不包含正文标记 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY`。
  - [S1-7] [prisma] 应不存在 本用例成员在测试执行当天提交的正文标记为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 的工作日志。
  - [S1-8] [prisma] 应不存在 名称为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN` 的工作日志分类。
  - [S1-9] [prisma] 应不存在 本用例成员在测试执行当天提交的分类名称快照为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN` 的工作日志。

- Clean：恢复 B。
  - [Clean-1] [prisma] 删除 本用例创建的工作日志正文标记 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 对应的工作日志。
  - [Clean-2] [prisma] 删除 本用例创建的工作日志分类 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN`。
  - [Clean-3] [api] 注销当前成员登录会话。
  - [Clean-4] [playwright] 移除当前浏览器中的残留登录态。
  - [Clean-5] [api] 删除 本用例成员登录身份。
  - [Clean-6] [prisma] 删除 本用例成员用户。
  - [Clean-7] [prisma] 应不存在 正文标记为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN-BODY` 的工作日志。
  - [Clean-8] [prisma] 应不存在 名称为 `E2E-WORK-LOG-NEW-CATEGORY-FORBIDDEN` 的工作日志分类。
  - [Clean-9] [api] 邮箱为 `orf-member-new-category-work-log-e2e@orf.local` 的成员登录身份 应不存在。
  - [Clean-10] [prisma] 邮箱为 `orf-member-new-category-work-log-e2e@orf.local` 的成员用户 应不存在。
  - [Clean-11] [api] 当前会话 应为 未登录。
