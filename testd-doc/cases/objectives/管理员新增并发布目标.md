## 1. 测试目标

验证：预置 ORF 管理员可以从全局 `新建目标` 入口进入挑战工作台，在目标树中创建一个独占候选目标；该目标创建后可以出现在所有挑战视图中，可以点击 `发布`，在挑战工作台显示为 `可申请`，并进入悬赏大厅的可申请目标列表。

边界：

- 本用例只验证管理员新增目标并发布到悬赏大厅，不验证新增指标、行动项、挑战申请、征召、重估、冻结、提交战利品、验收或结算。
- 本用例使用预置管理员账号 `zrx831@gmail.com`，密码为 `123123123`，角色为 `admin`，状态为 `active`。
- 本用例使用独占测试目标标题，例如 `E2E-OBJECTIVE-PUBLISH: 管理员发布目标`；B 和 Clean 都必须保证不存在该测试目标。
- 新建目标只通过页面填写目标标题；`whyItMatters`、`boundary`、`cycle`、`finalDueAt` 等创建接口必填字段由当前页面创建流程填充默认值。
- 发布后的目标可以没有指标；悬赏大厅可见性不依赖目标下是否已经存在 `Result`。
- 本用例的 Action 是“创建一个候选目标并发布该目标”这一完整业务动作；登录、打开页面、清理残留和删除测试目标不属于 Action。

## 2. 状态模型

- B：测试开始前和 Clean 后都必须满足的基准状态。该状态用于确认基础环境可用、预置管理员可登录、当前浏览器未登录，且本用例独占测试目标不存在。
  - [api] 前端和后端服务已正常启动，健康检查或等价探测通过。
  - [prisma] ORF 数据库连接正常，schema 已迁移到当前测试版本。
  - [api] Ory/Kratos 服务可访问，Admin/Public API 对测试环境可用。
  - [api] Ory/Kratos 中已存在管理员测试身份 `zrx831@gmail.com`，并具备可用密码凭据。
  - [prisma] ORF 中已存在管理员用户和 `team_members` 记录，角色为 `admin`，状态为 `active`。
  - [prisma] `objectives.title` 不存在 `E2E-OBJECTIVE-PUBLISH: 管理员发布目标`。
  - [api] `/api/auth/session` 返回 `authenticated: false`。
  - [playwright] 当前浏览器上下文不存在 `orf_ory_session` cookie。
  - [playwright] localStorage/sessionStorage 不包含登录态。
  - [playwright] 访问受保护入口 `/tasks` 会回到 `/auth`。

- Action：本次测试唯一要验证的业务动作是什么？
  - [playwright] 点击顶部栏 `新建目标`，进入 `/tasks?create=objective` 触发的页面内创建流程。
  - [playwright] 确认挑战树中出现完整目标草稿面板，目标标题输入框获得焦点，空指标区显示 `待定义指标`，空行动项区显示 `待创建行动项`。

  - [playwright] 在按 Enter 或输入框失焦提交标题前注册 `POST /api/objectives` 响应捕获。
  - [playwright] 按 Enter，或让标题输入框失焦，提交候选目标创建。
  - [api] 记录 `POST /api/objectives` 返回的目标为 `runtime.createdObjective`。
  - [playwright] 等待真实目标连续替换草稿，目标行标题保持为 `E2E-OBJECTIVE-PUBLISH: 管理员发布目标`，目标状态显示 `候选中`，并出现 `发布` 按钮。

  - [playwright] 点击该目标行的 `发布`。
