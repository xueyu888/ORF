# 成员提交匿名互评-管理员和非参与成员不可互评

## 1. 测试目标

验证：本用例独占的待验收目标已具备提交匿名互评条件时，管理员在挑战工作台看不到该目标的提交匿名互评入口；非参与成员进入挑战工作台后看不到该目标，也看不到提交匿名互评入口；页面、接口和数据库均不会产生本用例无互评权限用户匿名互评记录。

边界：

- 覆盖对象：管理员不可提交匿名互评，非参与成员不可提交匿名互评。
- 不覆盖对象：挑战成员提交匿名互评、非已验收状态不可互评、管理员验收、贡献分歧处理、分数结算。
- 依赖对象：[成员提交匿名互评](成员提交匿名互评.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体管理员账号、普通成员账号、目标、战利品或匿名互评记录。
- Setup 产物：邮箱为 `orf-admin-peer-review-permission-forbidden-e2e@orf.local` 的管理员身份、用户和 admin 成员关系；邮箱为 `orf-member-peer-review-permission-forbidden-e2e@orf.local` 的非参与成员身份、用户和 member 成员关系；标题为 `E2E-PEER-REVIEW-PERMISSION-FORBIDDEN: 待验收目标`、流转状态为 `submitted`、阶段为 `goalFrozen`、战利品提交时间已存在且挑战者仅包含 `ORF Peer Review Permission Challenger E2E` 和 `ORF Peer Review Permission Collaborator E2E` 的本用例权限边界互评目标；内容为 `E2E-PEER-REVIEW-PERMISSION-FORBIDDEN-LOOT: 前置战利品` 的前置战利品；管理员已登录会话。
- Action 产物：非参与成员已登录并进入挑战工作台后的页面状态。
- Clean 产物：删除本用例权限边界互评目标、前置战利品、匿名互评残留、管理员身份、非参与成员身份、用户、成员关系与 session。
- 原状态恢复：目标、战利品和账号均为当前用例独占资源，Clean 直接删除，不恢复任何共享目标状态。
