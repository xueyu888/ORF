# 成员提交战利品-管理员和非挑战成员不可提交

## 1. 测试目标

验证：本用例独占的实施阶段目标已具备提交战利品条件时，管理员在挑战工作台看不到该目标的提交战利品入口；非挑战成员进入挑战工作台后看不到该目标，也看不到提交战利品入口；页面、接口和数据库均不会产生本用例测试战利品。

边界：

- 覆盖对象：管理员不可提交战利品，非挑战成员不可提交战利品。
- 不覆盖对象：挑战成员提交战利品、发布阶段不可提交、评估阶段不可提交、匿名互评、管理员验收、分数结算。
- 依赖对象：[成员提交战利品](成员提交战利品.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体管理员账号、普通成员账号、目标、指标或战利品。
- Setup 产物：邮箱为 `orf-admin-loot-permission-forbidden-e2e@orf.local` 的管理员身份、用户和 admin 成员关系；邮箱为 `orf-member-loot-permission-forbidden-e2e@orf.local` 的非挑战成员身份、用户和 member 成员关系；标题为 `E2E-LOOT-PERMISSION-FORBIDDEN: 实施阶段目标`、流转状态为 `frozen`、阶段为 `goalFrozen`、冻结确认时间已存在且挑战者仅包含 `ORF Loot Permission Challenger E2E` 的本用例权限边界目标；标题为 `E2E-LOOT-PERMISSION-FORBIDDEN: 前置指标` 的前置指标；管理员已登录会话。
- Action 产物：非挑战成员已登录并进入挑战工作台后的页面状态。
- Clean 产物：删除本用例权限边界目标、前置指标、战利品残留、管理员身份、非挑战成员身份、用户、成员关系与 session。
- 原状态恢复：目标、指标和账号均为当前用例独占资源，Clean 直接删除，不恢复任何共享目标状态。
