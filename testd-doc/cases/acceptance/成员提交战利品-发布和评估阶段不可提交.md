# 成员提交战利品-发布和评估阶段不可提交

## 1. 测试目标

验证：当前普通成员是本用例目标挑战者时，发布阶段目标和评估阶段目标会显示在挑战工作台中，但前端不提供提交战利品入口；页面、接口和数据库均不会产生本用例测试战利品。

边界：

- 覆盖对象：发布阶段不可提交战利品，评估阶段不可提交战利品。
- 不覆盖对象：实施阶段提交战利品、管理员不可提交、非挑战成员不可提交、匿名互评、管理员验收、分数结算。
- 依赖对象：[成员提交战利品](成员提交战利品.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体普通成员账号、目标、指标或战利品。
- Setup 产物：邮箱为 `orf-member-loot-stage-forbidden-e2e@orf.local` 的普通成员身份、用户和 member 成员关系；标题为 `E2E-LOOT-STAGE-FORBIDDEN: 发布阶段目标`、流转状态为 `open`、阶段为 `resultClaiming`、冻结确认时间为空且挑战者仅包含当前普通成员的本用例发布阶段目标；标题为 `E2E-LOOT-STAGE-FORBIDDEN: 评估阶段目标`、流转状态为 `reestimating`、阶段为 `orfReestimate`、冻结确认时间为空且挑战者仅包含当前普通成员的本用例评估阶段目标；两个目标各自存在一个前置指标；普通成员已登录会话。
- Action 产物：普通成员进入挑战工作台后的页面状态。
- Clean 产物：删除本用例发布阶段目标、评估阶段目标、两个前置指标、战利品残留、普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标、指标和账号均为当前用例独占资源，Clean 直接删除，不恢复任何共享目标状态。
