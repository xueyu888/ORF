# 用户增加行动项和子行动项

## 1. 测试目标

验证：由当前用例独占准备的管理员和普通成员都可以在当前用例独占目标的重估阶段新增行动项，并在各自新增的行动项下新增子行动项；新增后，行动项和子行动项在页面中可见，且接口返回和数据库记录与页面结果一致。

边界：

- 覆盖对象：管理员新增行动项和子行动项；账号身份参与目标且有当前阶段权限的普通成员新增行动项和子行动项。
- 不覆盖对象：无权限用户不可新增、行动项编辑、行动项删除、子行动项编辑、子行动项删除、排序、完成状态切换。
- 原 legacy B 依赖：预置普通成员账号 `orf-member-e2e@orf.local`，以及默认团队中任意可改造为成员新增行动项起点的共享目标。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体管理员账号、普通成员账号、目标、行动项或子行动项。
- Setup 产物：以 "orf-admin-create-task-e2e@orf.local" 为基准并按本次运行作用域化的管理员身份、用户和 admin 成员关系；以 "orf-member-create-task-e2e@orf.local" 为基准并按本次运行作用域化的普通成员身份、用户和 member 成员关系；标题为 "E2E-USER-CREATE-TASK: 目标前置"、`flowStatus` 为 `reestimating` 且挑战者账号身份包含该成员的本用例行动项目标；运行时记录的 `runtime.taskTarget`。
- Action 产物：标题为 "E2E-TASK-CREATE: 管理员增加行动项"、说明为系统默认说明、执行人为本用例管理员的管理员测试行动项；标签为 "管理员子任务" 的管理员测试子行动项；标题为 "E2E-TASK-CREATE: 成员增加行动项"、说明为系统默认说明、执行人为本用例普通成员的成员测试行动项；标签为 "成员子任务" 的成员测试子行动项。
- Clean 产物：删除本用例行动项、子行动项、目标及其派生数据，删除本次运行作用域化后的本用例独占管理员和普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标、行动项和子行动项均为当前用例独占资源，Clean 直接删除，不恢复任何共享目标状态。
