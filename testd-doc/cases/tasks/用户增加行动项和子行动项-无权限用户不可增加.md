# 用户增加行动项和子行动项-无权限用户不可增加

## 1. 测试目标

验证：当前普通成员不是本用例目标挑战者时，当前普通成员进入挑战工作台后看不到本用例目标，也看不到本用例目标的新增行动项入口和新增子行动项入口；页面、接口和数据库都不会产生本用例测试行动项和测试子行动项。

边界：

- 覆盖对象：非目标挑战成员不可新增行动项和子行动项。
- 不覆盖对象：管理员新增行动项、目标挑战成员新增行动项、行动项编辑、行动项删除、子行动项编辑、子行动项删除、排序、完成状态切换、实施阶段新增行动项。
- 依赖对象：[用户增加行动项和子行动项](用户增加行动项和子行动项.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体普通成员账号、目标、行动项或子行动项。
- Setup 产物：邮箱为 `orf-member-task-forbidden-e2e@orf.local` 的无权限普通成员身份、用户和 member 成员关系；邮箱为 `orf-member-task-challenger-e2e@orf.local` 的目标挑战成员身份、用户和 member 成员关系；标题为 `E2E-TASK-FORBIDDEN: 目标前置`、流转状态为 `reestimating`、阶段为 `orfReestimate` 且挑战者只包含目标挑战成员的本用例行动项目标；无权限普通成员已登录会话。
- Action 产物：无权限普通成员进入挑战工作台后的页面状态。
- Clean 产物：删除本用例行动项目标、测试行动项、测试子行动项，删除本用例独占两个普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标、行动项和子行动项均为当前用例独占资源，Clean 直接删除，不恢复任何共享目标状态。
