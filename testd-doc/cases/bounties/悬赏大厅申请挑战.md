## 1. 测试目标

验证：一个已审核通过的 ORF 普通成员可以登录悬赏大厅，对一个当前可申请的目标提交挑战申请；申请提交后，该目标记录中出现一条以该成员为申请人的 `pending` 挑战申请，悬赏大厅中该目标的操作状态变为已申请。

边界：

- 本用例只验证普通成员提交挑战申请，不验证管理员审批申请、接受征召、拒绝申请、重复申请、已关闭目标或已是挑战者的目标。
- 本用例使用预置普通成员账号 `orf-member-e2e@orf.local` / `ORF Member E2E`，密码为 `OrfMemberE2E!2026`，角色为 `member`，状态为 `active`。
- 本用例选择运行时当前可申请的目标，不依赖固定目标标题或固定目标 ID。
- Clean 只删除本用例创建的挑战申请并恢复目标申请前的流转状态，不删除预置普通成员账号和基础业务目标数据。

## 2. 状态模型

- B：测试开始前和 Clean 后都必须满足的基准状态。该状态不是空系统，而是已经允许悬赏大厅开测的稳定业务状态：普通成员账号已可登录，系统中至少存在一个当前可申请的悬赏目标，且该成员尚未申请该目标。
  - [B-1] [api] 前端和后端服务已正常启动，健康检查或等价探测通过。
  - [B-2] [prisma] ORF 数据库连接正常，schema 已迁移到当前测试版本。
  - [B-3] [api] Ory/Kratos 服务可访问，Admin/Public API 对测试环境可用。
  - [B-4] [api] Ory/Kratos 中已存在普通成员测试身份 `orf-member-e2e@orf.local`，并具备可用密码凭据。
  - [B-5] [prisma] ORF 中已存在普通成员测试用户 `ORF Member E2E` 和 `team_members` 记录，角色为 `member`，状态为 `active`。
  - [B-6] [prisma] 默认团队中至少存在一个非终态、允许申请挑战的目标，目标 `flowStatus` 属于 `open`、`applying` 或 `recruiting`，且该目标当前挑战者不包含 `ORF Member E2E`。
  - [B-7] [prisma] 该目标的 `challengeApplications` 中不存在申请人为 `ORF Member E2E` 且状态为 `pending` 的记录。
  - [B-8] [api] `/api/auth/session` 返回 `authenticated: false`。
  - [B-9] [playwright] 当前浏览器上下文不存在 `orf_ory_session` cookie。
  - [B-10] [playwright] localStorage/sessionStorage 不包含登录态。

- Setup：如何从 B 构造 S0？
  - [Setup-1] [playwright] 创建全新的浏览器上下文，或清空当前上下文的 cookies/localStorage/sessionStorage。
  - [Setup-2] [playwright] 打开 `/auth`，使用普通成员测试邮箱和密码登录。
  - [Setup-3] [playwright] 打开 `/bounties`。
  - [Setup-4] [api] 读取 `GET /api/bounties`，从 `availableItems` 中选择一个 `hasCurrentApplication === false` 且当前可申请的目标，记录为 `runtime.bountyTarget`。

- S0：Action 前必须满足什么条件？用于确认 Setup 成功。
  - [S0-1] [api] `/api/auth/session` 返回 `authenticated: true`，用户邮箱为 `orf-member-e2e@orf.local`，角色为 `member`，状态为 `active`。
  - [S0-2] [playwright] `page` URL 为 `/bounties`。
  - [S0-3] [playwright] `page` 中主导航可见，当前用户显示为 `ORF Member E2E`。
  - [S0-4] [api] `GET /api/bounties` 返回 `runtime.bountyTarget` 对应的悬赏目标，且 `hasCurrentApplication` 为 `false`。
  - [S0-5] [playwright] 悬赏大厅列表中 `runtime.bountyTarget.objective.title` 对应的行可见。
  - [S0-6] [playwright] 该目标行中的 `申请挑战` 按钮可见且可点击。
  - [S0-7] [prisma] 数据库中该目标不存在申请人为 `ORF Member E2E` 且状态为 `pending` 的挑战申请。

- Action：本次测试唯一要验证的业务动作是什么？
  - [Action-1] [playwright] 点击所选目标行的 `申请挑战` 按钮。
  - [Action-2] [playwright] 确认弹窗显示“提交后等待指挥官确认”。
  - [Action-3] [playwright] 在点击确认弹窗的 `申请挑战` 前注册 `POST /api/objectives/{objectiveId}/challenge-applications` 响应捕获。
  - [Action-4] [playwright] 点击确认弹窗中的 `申请挑战`。

- S1：Action 后系统应该变成什么状态？用于确认业务动作正确。
  - [S1-1] [api] `POST /api/objectives/{objectiveId}/challenge-applications` 响应成功，返回的目标 ID 与 `runtime.bountyTarget.objective.id` 一致。
  - [S1-2] [prisma] 该目标的 `challengeApplications` 中新增一条申请人为 `ORF Member E2E`、状态为 `pending` 的记录，且 `createdAt` 不为空。
  - [S1-3] [prisma] 若该目标申请前不是 `recruiting`，提交申请后 `flowStatus` 为 `applying`；若申请前是 `recruiting`，则仍保持 `recruiting`。
  - [S1-4] [api] 再次读取 `GET /api/bounties` 时，该目标对当前用户的 `hasCurrentApplication` 为 `true`。
  - [S1-5] [playwright] 该目标行的操作按钮显示为 `已申请` 且不可点击，或该目标不再作为可申请项出现。
  - [S1-6] [playwright] 页面不显示错误提示。

- Clean：如何清理并恢复到 B？
  - [Clean-1] [prisma] 从 `runtime.bountyTarget.objective.challengeApplications` 中删除申请人为 `ORF Member E2E` 且由本用例创建的 `pending` 记录。
  - [Clean-2] [prisma] 如果删除后该目标没有其他待处理申请，且申请前 `flowStatus` 不是 `recruiting`，将目标 `flowStatus` 恢复为申请前状态。
  - [Clean-3] [api] 在当前浏览器上下文中调用 `/api/auth/logout`，撤销本次登录产生的 Ory session。
  - [Clean-4] [playwright] 清空当前浏览器上下文的 cookies/localStorage/sessionStorage。
  - [Clean-5] [api] 确认普通成员测试身份仍然存在。
  - [Clean-6] [prisma] 确认预置普通成员账号和 `member` 成员关系仍然存在；Clean 不删除该账号。
  - [Clean-7] [prisma] 确认 `runtime.bountyTarget` 对应目标仍然存在，且不包含本用例挑战申请残留。
