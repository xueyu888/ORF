# 悬赏大厅申请挑战

## 1. 测试目标

验证：由当前用例独占准备的已审核普通成员可以在悬赏大厅选择当前用例独占的可申请目标并提交挑战申请；提交后该目标进入已申请状态，并产生一条待审批挑战申请。

实现说明：

- 当前实现：已登录普通成员可以对可申请目标提交挑战申请。
- 当前用例类型：正向业务用例。
- 当前代码状态：已生成独立 testd 用例，待锁定。

边界：

- 覆盖对象：普通成员提交挑战申请。
- 不覆盖对象：管理员审批申请、接受征召、拒绝申请、重复申请、已关闭目标、已是挑战者的目标。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体普通成员账号、目标或挑战申请。
- Setup 产物：邮箱为 `orf-member-apply-challenge-e2e@orf.local` 的普通成员身份、用户和 member 成员关系；标题为 `E2E-APPLY-CHALLENGE: 成员申请挑战`、流转状态为 `open`、阶段为 `resultClaiming` 的本用例可申请目标；悬赏大厅数据中选中的本用例可申请目标。
- Action 产物：申请人为 "ORF Member Apply Challenge E2E"、状态为 `pending` 的本用例挑战申请，以及由申请动作引起的本用例目标流转状态变化。
- Clean 产物：删除本用例目标及其派生挑战申请，删除本用例独占普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标为当前用例独占资源，Clean 直接删除目标及派生数据，不恢复任何共享目标状态。

## 2. 状态-动作模型

- B：基准状态。
  - [B-1] [api] 前端服务 应可用。
  - [B-2] [api] 后端服务 应可用。
  - [B-3] [api] 前端登录页入口 应可访问。
  - [B-4] [api] 当前会话查询能力 应可用。
  - [B-5] [prisma] ORF 数据库 应可连接。
  - [B-6] [prisma] ORF 数据库 schema 应为 当前测试版本。
  - [B-7] [api] Ory/Kratos 认证服务的管理和公共访问能力 应可用。
  - [B-8] [api] 当前会话 应为 未登录。
  - [B-9] [playwright] 当前浏览器 应不存在 Ory 登录会话 cookie。
  - [B-10] [playwright] 当前浏览器 应不保留本地登录态。

- Setup：构造 S0。
  - [Setup-1] [prisma] 删除可能残留的本用例可申请目标及其派生数据。
  - [Setup-2] [api] 准备邮箱为 `orf-member-apply-challenge-e2e@orf.local`、使用固定测试密码的普通成员登录身份。
  - [Setup-3] [prisma] 准备邮箱为 `orf-member-apply-challenge-e2e@orf.local`、角色为 `member`、状态为 `active` 的普通成员用户和默认团队成员关系。
  - [Setup-4] [prisma] 创建标题为 `E2E-APPLY-CHALLENGE: 成员申请挑战`、流转状态为 `open`、阶段为 `resultClaiming` 的本用例可申请目标。
  - [Setup-5] [api] 撤销普通成员登录身份可能残留的登录会话。
  - [Setup-6] [playwright] 移除当前浏览器中的残留登录态。
  - [Setup-7] [playwright] 打开 ORF 登录页。
  - [Setup-8] [playwright] 在邮箱输入框输入普通成员固定测试邮箱。
  - [Setup-9] [playwright] 在密码输入框输入普通成员固定测试密码。
  - [Setup-10] [playwright] 点击 "Sign In" 登录操作。
  - [Setup-11] [api] 当前会话 应为 普通成员已登录会话。
  - [Setup-12] [playwright] 打开 悬赏大厅。
  - [Setup-13] [api] 选择悬赏大厅数据中的本用例可申请目标。

- S0：Action 前状态。
  - [S0-1] [api] 当前会话 应为 普通成员已登录会话。
  - [S0-2] [playwright] 当前页面 应为 悬赏大厅。
  - [S0-3] [playwright] 主导航 应可见。
  - [S0-4] [playwright] 当前用户显示 应为 "ORF Member Apply Challenge E2E"。
  - [S0-5] [api] 悬赏大厅数据中的本用例可申请目标 对当前普通成员 应为 尚未申请。
  - [S0-6] [playwright] 悬赏大厅列表中本用例目标对应的行 应可见。
  - [S0-7] [playwright] 本用例目标行中的 "申请挑战" 操作 应可见。
  - [S0-8] [playwright] 本用例目标行中的 "申请挑战" 操作 应可点击。
  - [S0-9] [prisma] 本用例目标 应不存在 申请人为 "ORF Member Apply Challenge E2E" 且状态为 `pending` 的挑战申请。

- Action：被测业务动作。
  - [Action-1] [playwright] 点击 本用例目标行的 "申请挑战" 操作。
  - [Action-2] [playwright] 确认弹窗 应显示 "提交后等待指挥官确认"。
  - [Action-3] [api] 监听提交挑战申请请求响应。
  - [Action-4] [playwright] 点击 确认弹窗中的 "申请挑战" 操作。

- S1：Action 后状态。
  - [S1-1] [api] 提交挑战申请结果 应为 本用例可申请目标的成功结果。
  - [S1-2] [prisma] 本用例目标 应存在 当前普通成员的已创建 pending 挑战申请。
  - [S1-3] [prisma] 本用例目标提交申请后的流转状态 应为 申请中状态。
  - [S1-4] [api] 悬赏大厅数据中的本用例目标 对当前普通成员 应为 已申请。
  - [S1-5] [playwright] 本用例目标的可申请操作 应不可再点击。

- Clean：恢复 B。
  - [Clean-1] [prisma] 删除 本用例可申请目标及其派生数据。
  - [Clean-2] [api] 注销当前登录会话。
  - [Clean-3] [playwright] 离开当前 ORF 前端页面。
  - [Clean-4] [playwright] 移除当前浏览器中的残留登录态。
  - [Clean-5] [api] 撤销普通成员登录身份的残留登录会话。
  - [Clean-6] [api] 删除邮箱为 `orf-member-apply-challenge-e2e@orf.local` 的普通成员登录身份。
  - [Clean-7] [prisma] 删除邮箱为 `orf-member-apply-challenge-e2e@orf.local` 的普通成员用户默认团队成员关系。
  - [Clean-8] [prisma] 删除邮箱为 `orf-member-apply-challenge-e2e@orf.local` 的普通成员用户。
  - [Clean-9] [prisma] 标题为 `E2E-APPLY-CHALLENGE: 成员申请挑战` 的测试目标 应不存在。
  - [Clean-10] [prisma] 邮箱为 `orf-member-apply-challenge-e2e@orf.local` 的普通成员用户 应不存在。
