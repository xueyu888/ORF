# 成员申请挑战审批-普通成员不可审批申请

## 1. 测试目标

验证：挑战申请审批是管理员业务能力；普通成员进入挑战工作台后，前端不提供 "通过" 和 "拒绝" 审批入口，挑战工作台不展示与当前普通成员无关的审批目标，并且挑战申请状态、目标挑战者列表和目标流转状态保持不变。

实现说明：

- 当前实现：挑战申请审批入口只向具备审批权限的管理员开放；普通成员挑战工作台只展示当前普通成员已接下的挑战目标。
- 当前用例类型：反向权限用例。
- 当前代码状态：已生成独立 testd 用例，已锁定。

边界：

- 覆盖对象：普通成员不可审批 pending 挑战申请。
- 不覆盖对象：管理员审批申请、普通成员提交申请入口、审批拒绝接口越权、目标关闭后的审批限制。
- 依赖对象：[成员申请挑战审批](成员申请挑战审批.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体普通成员账号、目标或申请。
- Setup 产物：邮箱为 `orf-member-review-forbidden-e2e@orf.local` 的普通成员身份、用户和 member 成员关系；邮箱为 `orf-member-review-forbidden-applicant-e2e@orf.local` 的申请人普通成员身份、用户和 member 成员关系；标题为 `E2E-REVIEW-FORBIDDEN: 普通成员不可审批申请` 的本用例审批目标；申请人对本用例审批目标的 pending 挑战申请；普通成员已登录会话。
- Action 产物：普通成员进入挑战工作台后可见的审批操作入口和工作台数据。
- Clean 产物：删除本用例审批目标及其派生申请，删除本用例独占两个普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标为当前用例独占资源，Clean 直接删除目标及派生数据，不恢复任何共享目标状态。
