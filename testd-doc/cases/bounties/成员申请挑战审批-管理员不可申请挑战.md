# 成员申请挑战审批-管理员不可申请挑战

## 1. 测试目标

验证：提交挑战申请是普通成员业务能力；管理员进入悬赏大厅后可以看到可申请目标，但点击该目标的 "申请挑战" 操作时，前端显示 "指挥官不应该申请挑战" 阻拦弹窗，并且不创建挑战申请、不修改目标挑战者列表和目标流转状态。

实现说明：

- 当前实现：悬赏大厅对管理员和普通成员均可见；管理员点击可申请目标的申请入口后，前端显示阻拦弹窗，不提交挑战申请。
- 当前用例类型：反向权限用例。
- 当前代码状态：已生成独立 testd 用例，已锁定。

边界：

- 覆盖对象：管理员不可提交挑战申请。
- 不覆盖对象：普通成员提交挑战申请、管理员审批申请、申请接口越权校验、目标关闭后的申请限制。
- 依赖对象：[成员申请挑战审批](成员申请挑战审批.md) 的正向业务定义。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体管理员账号、目标或申请。
- Setup 产物：邮箱为 `orf-admin-apply-forbidden-e2e@orf.local` 的管理员身份、用户和 admin 成员关系；标题为 `E2E-APPLY-FORBIDDEN: 管理员不可申请挑战` 的本用例申请目标；管理员已登录会话。
- Action 产物：管理员进入悬赏大厅后可见的目标申请操作入口和阻拦弹窗。
- Clean 产物：删除本用例申请目标及其派生申请，删除本用例独占管理员身份、用户、成员关系与 session。
- 原状态恢复：目标为当前用例独占资源，Clean 直接删除目标及派生数据，不恢复任何共享目标状态。
