## 1. 测试目标

验证：管理员可以在挑战工作台处理普通成员提交的挑战申请；通过后，成员进入目标挑战者列表；拒绝后，成员不进入目标挑战者列表，申请状态变为 `declined`。

边界：

- 本用例只验证管理员审批挑战申请，不验证普通成员提交申请入口、普通成员不可审批、目标关闭后的审批限制。
- 本用例使用预置管理员账号 `zrx831@gmail.com`，角色为 `admin`，状态为 `active`。
- 本用例使用两个预置普通成员作为申请人，分别覆盖“通过”和“拒绝”两种审批结果。
- 本用例选择运行时可审批的目标，不依赖固定目标标题或固定目标 ID。
- Setup 可以直接准备待审批申请，因为待审批申请是本用例 Action 的起点，不是本用例要验证的业务动作。
- Clean 恢复目标在 Setup 前的完整申请、挑战者和流转状态，不删除预置账号和基础目标数据。

## 2. 状态模型

- B：测试开始前和 Clean 后都必须满足的基准状态。
  - [api] 前端和后端服务 应为 可用。
  - [api] 健康检查或等价探测 应为 通过。
  - [prisma] ORF 数据库 应为 可连接。
  - [prisma] ORF 数据库 schema 应为 当前测试版本。
  - [api] Ory/Kratos Admin/Public API 应为 可访问。
  - [api] Ory/Kratos 中 应存在 邮箱为 `zrx831@gmail.com` 的管理员测试身份。
  - [prisma] 应存在 邮箱为 `zrx831@gmail.com`、角色为 `admin`、状态为 `active` 的管理员用户。
  - [prisma] 应存在 名称为 `ORF Member E2E`、角色为 `member`、状态为 `active` 的普通成员用户。
  - [prisma] 应存在 名称为 `m2`、角色为 `member`、状态为 `active` 的普通成员用户。
  - [prisma] 应存在 一个允许创建待审批挑战申请的目标。
  - [api] 当前会话 应为 未登录。
  - [playwright] 浏览器 应不存在 登录 cookie。
  - [playwright] 浏览器 storage 应不包含 登录态。

- Setup：如何从 B 构造 S0？
  - [playwright] 清空 浏览器状态。
  - [playwright] 打开 `/auth` 登录页。
  - [playwright] 在 Email 输入框 输入 管理员邮箱。
  - [playwright] 在 Password 输入框 输入 管理员密码。
  - [playwright] 点击 `Sign In` 登录操作。
  - [api] 当前会话 应为 管理员已登录。
  - [prisma] 选择 一个允许审批挑战申请的目标。
  - [prisma] 记录 目标 的原始状态。
  - [prisma] 为 目标 创建 申请人为 `ORF Member E2E`、状态为 `pending` 的挑战申请。
  - [prisma] 为 目标 创建 申请人为 `m2`、状态为 `pending` 的挑战申请。
  - [playwright] 打开 `/tasks` 挑战工作台。
  - [playwright] 点击 `所有挑战` 视图切换操作。

- S0：Action 前必须满足什么条件？
  - [api] 当前会话 应为 邮箱 `zrx831@gmail.com` 的管理员已登录。
  - [playwright] 当前页面 应为 挑战工作台。
  - [playwright] 目标 面板 应可见。
  - [playwright] 目标中 `ORF Member E2E` 的挑战申请 应显示 `通过` 操作。
  - [playwright] 目标中 `m2` 的挑战申请 应显示 `拒绝` 操作。
  - [prisma] 目标 应存在 申请人为 `ORF Member E2E`、状态为 `pending` 的挑战申请。
  - [prisma] 目标 应存在 申请人为 `m2`、状态为 `pending` 的挑战申请。
  - [prisma] 目标 的挑战者列表 应不包含 `ORF Member E2E`。
  - [prisma] 目标 的挑战者列表 应不包含 `m2`。

- Action：本次测试唯一要验证的业务动作是什么？
  - [playwright] 在点击 `ORF Member E2E` 的 `通过` 前注册 审批通过接口响应捕获。
  - [playwright] 点击 目标中 `ORF Member E2E` 挑战申请的 `通过` 操作。
  - [playwright] 在点击 `m2` 的 `拒绝` 前注册 审批拒绝接口响应捕获。
  - [playwright] 点击 目标中 `m2` 挑战申请的 `拒绝` 操作。

- S1：Action 后系统应该变成什么状态？
  - [api] 审批通过接口响应 应成功。
  - [api] 审批拒绝接口响应 应成功。
  - [prisma] 目标中 `ORF Member E2E` 的挑战申请状态 应为 `approved`。
  - [prisma] 目标 的挑战者列表 应包含 `ORF Member E2E`。
  - [prisma] 目标中 `m2` 的挑战申请状态 应为 `declined`。
  - [prisma] 目标 的挑战者列表 应不包含 `m2`。
  - [prisma] 目标 flowStatus 应为 `reestimating`。
  - [api] 当前会话 应仍为 管理员已登录。

- Clean：如何清理并恢复到 B？
  - [prisma] 恢复 目标 在 Setup 前记录的原始状态。
  - [api] 退出 当前登录态。
  - [playwright] 清空 浏览器状态。
  - [api] Ory/Kratos 中 应仍存在 管理员测试身份。
  - [prisma] 应仍存在 邮箱为 `zrx831@gmail.com`、角色为 `admin`、状态为 `active` 的管理员用户。
  - [prisma] 应仍存在 名称为 `ORF Member E2E`、角色为 `member`、状态为 `active` 的普通成员用户。
  - [prisma] 应仍存在 名称为 `m2`、角色为 `member`、状态为 `active` 的普通成员用户。
