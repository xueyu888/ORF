# 成员申请挑战审批

## 1. 测试目标

验证：两个普通成员分别从悬赏大厅对同一目标提交挑战申请后，管理员可以通过其中一个申请并拒绝另一个申请；通过的成员进入目标挑战者列表并能在挑战工作台看到该目标，拒绝的成员不进入目标挑战者列表。

实现说明：

- 当前实现：普通成员在悬赏大厅提交挑战申请；审批接口要求管理员会话；通过申请会把申请人加入目标挑战者列表，拒绝申请不会加入目标挑战者列表。
- 当前用例类型：正向业务用例。
- 当前代码状态：已生成独立 testd 用例，当前未锁定。

边界：

- 覆盖对象：普通成员提交挑战申请、管理员审批 pending 挑战申请、审批后两个成员各自查看挑战结果。
- 不覆盖对象：重复提交挑战申请、普通成员不可审批、目标关闭后的申请限制、目标关闭后的审批限制。
- B 基准：前端、后端、数据库、schema、Ory/Kratos 和当前浏览器可开测；不要求存在任何具体管理员账号、普通成员账号、目标或申请。
- Setup 产物：邮箱为 "orf-admin-review-application-e2e@orf.local" 的管理员身份、用户和 admin 成员关系；邮箱为 "orf-member-review-approve-e2e@orf.local"、"orf-member-review-reject-e2e@orf.local" 的两个普通成员身份、用户和 member 成员关系；标题为 "E2E-REVIEW-APPLICATION: 成员申请审批" 的本用例审批目标。
- Action 产物：两个普通成员分别提交 pending 挑战申请；管理员将审批通过申请变为 `approved`，将审批拒绝申请变为 `declined`；通过申请人成为目标挑战者并能在挑战工作台看到目标；拒绝申请人不能在挑战工作台看到目标；目标进入 `reestimating`。
- Clean 产物：删除本用例审批目标及其派生申请，删除本用例独占管理员和两个普通成员身份、用户、成员关系与 session。
- 原状态恢复：目标为当前用例独占资源，Clean 直接删除目标及派生数据，不恢复任何共享目标状态。
