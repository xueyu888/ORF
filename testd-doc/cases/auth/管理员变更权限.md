## 1. 测试目标

验证：已登录管理员可以修改 member 角色权限配置；保存后该配置可以再次读取，并在 Clean 中恢复为修改前状态。

边界：

- 覆盖对象：管理员修改 member 角色权限。
- 不覆盖对象：admin 角色权限变更、所有权限组合验证。
- Action 边界：只切换一个明确权限 key，例如 "comment.manage"。
- Clean 产物：修改前的 member 权限配置。

## 2. 状态模型

- B：基准状态。
  - [api] 前端服务 应可用。
  - [api] 后端服务 应可用。
  - [api] 前端登录页入口 应可访问。
  - [api] 当前会话查询接口 应可访问。
  - [prisma] ORF 数据库 应可连接。
  - [prisma] ORF 数据库 schema 应为 当前测试版本。
  - [api] Ory/Kratos Admin/Public API 应可访问。
  - [api] 应存在 邮箱为 `zrx831@gmail.com` 的管理员测试身份。
  - [api] 管理员测试身份 的密码凭据 应可用。
  - [prisma] 应存在 邮箱为 `zrx831@gmail.com`、角色为 `admin`、状态为 `active` 的管理员用户。
  - [api] 当前会话 应为 未登录。
  - [playwright] 当前浏览器 应不存在 Ory session cookie。
  - [playwright] 当前浏览器 storage 应不包含 登录态。

- Setup：构造 S0。
  - [api] 记录管理员登录前的 `last_online_at`，用于 Clean 恢复。
  - [api] 撤销管理员测试身份可能残留的 Ory session。
  - [playwright] 清空当前浏览器上下文的 cookies/localStorage/sessionStorage。
  - [playwright] 打开 登录页，使用管理员账号登录。
  - [api] 读取权限配置接口，记录当前 `member` 角色权限为 `runtime.originalMemberPermissionRules`。
  - [playwright] 打开 权限管理页面。

- S0：Action 前状态。
  - [api] 当前会话 应为 邮箱为 `zrx831@gmail.com`、角色为 `admin`、状态为 `active` 的已登录会话。
  - [playwright] 当前页面 应为 权限管理页面。
  - [playwright] 权限管理页面 应显示 `成员` 角色页签。
  - [playwright] 权限管理页面 应显示 `comment.manage` 对应的权限开关。
  - [api] 已记录修改前的 `member` 权限配置。

- Action：被测业务动作。
  - [api] 基于 `runtime.originalMemberPermissionRules` 生成新的 `member` 权限配置。
  - [api] 以当前管理员会话调用 member 权限保存接口，保存新的 `member` 权限配置。

- S1：Action 后状态。
  - [api] member 权限保存接口响应 应成功。
  - [api] 再次读取权限配置接口时，`member` 角色权限配置应等于 Action 中保存的新配置。
  - [playwright] 管理员仍停留在 ORF 已登录状态。
  - [prisma] ORF 管理员用户和 `admin` 成员关系 应仍存在。

- Clean：恢复 B。
  - [api] 以当前管理员会话调用 member 权限保存接口，恢复 `runtime.originalMemberPermissionRules`。
  - [api] 调用退出登录接口撤销本次登录产生的 Ory session。
  - [playwright] 清空当前浏览器上下文的 cookies/localStorage/sessionStorage。
  - [prisma] 恢复管理员登录前记录的 `last_online_at`。
  - [api] 撤销管理员测试身份可能残留的 Ory session。
  - [api] 管理员 Ory 身份 应仍存在。
  - [prisma] 管理员 ORF 用户和 `admin` 成员关系 应仍存在。
