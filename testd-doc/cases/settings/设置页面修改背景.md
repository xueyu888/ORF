## 1. 测试目标

验证：当前产品权限模型下，预置普通成员账号不能进入设置页面修改系统背景；直接访问 `/settings` 会被重定向回可访问页面，直接调用背景修改接口会被拒绝。

说明：

- 用户期望“用普通成员测试账号修改背景”，但当前实现中设置入口和 `/api/settings/visual/backgrounds`、`/api/settings/visual/background-config` 的写操作都要求管理员权限。
- 因此本文档先按当前实现定义为权限防护用例，而不是正向修改背景用例。
- 如果产品后续决定普通成员可以修改自己的背景偏好，需要先调整前端可见性和后端权限，再把本用例改为正向“普通成员修改个人背景”。

边界：

- 本用例只验证普通成员不能修改设置背景，不验证管理员上传图片、设置默认背景、切换规则保存或图片文件校验。
- 本用例使用预置普通成员账号 `orf-member-e2e@orf.local` / `ORF Member E2E`，密码为 `OrfMemberE2E!2026`，角色为 `member`，状态为 `active`。
- 本用例不应修改任何背景配置或上传背景文件。

## 2. 状态模型

- B：测试开始前和 Clean 后都必须满足的基准状态，用于确认普通成员账号可登录、背景配置存在或可为空，且当前浏览器未登录。
  - [api] 前端和后端服务已正常启动，健康检查或等价探测通过。
  - [prisma] ORF 数据库连接正常，schema 已迁移到当前测试版本。
  - [api] Ory/Kratos 服务可访问，Admin/Public API 对测试环境可用。
  - [api] Ory/Kratos 中已存在普通成员测试身份 `orf-member-e2e@orf.local`，并具备可用密码凭据。
  - [prisma] ORF 中已存在普通成员测试用户 `ORF Member E2E` 和 `team_members` 记录，角色为 `member`，状态为 `active`。
  - [api] 记录当前 `login_background` 和 `sidebar_background` 的背景列表与配置，用于确认本用例没有产生修改。
  - [api] `/api/auth/session` 返回 `authenticated: false`。
  - [playwright] 当前浏览器上下文不存在 `orf_ory_session` cookie。
  - [playwright] localStorage/sessionStorage 不包含登录态。

- Setup：如何从 B 构造 S0？
  - [playwright] 创建全新的浏览器上下文，或清空当前上下文的 cookies/localStorage/sessionStorage。
  - [playwright] 打开 `/auth`，使用普通成员测试邮箱和密码登录。
  - [playwright] 打开 `/bounties` 或登录后默认可访问页面。

- S0：Action 前必须满足什么条件？用于确认 Setup 成功。
  - [api] `/api/auth/session` 返回 `authenticated: true`，用户邮箱为 `orf-member-e2e@orf.local`，角色为 `member`，状态为 `active`。
  - [playwright] 主导航可见，当前用户显示为 `ORF Member E2E`。
  - [playwright] 侧边栏 `设置` 入口不可见。
  - [playwright] 访问 `/bounties` 成功。
  - [api] 以当前普通成员会话读取 `GET /api/settings/visual/backgrounds?scene=sidebar_background` 可以成功返回当前背景配置。

- Action：本次测试唯一要验证的权限行为是什么？
  - [playwright] 直接导航到 `/settings`。
  - [api] 以当前普通成员会话尝试调用 `PUT /api/settings/visual/background-config` 修改 `sidebar_background` 配置。
  - [api] 以当前普通成员会话尝试调用 `PUT /api/settings/visual/backgrounds/{id}/default` 设置默认背景；若当前没有可用背景图片，则跳过该接口尝试。

- S1：Action 后系统应该变成什么状态？用于确认权限防护正确。
  - [playwright] 直接访问 `/settings` 后不会停留在设置页面，应被重定向到 `/bounties` 或其他当前用户可访问页面。
  - [playwright] 页面中不显示 `视觉设置`、`登录页面背景设置` 或 `侧边栏背景设置`。
  - [api] `PUT /api/settings/visual/background-config` 返回 403，或等价的“只有管理员可以操作”错误。
  - [api] `PUT /api/settings/visual/backgrounds/{id}/default` 返回 403，或等价的“只有管理员可以操作”错误。
  - [api] 再次读取 `login_background` 和 `sidebar_background` 的背景列表与配置，与 B 阶段记录一致。
  - [playwright] 普通成员仍保持已登录状态，可以继续访问 `/bounties`。

- Clean：如何清理并恢复到 B？
  - [api] 在当前浏览器上下文中调用 `/api/auth/logout`，撤销本次登录产生的 Ory session。
  - [playwright] 清空当前浏览器上下文的 cookies/localStorage/sessionStorage。
  - [api] 确认 `login_background` 和 `sidebar_background` 背景列表与配置没有被本用例修改。
  - [api] 确认普通成员测试身份仍然存在。
  - [prisma] 确认预置普通成员账号和 `member` 成员关系仍然存在；Clean 不删除该账号。
