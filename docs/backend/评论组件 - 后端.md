# 评论组件 - 后端

本文档只记录评论后端的必要约束，前端交互见 [评论组件 - 前端.md](../frontend/评论组件%20-%20前端.md)。

## 后端要求

1. 评论必须写入 ORF 当前 PostgreSQL 数据库，使用现有 `DATABASE_URL`、当前 schema 和 Drizzle migration，不单独建立评论数据库或评论服务。
2. 评论数据模型沿用前端现有 `CommentThread` 和 `CommentMessage`，绑定对象类型保持 `objective`、`result`、`task`、`subtask`，其中 `result` 在产品层展示为指标。
3. 评论随 ORF 主数据返回；优先并入 `/api/tasks-page` 的返回集合，避免前端继续用 `localStorage` 保存评论。
4. 评论新增、编辑、删除和解决状态变更必须通过后端写入数据库，前端操作成功后刷新或合并评论数据。
5. 评论权限先按对象可见性处理：能看到对象即可看评论；发评论必须登录；编辑和删除限作者本人或管理员。
