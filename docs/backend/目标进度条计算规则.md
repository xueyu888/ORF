# 目标进度条计算规则

## 1. 职责归属

目标进度是后端业务数据，不是前端展示派生值。

后端负责：

* 根据目标、悬赏指标、任务、子任务的业务状态计算目标进度。
* 在接口中返回 `Objective.progress`。
* 保证 `Objective.progress` 是 `0` 到 `100` 的整数。

前端负责：

* 读取 `Objective.progress`。
* 用进度条 UI 展示该值。
* 做展示兜底，例如限制异常值不超过 `0%` 到 `100%`。

前端不得重新实现目标进度业务算法。

---

## 2. 接口字段

后端在挑战页目标数据中返回：

```ts
type Objective = {
  id: string;
  title: string;
  progress: number;
  // ...
}
```

字段语义：

| 字段 | 类型 | 归属 | 含义 |
| --- | --- | --- | --- |
| `Objective.progress` | `number` | 后端 | 目标进度，整数百分比，范围 `0..100` |

前端目标进度条只绑定：

```text
objective.progress
```

---

## 3. 计算触发

目标进度计算遵循 [自动化计算规则.md](./自动化计算规则.md) 的阶段约束：

```text
1. 目标阶段由非 goalFrozen 转为 goalFrozen
2. 目标已经处于 goalFrozen，且该目标下的 goal / ret / task / subtask 发生变化
```

满足触发条件时，后端基于目标最新层级快照重新计算并返回目标进度。

不满足触发条件时，不调用自动化计算模块，也不因为页面数据变化产生新的目标进度计算结果。

---

## 4. 计算口径

自动化计算模块输出悬赏指标完成值：

```text
C(ret) ∈ {0, 1}

1 = 悬赏指标已完成
0 = 悬赏指标未完成
```

目标进度由当前目标下所有悬赏指标完成值平均得到：

```text
p(goal) = average(C(ret[]))

Objective.progress = round(p(goal) × 100)
```

如果某个悬赏指标没有对应的自动化完成结果，按 `0` 处理。

如果目标没有任何悬赏指标，目标不是合法计算输入，不得按空集合完成处理；接口返回进度应为 `0` 或保留已有未完成进度，不能返回 `100`。

---

## 5. 非目标冻结阶段

非目标冻结阶段不进行自动化目标进度计算。

后端返回当前持久化的 `Objective.progress`。

前端仍然展示该字段，但不因为目标、悬赏指标、任务、子任务的页面变化重新计算目标进度。

---

## 6. 示例

### 6.1 非目标冻结阶段

```text
objective.progress = 61
当前阶段 != goalFrozen

接口返回 Objective.progress = 61
前端展示 61%
```

### 6.2 目标冻结阶段

目标下有 3 个悬赏指标：

```text
retA = 1
retB = 0
retC = 1
```

则：

```text
p(goal) = average([1, 0, 1]) = 0.666...
Objective.progress = round(0.666... × 100) = 67
前端展示 67%
```

---

## 7. 前后端对齐要求

* 后端文档中的 `Objective.progress` 是唯一业务口径。
* 前端文档中的目标进度条只是 UI 展示规则。
* 如果后端计算规则变化，先更新本文档，再调整接口和前端展示。
* 前端不得新增另一套 `objectiveProgress(...)` 业务算法与后端返回值竞争。
