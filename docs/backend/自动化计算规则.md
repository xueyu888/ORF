
# 目标完成的自动化计算规则

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

## 目标

定义单个目标在冻结阶段后的自动化完成状态计算规则。
也就是：
1. 在目标冻结阶段，才进行自动化计算
2. 在非目标冻结阶段，不进行任何自动化计算

自动化计算必须封装为一个独立计算模块。

非目标冻结阶段不调用计算模块。无论计划页面中的目标、指标、任务、子任务如何创建、编辑、删除、移动或勾选，都不触发本规则，也不产生新的自动化完成状态。

计算层级为：

```text
goal → ret → task → subtask
```

其中：

```text
goal 表示目标
ret 表示指标
task 表示任务
subtask 表示子任务
```

系统只自动计算：

```text
task
ret
goal
```

`subtask` 是最小状态输入，不再继续计算。

---

## 模块边界与触发条件

计算模块的输入是单个目标的最新层级快照：

```text
goal
ret[]
task[]
subtask[]
```

计算模块的输出只包含：

```text
C(task)
C(ret)
C(goal)
```

业务页面、增删改查、拖拽排序、勾选操作和普通状态展示都不是自动化计算本身。它们只能在触发条件成立时调用计算模块。

触发条件只有两类：

```text
1. 目标阶段由非 goalFrozen 转为 goalFrozen
2. 目标已经处于 goalFrozen，且该目标下的 goal / ret / task / subtask 发生变化
```

满足任一触发条件时，必须基于该目标的最新层级快照重新计算：

```text
C(task)
C(ret)
C(goal)
```

重新计算是整棵目标树级别的计算，不只局部修补单个节点。

不满足触发条件时，不调用计算模块；不因为页面数据变化产生新的自动化完成状态。

## 最小基

设单个目标为：

```text
g
```

目标 `g` 下的指标集合为：

```text
R = {r₁, r₂, ..., rₙ}, n ≥ 1
```

指标 `rᵢ` 下的任务集合为：

```text
Tᵢ = {tᵢ₁, tᵢ₂, ..., tᵢₘᵢ}, mᵢ ≥ 1
```

任务 `tᵢⱼ` 下的子任务集合为：

```text
Sᵢⱼ = {sᵢⱼ₁, sᵢⱼ₂, ..., sᵢⱼₖᵢⱼ}, kᵢⱼ ≥ 0
```

状态域为：

```text
B = {0, 1}
```

其中：

```text
1 = done
0 = undone
```

定义叶子状态函数：

```text
d(x) ∈ B
```

其中 `x` 只能是：

```text
没有 subtask 的 task
或 subtask
```

定义系统计算函数：

```text
C(x) ∈ B
```

其中 `x` 只能是：

```text
task
ret
goal
```

---

## 组合原则

### 1. task 的计算

对于任务 `tᵢⱼ`：

```text
C(tᵢⱼ) =
{
  d(tᵢⱼ),              kᵢⱼ = 0
  ∧ₗ d(sᵢⱼₗ),          kᵢⱼ > 0
}
```

即：

```text
task 没有 subtask 时，由 task 自身状态决定。
task 有 subtask 时，由全部 subtask 状态决定。
```

---

### 2. ret 的计算

对于指标 `rᵢ`：

```text
C(rᵢ) = ∧ⱼ C(tᵢⱼ)
```

即：

```text
ret done ⇔ ret 下所有 task done
```

---

### 3. goal 的计算

对于目标 `g`：

```text
C(g) = ∧ᵢ C(rᵢ)
```

即：

```text
goal done ⇔ goal 下所有 ret done
```

---

## 组合空间

单个目标的合法组合空间为：

```text
g
└── rᵢ, i = 1...n, n ≥ 1
    └── tᵢⱼ, j = 1...mᵢ, mᵢ ≥ 1
        └── sᵢⱼₗ, l = 1...kᵢⱼ, kᵢⱼ ≥ 0
```

约束为：

```text
goal 下至少有 1 个 ret
ret 下至少有 1 个 task
task 下可以有 0 个或多个 subtask
```

以上结构约束是计算模块的合法输入前提。

当目标处于 `goalFrozen` 且触发自动化计算时，如果数据不满足 `n ≥ 1` 或 `mᵢ ≥ 1`，该目标不是合法计算输入，计算模块不得把缺失下级的 `goal` 或 `ret` 视为空集合完成，也不得输出 `done`。

因此合法路径只有两类：

```text
goal → ret → task
```

和：

```text
goal → ret → task → subtask
```

最终计算式为：

```text
C(g) = ∧ᵢ ∧ⱼ F(tᵢⱼ)
```

其中：

```text
F(tᵢⱼ) =
{
  d(tᵢⱼ),              kᵢⱼ = 0
  ∧ₗ d(sᵢⱼₗ),          kᵢⱼ > 0
}
```
