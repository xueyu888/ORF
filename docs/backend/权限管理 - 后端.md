# 权限管理 - 后端

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/permissions`。

## 文档定位

本文档只记录权限管理的后端模型、校验规则和接口口径。

权限原则和权限清单见 [权限管理.md](../legacy/权限管理.md)。

权限 key 唯一配置来源是 `src/config/permissions.ts`。

## 技术选型

1. 使用 PostgreSQL 持久化权限配置。
2. 不需要缓存。

## 模型

权限采用角色权限 key 列表：

```text
User -> default-scope membership.role -> PermissionRule
can(user, permissionKey)
```

| 字段 | 说明 |
| --- | --- |
| `role` | `admin`、`member` |
| `permissions` | 当前角色开启的权限 key 数组 |

管理员默认拥有全部权限，不需要保存单独规则。

成员权限由 `PermissionRule.permissions` 决定。

## 持久化

当前继续使用 `role_permissions` 表保存角色权限。

成员权限保存为一条角色记录：

| 字段 | 值 |
| --- | --- |
| `role` | `member` |
| `stage` | `global` |
| `resource` | `permissionKeys` |
| `actions` | 权限 key 数组 |

`stage`、`resource`、`actions` 是历史字段名，业务含义以 `actions` 中的权限 key 为准。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/permissions` | 返回当前默认作用域权限配置 |
| `PUT` | `/api/permissions/:role` | 保存指定角色权限配置 |

`PUT /api/permissions/admin` 不允许修改。

## 默认成员权限

成员默认不开启权限清单中的任何权限。
