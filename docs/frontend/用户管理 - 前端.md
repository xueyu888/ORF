# 用户管理 - 前端

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

后端认证、用户和默认作用域成员关系见 [用户管理 - 后端.md](../backend/用户管理%20-%20后端.md)。

## 页面入口

- 路由：`/system/members`，旧 `/members` 只作为兼容跳转。
- 系统管理页签展示名：`成员管理`。
- 仅管理员可见、可访问；非管理员进入时跳回悬赏大厅。

## 页面区域

| 区域 | 内容 | 行为 |
| --- | --- | --- |
| 筛选工具栏 | 姓名 / 邮箱搜索、角色筛选、用户总数、角色总数、新增用户 | 搜索和筛选用户；统计靠右展示，新增用户按钮在最右侧打开弹窗。 |
| 用户表 | 用户、邮箱、角色、状态、最近在线、操作 | 展示用户列表；支持编辑用户资料、停用用户和删除未被业务引用的用户。 |

## 交互规则
- 成员头像展示使用通用用户头像组件，优先显示后端返回的 `avatarUrl`，缺失或图片加载失败时回退姓名首字母。
- 管理员不能在成员管理页替其他用户上传、删除或替换头像；头像只能由用户本人到个人设置页维护。
- 当前用户在列表中显示 `当前` 标记。
- 最近在线只展示后端返回的 `lastOnlineAt`；没有在线记录时显示 `未在线`。
- 新增 / 编辑弹窗提交前会裁剪姓名和邮箱首尾空白，并把邮箱统一转成小写。
- 姓名或邮箱裁剪后为空时，前端不发起 `/api/users` 写请求，弹窗保持打开并提示用户补全。
- 新增 / 编辑成员必须等待 `/api/users` 写请求返回；保存中禁用关闭、取消、输入和提交入口，避免慢请求或失败请求丢失表单上下文。
- 已绑定登录身份和未绑定预批准成员编辑时，邮箱输入框都可编辑；前端只提交规范化后的邮箱，Ory identity 同步由后端负责。
- 管理员不能停用自己，也不能将自己的角色降级为成员。
- 当前默认作用域内不能存在重名成员；新增或编辑成员时如果后端返回当前成员重名错误，应保留表单输入并提示用户改名。历史 ORF 业务记录中的旧展示名不再占用新姓名。
- 已经参与 ORF 目标或被业务记录引用的成员可以修改显示名；业务参与关系由后端的 `users.id` UUID 字段保持，前端只提交用户资料并展示后端返回的成员集合，不在页面层维护业务引用迁移。
- 停用用户前需要二次确认。
- 删除账号前需要二次确认；当前管理员不能删除自己。删除成功代表后端已经按账号级契约清理 ORF 用户、默认作用域成员关系和已绑定登录身份。
- 后端拒绝删除已被 ORF 业务记录引用的成员时，前端展示错误并保留该行。

## 前端验收用例

| 用例 | 操作 | 断言 |
| --- | --- | --- |
| 编辑已绑定成员 | 打开 `authLinked = true` 成员的编辑弹窗 | 邮箱、姓名和角色按原规则可编辑；当前管理员仍不能把自己降级 |
| 编辑预批准成员 | 打开 `authLinked = false` 成员的编辑弹窗 | 邮箱输入框可编辑，提交前仍裁剪空白并转小写 |
| 后端拒绝邮箱修改 | 保存时后端返回邮箱重复或 Ory 管理接口不可用错误 | 弹窗保留输入，显示错误提示 |
| 删除未引用账号 | 点击成员行 `删除` 并确认 | 前端调用 `DELETE /api/users/:userId`，成功后该行从列表移除；如果账号已绑定登录身份，后端同时删除 Ory identity |

## 最近在线上报

- 前端不使用轮询刷新在线状态。
- 已认证用户发生真实交互时，上报 `POST /api/users/me/activity`，包括 `pointerdown`、`keydown`、`wheel`、`touchstart`、窗口重新 `focus`、页面从隐藏变为可见。
- 前端必须带同一个 `clientId` 连接 `/api/events` 和上报 `/api/users/me/activity`，后端用它区分同一用户的多个设备或窗口。
- 桌面客户端通过 `orfDesktopShell.getSystemIdleSnapshot()` 上报系统级 `systemIdleSeconds/systemIdleState`；普通网页只能上报 `documentVisible/documentFocused/lastInteractionAt`，不能声称拥有系统级空闲时间。
- 上报请求可以携带客户端活动证据，但最近在线持久化时间仍由后端生成。
- 前端对上报做节流，同一页面会话内 60 秒最多发送一次。
- 即使没有页面内交互，前端也每 60 秒发送一次 presence heartbeat，让长时间挂机、锁屏或系统空闲能从活跃在线变为离开；空闲 heartbeat 不应导致后端刷新 `lastOnlineAt`。
- 页面隐藏或卸载时可以用 `sendBeacon` 或 `keepalive` 尽量补发一次，但不依赖它作为强一致能力。
- 聊天头像只消费后端 `ChatUser.presence` 派生状态；`presence` 缺失时直接打开现有“版本与更新”界面并提示升级，不用旧 `lastOnlineAt` 兼容。
- 绿色徽标只表示 `presence.state = active`；黄色徽标表示 `idle` 或 `recent`；灰色表示 `offline`。`lastOnlineAt` 只用于断开后的最近在线展示，不能反向定义活跃在线。
