# ORF 工作日志页面 - 前端

## 页面

`/work-logs` 承载工作日志页面。侧边栏显示“工作日志”，移动端底部导航也提供入口。

页面默认日期为今天，也支持前一天、后一天和日期选择。

## 结构

页面使用两个页面级视图：

| 视图 | 职责 |
| --- | --- |
| 日志 | 当前日期的日常工作流：填写自己的日志、查看当天已提交记录，同时查看团队历史动态 |
| 统计 | 从日志事实派生个人月历和全员日期矩阵 |

“日志”视图在桌面端为左右布局：左侧是团队动态，右侧是我的日志编辑器和当天记录。移动端使用同一视图结构纵向排列，避免填写和查看团队动态拆成两个互斥入口。

日志视图内部区域：

| 区域 | 职责 |
| --- | --- |
| 我的日志 | 当前用户用单一编辑器提交或修改一条日志，并查看当天已提交记录 |
| 团队动态 | 读取团队工作日志历史活动流，按日期和更新时间倒序展示最新记录 |

## 编辑

- 日志正文复用 `OrfRichTextEditor`，保存 Markdown；工作日志场景开启 `autoGrow`，正文区随输入内容增高，到达视口内上限后再滚动，移动端也使用同一编辑器事实源和草稿状态。
- 活动流正文复用 `OrfRichTextMarkdownViewer`。
- 页面不复用 `ChatComposer`，避免把频道、回复、typing、附件上传等聊天语义带入工作日志。
- 历史记录在编辑态展示“日志资源”入口，复用 `RelatedResourcesPanel` 把资源关联到该条 `work_log_entries.id`；当天资源块只汇总当前日期所有日志条目的关联资源，并跳转到 `/resources/:nodeId/preview`。
- 普通非 FAE 成员默认必须选择目标、填写目标进度估计并填写正文；目标默认候选只显示当前用户正在做的目标。用户在目标搜索框输入关键词时可以搜到当前团队全部目标，包括已验收、已结算、已关闭以及自己不是挑战者的目标；已完成目标选中后页面提示这条日志属于验收后工作/返工日志或历史记录，且不会改变目标状态；自己不是挑战者的目标选中后页面提示确认目标选择。所有 active 成员都可以选择内置分类“请假”保存免目标日志，且不要求目标进度估计。指挥官/管理员默认可以直接选择当前团队全部目标、管理分类、新建管理分类或“不指定目标”记录日常工作；“管理事务”仍只在指挥官/管理员的管理分类里出现。当前临时允许 FAE 成员邓滨虎、何永杰选择“未归类”保存日志，但不显示管理分类入口。
- 同一天可以提交多条日志，也可以多次记录同一个目标。
- 页面只允许一个编辑器同时存在；编辑历史日志时把该条记录加载进同一个编辑器，不新开第二个编辑窗口。
- 页面按当前用户和当前日期把单编辑器草稿自动保存到本机 `localStorage`。刷新页面后恢复未提交草稿；如果草稿正在编辑的历史日志已经不存在，则丢弃草稿。草稿只是本机恢复能力，不写入 `work_log_entries`，不触发团队动态、报表、欠账提醒或系统通知。提交成功、清空空白草稿或取消到空白状态后清理本机草稿。
- 空白草稿不会保存；普通非 FAE 成员提交目标日志时必须有目标、目标进度估计和正文；选择“请假”时只要求正文有效；指挥官以及当前临时 FAE 例外成员未指定目标时只要求正文有效。
- 目标进度估计是可空的 `0..100` 百分比，只在选择目标时保存；未指定目标时清空。普通非 FAE 成员选择目标后必须填写；页面会默认沿用该用户上一次给同一目标记录的进度估计，用户可以上调、下调或保持不变。它只作为当前日志快照展示和报表统计，不更新 `Objective.progress`。当前 API/存储兼容字段仍是 `remainingEstimatePercent`，页面读写边界用 `100 - remainingEstimatePercent` 转成用户看到的进度估计。
- 记录时间是可选分钟数，默认不填写。填写后只作为该条日志的可选快照展示和统计，不强制工时核算。
- 指挥官/管理员输入正文后，页面标题区固定 AI 状态槽可以展示轻量智能分类建议；建议不弹窗、不打断输入，不插入编辑控件内部，用户可以点击采用或忽略。
- 历史记录支持本人删除；删除后刷新当天记录、团队动态和报表。
- 新增日志提交成功后，后端派生 `worklog.submitted` 系统公告给当前团队 active 成员；前端仍只通过工作日志 API 刷新当天记录、团队动态和报表，不用通知反向修改页面事实。

## 智能推荐交互

智能推荐只是编辑器标题区的固定状态槽，不是页面事实源：

- 只有后端返回 `classificationSuggestionEnabled: true` 且当前用户可使用日志分类时，页面才启动推荐。
- 正文少于 8 个字符或没有有效 Markdown 内容时不请求推荐。
- 正文变化后等待 700ms 再请求 `/api/work-logs/classification-suggestion`，避免每个按键都触发模型调用。
- 推荐请求只发送正文；目标候选、分类候选和权限边界由后端决定。智能推荐只使用当前用户的默认目标候选：指挥官/管理员可覆盖当前团队全部目标，普通成员不自动推荐搜索专用目标。
- 新一轮输入会取消上一轮结果的 UI 接收，避免旧响应覆盖新草稿。
- 请求中显示“智能分析中 / 正在匹配目标和分类”；请求失败、无建议或建议和当前草稿已经一致时，状态槽保留空闲/等待状态，不显示弹窗。
- 状态槽固定占位，不随分析状态插入或移除编辑器内部节点，避免目标选择、进度估计、时间输入和正文编辑器上下跳动。
- 点击“采用”只把建议转换成草稿 patch：目标建议选中目标，分类建议选中分类，新分类建议填入分类名称，未归类建议清空目标和分类。
- 用户可以忽略建议直接保存；最终保存仍由后端按 `objectiveId`、`categoryId`、`categoryName` 三选一校验。

## 编辑模型

`src/features/work-logs/workLogEditorModel.ts` 集中维护编辑草稿的不变量：

- `classificationKind` 只能是 `objective`、`category` 或 `uncategorized`。
- 选择目标会清空分类，并带入该用户对同一目标最近一次记录的目标进度估计；选择分类会清空目标和目标进度估计；未归类会清空二者。
- `category` 分为内置特殊分类和管理员管理分类；内置“请假”对所有 active 成员开放，管理员管理分类和新建分类只对指挥官/管理员开放；当前临时 FAE 例外只额外开放 `uncategorized`，不开放管理分类创建或管理分类选择。
- 保存前规范化为 `objectiveId`、`categoryId`、`categoryName` 三选一。
- AI 建议只转换成草稿 patch，不直接写入日志事实。

## 团队动态

- 默认只展示历史最新 20 条团队日志。
- 折叠态请求 21 条记录，用第 21 条判断是否显示“展开更多”，但只渲染前 20 条。
- 点击“展开更多”后读取并展示历史最新 80 条。
- 团队动态按 `workDate`、`updatedAt`、`createdAt` 派生排序；它不按当前日期筛选，当前日期只影响“我的日志”和当天记录。

## 报表

- 个人视图使用月历结构，按日期展示日志条数、覆盖归类数、归类摘要、记录时间和最新进度估计。
- 全员视图使用日期矩阵，行是 active `admin/member`，列是日期，单元格展示日志条数和记录时间或最新进度估计；有日志的单元格可打开浮层查看当日具体日志内容。
- 报表统计日志总数、有记录日期、覆盖归类数、记录时间和平均进度估计。报表响应里的后端兼容字段只作为数据源，页面展示时同样转成进度估计。
- 报表只调用 `/api/work-logs/report`，不读取或修改目标真实进度。

## 数据边界

- 页面通过 `/api/work-logs/*` 独立读写，不并入任务管理读模型。
- 当天日志、目标选项、团队动态和报表分别使用具名会话缓存键；重新进入页面时先展示缓存，保存、删除或 `workLogs` 失效事件只使对应缓存过期并后台刷新，不清空仍可使用的页面内容。
- 目标选择消费后端返回的默认目标列表、搜索目标列表和当前用户同目标最近一次日志进度估计。默认目标列表按角色派生：普通成员只包含自己正在做的目标，指挥官/管理员包含当前团队全部可挂载目标；搜索目标列表可以包含当前团队全部目标。选项状态只显示目标状态，例如“已验收”“已结算”“已关闭”；提交提示才说明这属于验收后工作/返工日志或历史记录；自己不是挑战者的目标也会提示确认目标选择。历史日志仍靠快照展示。这个默认值只来自 `work_log_entries` 的历史快照，不读取或修改 `Objective.progress`。分类选择消费后端返回的当前用户可选分类：所有人可见内置“请假”，只有指挥官/管理员可见管理分类和新建分类入口。“不指定目标”只是指挥官和当前临时 FAE 例外成员草稿里的空归类展示状态，保存时转换为 `null`。
- 智能分类建议来自 `/api/work-logs/classification-suggestion`，它只是临时 UI 状态；只有用户保存日志后才进入后端事实源。
- 日志资源来自 `/api/drive/search?contextType=workLog&contextId={entryId}` 和云盘 context-link API。页面只把 `work_log_entries.id` 作为上下文 ID，不创建日期级、用户级或目标级的第二套资源事实；当天资源块是当前日期日志条目资源的派生汇总。
- 团队动态由日志读模型派生，不反向定义日志契约。
- 保存成功后刷新团队动态，并关闭工作日志提醒横幅。
- 本机自动保存草稿只属于当前浏览器/客户端，不跨设备同步，也不是服务器草稿事实源。
- 删除或报表刷新只影响工作日志读模型，不触发目标、任务、验收或积分状态变化。
