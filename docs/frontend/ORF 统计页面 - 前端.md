# ORF 统计页面 - 前端

`/reports` 展示公开积分排行榜。管理员和普通成员都通过 `/api/reports-page` 读取同一份 `ReportsPageData` 统计页公开读模型，包含公开积分流水、目标状态、最小验收结论和成员展示投影，支持按月度、季度、年度、自定义和全部时间查看。

统计事实由 `/api/reports-page` 返回。结算通知使用 `/reports?start=YYYY-MM-DD&end=YYYY-MM-DD&objective=...` 定位成果区间；参数只控制筛选，不定义归属。旧日期链接仅用于导航，不可推断或修改归属。

## 成果周期筛选

- 周度：周一至周日；月度：自然月；季度：自然季度；年度：自然年。周期内任意日期定位同一完整周期。
- 自定义：显式起止日期，包含首尾两天。全部：保留所有积分，不计算排名变化。
- 默认展示当前自然季度。前后按钮移动完整周期；日期、月份、季度、年度选择控件直接就地操作，桌面和移动端使用同一模型。
- 只有成果区间完整包含于查询区间的账本计入该期排行榜；相交但未完整包含的记录单列“跨界成果”，不并入总分、不按天数分摊。未知归属单列“归属待确认”；全部统计仍保留原积分。
- 筛选由 `achievementPeriodRelation` 统一决定，排行榜积分、积分来源、完成率、同期排名比较使用同一筛选结果。成员按 UUID 分组。
- 归属区间来自结算事件，读模型展开为 `pointLedger.achievementPeriod`。不得从标题、目标计划周期、旧归属时间、验收时间或创建时间隐式补值。
- “结算节奏”日历按真实账本写入时间 `createdAt` 展示入账记录，不用于改变成果筛选。历史补录不挪动真实操作时间。

完成率和排名只由 `src/domain/reportsLeaderboard` 的同一套模型计算：按同一时间范围内有积分流水的成员-目标去重，目标必须最终进入 `settled` 且不是 `acceptedResult = abandoned`，并且该目标验收历史中不能出现 `objectiveAcceptanceReviews.acceptedResult = abandoned`。一旦正式验收不通过，说明截止验收未通过，该目标即使后续返工通过，也不再计入完成率的已完成数。
`userProfiles` 只包含本次读模型已引用成员的 `id`、`name`、`avatarUrl`，用于统计榜单、目标参与者头像栈和非管理页面的成员展示；邮箱、角色、状态、最近在线等用户管理字段仍只来自管理员用户接口。
表格里的积分占比只用于展示当前榜单成员相对榜首积分的条形长度，不是新的业务积分或目标进度事实源。

排行榜不按姓名、目标标题或流水原因过滤测试数据。正式榜单的数据边界由后端返回的团队 scope 和 `pointLedger` 事实源保证；seed、demo、E2E 数据必须写入独立的 demo/test team，不能混入正式业务 team。

普通成员访问统计页时不得复用“我的挑战”读模型，也不得把统计事实伪装成完整任务模型；“我的挑战”只包含当前成员参与目标，会缺失其他公开积分目标的验收历史，导致全员完成率口径不一致。`/api/reports-page` 只返回统计需要的公开事实，不返回任务、评论、战利品正文、验收原因或匿名互评原始数据。

## 排名变化

- `按月度` 的变化列对比结束日期向前移动 1 个月后的月度窗口排名。
- `按季度` 的变化列对比结束日期向前移动 3 个月后的季度窗口排名。
- `按年度` 的变化列对比结束日期向前移动 12 个月后的年度窗口排名。
- `自定义` 没有仓库已定义的上一周期，变化列显示 `-`，不计入变化人数。
- `全部时间` 没有上一周期，变化列显示 `-`，不计入变化人数。
- 新进入当前榜单且上一周期没有排名的成员，变化列显示 `新`。
- 上一周期有排名且名次不变的成员显示 `0`；排名上升或下降时显示方向和变化名次数。
