# ORF 统计页面 - 前端

`/reports` 展示公开积分排行榜。管理员和普通成员都通过 `/api/reports-page` 读取同一份 `ReportsPageData` 统计页公开读模型，包含公开积分流水、目标状态、最小验收结论和成员展示投影，支持按月度、季度、年度、自定义和全部时间查看。

系统通知可以通过 `/reports?date={settlementDate}&objective={objectiveId}` 打开统计页。`date` 只作为页面导航状态，用于把排行榜结束日期和结算日历切到对应结算日；`objective` 只用于显示目标结算定位摘要。统计事实仍只来自 `ReportsPageData.pointLedger`、目标状态和验收结论，URL 参数不能反向定义积分、完成率或结算归属。

## 时间范围

| 控件 | 规则 |
| --- | --- |
| 按月度 | 以用户选择的结束日期为锚点，向前推 1 个月，结束日期包含当天 |
| 按季度 | 以用户选择的结束日期为锚点，向前推 3 个月，结束日期包含当天 |
| 按年度 | 以用户选择的结束日期为锚点，向前推 12 个月，结束日期包含当天 |
| 自定义 | 用户显式选择开始日期和结束日期，结束日期包含当天 |
| 全部时间 | 汇总当前可见的全部积分流水 |

默认结束日期是当天。用户可以通过前后切换把结束日期按当前粒度移动：月度每次移动 1 个月，季度每次移动 3 个月，年度每次移动 12 个月；也可以在结算日历里直接点选某一天作为结束日期。自定义模式下，页面提供开始日期和结束日期两个边界，结算日历点击只更新当前选中的边界；如果用户先选较晚日期再选较早日期，模型按日期大小归一成合法范围。页面必须展示实际统计范围，例如 `2026-07-03 至 2026-08-03` 或 `2026-07-01 至 2026-08-20`，并明确结束日期包含当天。实现可以用半开区间 `start <= settlementPeriodAt < endDate + 1 day` 保证日期边界一致。

统计周期选择必须优先使用一行主控制展示：时间粒度、当前统计范围、上一/下一周期和今天入口保持在同一控制区。结算日历只是辅助用户查看每日结算分和点选日期的面板，默认不铺满页面；用户点击结束日期或自定义开始/结束边界后再展开。

结算日历按 `pointLedger.settlementPeriodAt` 的日期聚合每日结算积分和流水条数；日期格只展示该日净积分缩略值，用于帮助用户找到集中结算日期。日历不引入新的积分事实源，也不按目标标题、成员名或账本写入时间重新解释积分。

排行榜积分只来自 `pointLedger`，前端不重新计算结算分。榜单按 `pointLedger.userId` 分组，成员名和头像优先从任务/统计读模型返回的公开 `userProfiles` 展示投影派生，管理员完整 `users` 集合只作为同源覆盖；`pointLedger.memberName` 只保留结算写入时的文本快照，不参与分组、头像或排名变化判断。`pointLedger.settlementPeriodAt` 是统计周期归属时间，由后端从同目标最后一条通过验收的 `objectiveAcceptanceReviews.reviewedAt` 写入；`pointLedger.createdAt` 只表示账本写入时间，不能决定月度、季度、年度或自定义范围归属。完成率和排名只由 `src/domain/reportsLeaderboard` 的同一套模型计算：按同一时间范围内有积分流水的成员-目标去重，目标必须最终进入 `settled` 且不是 `acceptedResult = abandoned`，并且该目标验收历史中不能出现 `objectiveAcceptanceReviews.acceptedResult = abandoned`。一旦正式验收不通过，说明截止验收未通过，该目标即使后续返工通过，也不再计入完成率的已完成数。
`userProfiles` 只包含本次读模型已引用成员的 `id`、`name`、`avatarUrl`，用于统计榜单、目标参与者头像栈和非管理页面的成员展示；邮箱、角色、状态、最近在线等用户管理字段仍只来自管理员用户接口。
表格里的积分占比只用于展示当前榜单成员相对榜首积分的条形长度，不是新的业务积分或目标进度事实源。

排行榜不按姓名、目标标题或流水原因过滤测试数据。正式榜单的数据边界由后端返回的团队 scope 和 `pointLedger` 事实源保证；seed、demo、E2E 数据必须写入独立的 demo/test team，不能混入正式业务 team。

普通成员访问统计页时不得复用“我的挑战”读模型，也不得把统计事实伪装成完整任务模型；“我的挑战”只包含当前成员参与目标，会缺失其他公开积分目标的验收历史，导致全员完成率口径不一致。`/api/reports-page` 只返回统计需要的公开事实，不返回任务、评论、战利品正文、验收原因或匿名互评原始数据。

## 排名变化

- `按月度` 的变化列对比结束日期向前移动 1 个月后的月度窗口排名。
- `按季度` 的变化列对比结束日期向前移动 3 个月后的季度窗口排名。
- `按年度` 的变化列对比结束日期向前移动 12 个月后的年度窗口排名。
- `自定义` 没有仓库已定义的上一周期，变化列显示 `-`，不计入变化人数。
- `全部时间` 没有上一周期，变化列显示 `-`，不计入变化人数。
- 新进入当前榜单且上一周期没有排名的成员，变化列显示 `新`。
- 上一周期有排名且名次不变的成员显示 `0`；排名上升或下降时显示方向和变化名次数。
