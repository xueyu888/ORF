# ORF 反馈收件箱 - 前端

`/feedback` 展示当前用户可见范围内的内部反馈列表，采用 GitHub issue 风格的搜索、状态切换和单列表结构。

## 入口显隐

- `新建反馈` 只在当前状态存在可见指标时展示。
- 没有可见指标的普通成员或观察者不能从反馈收件箱打开创建反馈弹窗。
- 反馈创建的最终权限仍以后端 `/api/feedback` 校验为准，前端只负责避免展示不可完成入口。

## 新建反馈

- 反馈收件箱只处理内部反馈；新建弹窗不展示来源选择。
- 前端创建反馈时统一提交内部复盘来源，避免用户在创建表单里维护外部/内部来源事实。
- 处理人来自当前活跃成员列表，避免把不可处理的文本处理人提交给后端。

## 页面结构

- 顶部只保留搜索输入、原因筛选、状态筛选和重置操作。
- 列表头只展示 `Open`、`Closed`、`All` 三个列表状态及匹配数量。
- 每条反馈以 issue 行展示：状态图标、标题、原因标签、影响标签、反馈 ID、处理人、更新时间、当前状态和关联指标。
- 搜索和筛选只维护页面展示状态，不回写反馈事实源。
