# ORF 反馈收件箱 - 前端

`/feedback` 展示当前团队作用域内的内部反馈列表，采用 GitHub issue 风格的搜索、状态切换和单列表结构，并复用悬赏大厅幻想皮肤。

## 入口显隐

- `新建反馈` 在当前用户为 active 成员时展示。
- 反馈是团队级内部 issue，不要求也不展示关联指标。
- 反馈创建的最终权限仍以后端 `/api/feedback` 校验为准，前端只负责避免向非 active 用户展示不可完成入口。

## 新建反馈

- 反馈收件箱只处理内部反馈；新建弹窗不展示来源选择。
- 前端创建反馈时不提交来源字段；团队内部属性由反馈模型和路由边界表达。
- 新建弹窗只提交标题、说明、分类、影响和处理人；目标或指标不参与必填校验。
- 处理人来自当前活跃成员列表，避免把不可处理的文本处理人提交给后端。

## 页面结构

- 顶部只保留搜索输入、分类筛选和重置操作。
- 列表头只展示 `Open`、`Closed`、`All` 三个列表状态及匹配数量。
- 每条反馈以 issue 行展示：状态图标、标题、原因标签、影响标签、反馈 ID、处理人、更新时间、Open/Closed 状态和评论数量。
- 点击任意反馈行进入 `/feedback/:feedbackId` 详情页；列表页不承载回复、关闭或重新打开动作。
- 反馈详情说明文本中的 `/path` 内部链接用前端路由跳转，`http://` / `https://` 外部链接在新窗口打开。
- 搜索和筛选只维护页面展示状态，不回写反馈事实源。

## 详情页

- 详情页采用 issue 结构：顶部展示标题、Open/Closed、短 ID、处理人、更新时间和评论数。
- 主体左侧展示原始反馈说明和评论时间线，右侧展示状态、处理人、分类、影响和时间。
- 评论时间线复用共享评论输入器，支持发送评论、回复、`@` 成员、粘贴或选择图片。
- `@` 候选人来自当前反馈目标的 `/api/comments/mentionable-users?targetType=feedback&targetId=...`。
- 关闭和重新打开只在当前用户有反馈状态管理权限时展示；打开态关闭后写入 `Closed`，关闭态重新打开后写回 `Open`。
- 详情页不展示、编辑或要求关联指标；反馈可以是技术问题、管理问题、系统问题或其他团队内部问题。
