# ORF 我的挑战页面 - 前端

## 页面定位

`/tasks` 是挑战工作台。普通成员看到自己已正式接受的目标，以及目标下并列的指标、任务和子任务；指挥官在所有挑战视图中创建、编辑和发布候选目标。

普通成员只看自己参与的目标；管理员可切换所有挑战 / 我的挑战。

我的挑战过滤规则：

```text
currentUser in Objective.challengers
```

目标来自挑战页内候选目标创建、悬赏大厅申请、征召或接受挑战流程；普通成员未正式接受的目标不在本页展示。

数据加载边界：普通成员只请求 `/api/my-challenges?scope=mine` 等成员可访问接口，不主动请求 `/api/permissions` 或 `/api/users` 等管理员集合。管理员进入业务页时才额外加载权限规则和成员列表。后端兼容的 `/api/tasks-page` 对普通成员也只返回 scoped `my-challenges` 数据，不返回全量 state。

## 页面内容

| 区域 | 内容 |
| --- | --- |
| 全局概览 | 管理员在所有挑战视图下可见：已结算、目标总体进度、待征召、待验收 |
| 工具栏 | 所有挑战 / 我的挑战、周期、状态筛选；状态筛选包含目标层级的“未分配”，按 `Objective.challengers` 为空判断 |
| 新建目标草稿行 | 有 `objective.create` 权限时在挑战树内插入完整目标草稿面板；草稿按目标统一排序进入未分配候选区，标题输入按 Enter 或输入框失焦快速生成 `candidate` 目标行；请求发起后立即退出标题编辑态，API 返回真实目标后必须连续替换草稿，刷新完成前不能出现目标消失或跳位 |
| 挑战树 | `Objective -> Result` 与 `Objective -> Task -> TaskChecklistItem` 两条分支 |

## 行字段

### 目标行

展示：

- 目标标题。
- 目标状态。
- 挑战者头像组，来源 `Objective.challengers`。
- 剩余时间，来源 `Objective.finalDueAt`。
- 截止时间。
- 目标进度，来源 `Objective.progress`。
- `提交战利品` 入口；仅 `flowStatus=frozen` 且当前用户是挑战者时展示。

### 指标行

展示：

- 指标标题。
- 难度 / 不确定性分。
- 验收状态。
- 指标进度。
- 最近更新时间，来源为指标趋势、反馈和历史材料。

指标不展示目标剩余时间、挑战者列或负责人。

### 任务和子任务行

展示标题、勾选框和更新时间。任务归属于目标，不挂到指标下；勾选只表示执行进度，不触发验收或积分结算。

## 状态

### 目标状态

| 状态 | 含义 |
| --- | --- |
| 候选中 | 指挥官刚创建，尚未发布到悬赏大厅 |
| 重估中 | 挑战者已确认，正在重估目标下指标和任务 |
| 已冻结 | 重估完成，指标口径冻结，可提交战利品 |
| 待验收 | 已提交战利品，等待验收 |
| 已结算 | 验收和积分结算完成 |

## 交互

| 操作 | 规则 |
| --- | --- |
| 新建目标 | 从顶部栏或命令菜单进入本页创建入口；在挑战树内复用目标面板创建草稿，草稿立即展示目标头、待定义指标和待创建行动项；标题输入按 Enter 或输入框失焦调用创建接口，请求发起后立即退出标题编辑态，创建成功后真实目标连续替换草稿；标题变化、API 源顺序变化、页面数据刷新和点击其他区域都不能触发目标面板重排、消失或重新进入编辑态；创建失败时回到标题编辑态并保留输入 |
| 新增指标 | 指挥官从目标行新增 |
| 提出指标 | 挑战者在自己参与目标的未过期重估期从目标行提出 |
| 编辑指标 | 指挥官可编辑未冻结目标下指标；挑战者可编辑自己参与目标的未过期重估期指标 |
| 新增任务 | 从目标行新增 |
| 新增子任务 | 从任务行新增 |
| 编辑标题 | 行操作或双击进入编辑 |
| 勾选任务 / 子任务 | 只更新执行进度 |
| 拖拽排序 | 指标只在同一目标内排序；任务只在同一目标内排序；子任务可在允许范围内移动 |
| 删除 | 删除前确认，并展示影响范围 |
| 评论 | 从行操作打开评论 |
| 提交战利品 | 只在目标冻结后从目标行进入提交页 |
| 发布/冻结 | 指挥官在所有挑战视图中操作 |
| 审核挑战申请 | 指挥官在目标行处理待审核申请 |

权限由 `permissionRules` 和状态机共同控制。目标内容只能由指挥官调整；指标可由指挥官编辑，挑战者只可在 `reestimating` 且未过 `confirmationDueAt` 时提出或编辑自己参与目标下的指标。冻结后指标口径锁定。

反馈状态控件仅对管理员、反馈创建人或反馈 `owner` 指定处理人显示。普通成员可以看到自己可见范围内的反馈内容，但不能关闭或改写他人反馈状态。

## 布局要求

- 我的挑战是高密度工作台，优先保证可扫描和列对齐。
- 目标排序统一为：候选中目标、未分配的待申请/待征召目标、已分配执行中的目标、待验收目标、已结算目标、已关闭目标。同一组内先按截止时间升序，再按创建日期降序；业务排序键相同则保留数据源顺序。目标标题不是列表排序键，避免用户编辑标题时改变当前目标位置。
- 新建目标草稿和创建成功后的真实目标共用同一套目标面板结构，渲染待定义指标和待创建行动项，草稿阶段只禁用依赖真实目标 id 的业务动作。提交草稿时记录草稿前后的目标邻居和当时的业务排序键；请求等待期间草稿以非编辑标题形态留在原位，API 返回真实目标后用该真实目标作为页面级临时覆盖层连续替换草稿，直到页面数据刷新包含同一目标后撤掉覆盖层。用户手动切换范围、周期、状态或目标业务状态变化后锚点失效，回到全局排序。
- 目标、指标、任务、子任务共用同一套列结构；指标和任务是目标下并列分支，不能用缩进或树线暗示任务属于指标。
- 树线、缩进、折叠入口只在主标题列内定位。
- 目标剩余时间按分钟展示，不显示秒；指标行不重复展示目标剩余时间。
- 长标题单行省略，不能挤压右侧列。
- 进度列宽度固定，百分比变化不能造成布局跳动。
