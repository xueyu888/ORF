# ORF 我的挑战页面 - 前端

## 页面定位

`/tasks` 是挑战工作台。普通成员看到自己已正式接受的目标，以及目标下并列的指标、任务和子任务；指挥官在所有挑战视图中创建、编辑和发布候选目标。

普通成员只看自己参与的目标；管理员可切换所有挑战 / 我的挑战。

我的挑战过滤规则：

```text
currentUser in Objective.challengers
```

悬赏大厅对所有已通过用户可见，但它只是发现页，不决定工作台归属。目标来自挑战页内候选目标创建、悬赏大厅申请、征召或接受挑战流程；普通成员只有在申请被通过或接受征召后，目标才进入本页。

数据加载边界：普通成员只请求 `/api/my-challenges?scope=mine` 等成员可访问接口，不主动请求 `/api/permissions` 或 `/api/users` 等管理员集合。管理员进入业务页时才额外加载权限规则和成员列表。后端兼容的 `/api/tasks-page` 对普通成员也只返回 scoped `my-challenges` 数据，不返回全量 state。

## 页面内容

| 区域 | 内容 |
| --- | --- |
| 全局概览 | 管理员在所有挑战视图下可见：已结算、目标总体进度、待征召、待验收 |
| 工具栏 | 所有挑战 / 我的挑战、周期、状态筛选；状态筛选包含目标层级的“未分配”，按 `Objective.challengers` 为空判断 |
| 新建目标 temporary 行 | 有 `objective.create` 权限时在挑战树内插入 temporary 目标行；temporary 目标按目标统一排序进入未分配候选区，标题输入按 Enter 或输入框失焦快速生成 `candidate` 目标行；请求发起后立即退出标题编辑态，API 返回真实目标后必须连续替换为 persisted 目标，刷新完成前不能出现目标消失或跳位；没有真实指标或行动项时不渲染伪子行，新增必须通过目标行 `+` 发起 |
| 挑战树 | `Objective -> Result` 与 `Objective -> Task -> TaskChecklistItem` 两条分支 |

## 行字段

### 目标行

展示：

- 目标标题。
- 目标状态。
- 挑战者头像组，来源 `Objective.challengers`。
- 剩余时间，来源 `Objective.finalDueAt`。
- 截止时间；指挥官可在目标行内编辑 `Objective.finalDueAt`。冻结前可正常调整，`frozen` 只允许延后，`submitted/settled/closed` 不显示编辑入口。
- 目标进度，来源 `Objective.progress`。
- `提交战利品` 入口；仅 `flowStatus=frozen` 且当前用户是挑战者时展示。
- `处理试验收` 入口；仅 `flowStatus=frozen`、当前用户为指挥官且存在待反馈试验收时展示。
- hover 工具层包含一个主新增 `+`；点击后选择新增指标或新增行动项。

### 指标行

展示：

- 指标标题。
- 难度 / 不确定性分。
- 验收状态。
- 指标进度。
- 最近更新时间，来源为指标趋势、反馈和历史材料。

指标不展示目标剩余时间、挑战者列或负责人。

指标行不展示 `+`。当前模型中指标没有子级对象，任务也不归属于指标。

### 任务和子任务行

展示标题、勾选框和更新时间。任务归属于目标，不挂到指标下；同一目标的正式挑战者都可以维护该目标下所有任务和子任务，指挥官按管理员权限维护。任务行 hover 工具层包含一个 `+`，点击后直接新增该任务的子任务；`assignee` 只作为执行提示，创建人不形成前端操作锁。勾选只表示执行进度，不触发验收或积分结算。勾选任务或子任务时，前端在挑战页数据合成层使用短生命周期完成状态覆盖层立即反馈点击结果；后端刷新数据仍是持久化事实源，刷新数据包含同一完成状态后撤销覆盖层，失败时撤销覆盖层并按后端事实刷新。

## 状态

### 目标状态

| 状态 | 含义 |
| --- | --- |
| 候选中 | 指挥官刚创建，尚未发布到悬赏大厅，可先定义指标和目标行动项 |
| 重估中 | 挑战者已确认，正在重估目标下指标和任务 |
| 已冻结 | 重估完成，指标口径冻结，可提交战利品 |
| 待验收 | 已提交战利品，等待验收 |
| 已结算 | 验收和积分结算完成 |

### 新建目标会话状态

`objectiveCreationSession` 是页面内唯一的目标创建 UI 状态源；后端目标列表仍是业务事实源。

| 状态 | UI 表现 | 退出条件 |
| --- | --- | --- |
| `idle` | 不显示 temporary 目标 | 点击 `新建目标` |
| `editingDraft` | 显示完整 temporary 目标面板，标题输入框聚焦 | Enter / 失焦提交，或 Escape 取消 |
| `submittingDraft` | temporary 目标留在原位但退出标题编辑态，状态列显示“保存中” | `POST /api/objectives` 返回成功或失败 |
| `submittedOverlay` | 用 POST 返回的真实目标替换 temporary 目标，继续沿用 temporary 目标位置 | 任务数据刷新后包含同一目标，或用户手动切换筛选 |
| `anchoredCreated` | 使用已刷新的后端目标行，但继续保留一次性排序锚点 | 用户手动切换筛选，或业务排序键变化 |
| `failedEditingDraft` | 回到标题输入框并保留用户输入 | 再次提交或取消 |

## 交互

| 操作 | 规则 |
| --- | --- |
| 新建目标 | 从顶部栏或命令菜单进入本页创建入口；在挑战树内复用目标面板创建 temporary 目标，temporary 阶段只展示目标行，不预置“待定义指标”或“待创建行动项”伪子行；标题输入按 Enter 或输入框失焦调用创建接口，请求发起后立即退出标题编辑态并显示“保存中”，创建成功后真实目标连续替换 temporary 目标；提交中重复点击 `新建目标` 只提示“目标正在创建，请稍后”，不能发起第二次创建；标题变化、API 源顺序变化、页面数据刷新和点击其他区域都不能触发目标面板重排、消失或重新进入编辑态；创建失败时回到标题编辑态并保留输入 |
| 新增指标 | 指挥官点击目标行唯一主新增 `+`，在类型选择层选择新增指标后插入指标 temporary 行并进入标题编辑；提交后后端返回的真实指标进入一次性创建覆盖层并替换 temporary 行，挑战页刷新数据包含同一真实 id 后撤掉覆盖层；成功后不自动生成下一条指标 temporary 行 |
| 提出指标 | 挑战者在自己参与目标的未过期重估期，点击目标行唯一主新增 `+`，在类型选择层选择提出指标后插入指标 temporary 行并进入标题编辑；提交后后端返回的真实指标进入一次性创建覆盖层并替换 temporary 行，挑战页刷新数据包含同一真实 id 后撤掉覆盖层；成功后不自动生成下一条指标 temporary 行 |
| 编辑指标 | 指挥官可编辑未冻结目标下指标；挑战者可编辑自己参与目标的未过期重估期指标 |
| 新增任务 | 指挥官或正式挑战者点击目标行唯一主新增 `+`，在类型选择层选择新增行动项后插入行动项 temporary 行并进入标题编辑；提交后后端返回的真实任务进入一次性创建覆盖层并替换 temporary 行，挑战页刷新数据包含同一真实 id 后撤掉覆盖层；成功后不自动生成下一条行动项 temporary 行 |
| 新增子任务 | 同一目标正式挑战者或指挥官点击任务行 `+` 后，在当前任务下插入子任务 temporary 行；提交后后端返回的真实子任务进入一次性创建覆盖层并替换 temporary 行，挑战页刷新数据包含同一真实 id 后撤掉覆盖层；成功后不自动生成下一条子任务 temporary 行 |
| 编辑标题 | 行操作或双击进入编辑 |
| 勾选任务 / 子任务 | 同一目标正式挑战者或指挥官可操作，只更新执行进度；点击后勾选状态立即展示，后端写入和刷新成功后由后端数据接管；失败时回到后端事实并提示 |
| 拖拽排序 | 指标只在同一目标内排序；任务只在同一目标内排序；子任务可在当前用户有维护权限的目标任务范围内移动 |
| 删除 | 同一目标正式挑战者或指挥官可删除任务和子任务；删除前确认，并展示影响范围 |
| 评论 | 从行操作打开评论 |
| 提交战利品 | 只在目标冻结后从目标行进入提交页 |
| 修改截止日期 | 只允许指挥官操作；冻结前可修改为合法日期，冻结后只能延后，待验收、已结算和已关闭目标不可修改 |
| 发布/冻结 | 指挥官在所有挑战视图中操作 |
| 审核挑战申请 | 指挥官在目标行处理待审核申请；审批成功后立即刷新目标状态和申请记录，当前目标使用列表位置锚点保持原展示位置，直到用户离开当前目标上下文 |

权限由 `permissionRules` 和状态机共同控制。目标内容只能由指挥官调整；截止日期以 `Objective.finalDueAt` 为唯一事实源。指标可由指挥官编辑，挑战者只可在 `reestimating` 且未过 `confirmationDueAt` 时提出或编辑自己参与目标下的指标。候选目标允许指挥官先维护目标行动项；挑战者正式进入 `Objective.challengers` 后，任务和子任务的新增、编辑、勾选、移动、删除都按目标共同维护，不按 `assignee` 或创建人区分。冻结后指标口径锁定。

反馈状态控件仅对管理员、反馈创建人或反馈 `owner` 指定处理人显示。普通成员可以看到自己可见范围内的反馈内容，但不能关闭或改写他人反馈状态。

## 布局要求

- 我的挑战是高密度工作台，优先保证可扫描和列对齐。
- 目标排序统一为：候选中目标、未分配的待申请/待征召目标、已分配执行中的目标、待验收目标、已结算目标、已关闭目标。同一组内先按截止时间升序，再按创建日期降序；业务排序键相同则保留数据源顺序。目标标题不是列表排序键，避免用户编辑标题时改变当前目标位置。
- 操作上下文位置稳定性是挑战页列表展示不变量。后端事实源立即刷新；正在操作的目标通过短生命周期位置锚点保持当前展示位置；点击其他目标、切换范围、切换筛选、离开页面或目标不再属于当前视图时释放锚点并恢复统一排序。
- 新建目标 temporary 行和创建成功后的 persisted 目标共用同一套目标面板结构；没有真实指标或行动项时不渲染“待定义指标”和“待创建行动项”伪子行，避免把不可编辑占位误认为业务行。真实目标行 hover 只保留一个主新增 `+`，点击后打开类型选择层，从当前权限和状态允许的 `新增/提出指标`、`新增行动项` 中选择一项。指标行没有 `+`；任务行 `+` 直接新增该任务的子任务。每次点击 `+` 只插入一条对应类型的 temporary 行，保存成功后替换为 persisted 行，不自动补出下一条 temporary 行。temporary 阶段只禁用依赖真实 id 的业务动作。指标、行动项和子任务行只有 `temporary / persisted` 的持久化差异：temporary 行保存标题后调用创建接口，并由后端返回的真实实体进入一次性创建覆盖层；persisted 行保存标题后走更新接口。创建覆盖层只桥接 POST 成功到 `/api/my-challenges` 刷新包含同一真实 id 之间的窗口，不能成为第二套长期业务事实源。提交目标标题时记录 temporary 目标前后的目标邻居和当时的业务排序键；请求等待期间目标以非编辑标题形态留在原位，`POST /api/objectives` 返回后立即用真实目标作为页面级临时覆盖层连续替换 temporary 目标，任务数据刷新只负责撤掉覆盖层，一次性排序锚点继续保留到用户手动切换筛选或目标业务排序键变化。用户手动切换范围、周期、状态或目标业务状态变化后锚点失效，回到全局排序。
- 目标、指标、任务、子任务共用同一套列结构；指标和任务是目标下并列分支，不能用缩进或树线暗示任务属于指标。
- 树线、缩进、折叠入口只在主标题列内定位。
- 目标剩余时间按分钟展示，不显示秒；指标行不重复展示目标剩余时间。
- 长标题单行省略，不能挤压右侧列。
- 进度列宽度固定，百分比变化不能造成布局跳动。
