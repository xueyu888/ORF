# 评论组件 - 前端

本文档记录 `src/features/challenge/comments/CommentPanel.tsx` 的展示和交互。

评论业务接口、权限和持久化规则见 [评论组件 - 后端.md](../backend/评论组件%20-%20后端.md)。

## 1. 绑定对象

评论窗口或内联评论区绑定当前对象。挑战页使用右下角浮窗；反馈详情页内联复用评论输入、正文渲染、@ 候选和图片上传能力。

| 对象 | 入口 |
| --- | --- |
| 目标 | 目标行块菜单、目标评论数量入口 |
| 指标 | 指标行块菜单、指标评论数量入口 |
| 任务 | 任务行块菜单、任务评论数量入口 |
| 子任务 | 子任务行块菜单、子任务评论数量入口 |
| 反馈 issue | 反馈详情页评论时间线 |

## 2. 组件结构

```text
<CommentPanel>
├─ <CommentPanelHeader>
│  ├─ 当前块标题
│  └─ 关闭按钮
├─ <CommentView>
│  ├─ <RootCommentListView>
│  │  └─ <CommentMessageRow>[]
│  │     └─ <CommentInlineEditor>?
│  └─ <ReplyDetailView>
│     ├─ 返回按钮
│     ├─ 顶部固定外层评论
│     └─ 回复消息列表
└─ <CommentComposer>
   ├─ 当前用户
   ├─ <OrfRichTextEditor>
   │  ├─ 所见即所得编辑区
   │  ├─ 加粗 / 斜体 / 删除线 / 列表 / 引用 / 链接工具栏
   │  ├─ @ 成员候选浮层
   │  └─ 图片上传入口
   ├─ 图片上传状态
   ├─ `Enter 发送，Shift + Enter 换行`
   └─ 发送按钮
```

## 3. 展示规则

| 内容 | 当前实现 |
| --- | --- |
| 窗口位置 | 右下角浮窗 |
| 拖拽 | 标题栏可拖拽 |
| 宽度 | `382px`，移动端不超过视口宽度 |
| 标题 | 展示当前块标题 |
| 空评论 | 显示 `暂无评论` |
| 空回复 | 显示 `暂无回复` |
| 外层评论排序 | 按创建时间倒序 |
| 回复排序 | 按创建时间正序 |
| 评论时间 | 1 分钟内显示 `刚刚`，1 小时内显示 `N 分钟前`，24 小时内显示 `N 小时前`，更早评论直接显示本地 `YYYY-MM-DD HH:mm`；所有有效时间的 `time` 元素带完整本地分钟级 `title` 和 ISO `dateTime` |
| 回复对象标记 | 回复内层评论时显示 `回复{作者}:` |
| 回复入口 | 仅外层评论已有回复时显示 `共 x 条回复`，无回复评论不展示空钻取入口 |
| 行内评论入口 | 挑战页跟随目标、指标、任务或子任务标题文本后方展示；有评论时显示评论数量，0 条评论时仅在对应行悬浮或聚焦时显示无数量评论图标；反馈列表行展示 issue 评论数量 |
| 评论窗口身份 | 以绑定对象的类型和 id 为边界，不以标题作为唯一身份 |
| 切换绑定对象 | 从一个块切换到另一个块的评论窗口时，清空回复、编辑、选中评论和回复详情状态 |
| Markdown 展示 | 评论正文通过共享 `OrfRichTextMarkdownViewer` 渲染，支持段落、标题、列表、引用、加粗、斜体、删除线、行内代码、链接、提及和图片附件 |
| 链接展示 | 显式 Markdown 链接、`http://`、`https://` 和 `www.` 链接自动转为可点击外链，新窗口打开；正文事实源仍是 ORF Markdown `body` |
| 标题链接 | URL 位于明确标题之后或独占标题下一行时，隐藏 URL，把标题文本显示为可点击外链；该兼容逻辑在共享 viewer 中实现，不保留评论专属解析器 |
| 图片展示 | 正文中的 `![alt](orf-attachment:{id})` 渲染为内联图片，图片内容从后端受控接口读取 |
| 图片查看 | 点击内联图片打开大图预览；点击遮罩、关闭按钮或按 `Esc` 关闭 |
| @ 提及展示 | 正文中的 `@[显示名](orf-user:{userId})` 渲染为轻量内联 `@当前成员名`；找不到当前成员名时使用 token 内显示名 |
| 评论头像 | 评论消息优先使用 `message.authorAvatarUrl`；候选人和输入区优先使用用户 `avatarUrl`；缺失或加载失败回退首字母 |
| 编辑器事实源 | `OrfRichTextEditor` 内部使用 Tiptap 文档作为临时编辑状态；提交给业务接口的正文仍是 ORF Markdown `body` 文本 |
| 展示事实源 | 评论展示不读取 Tiptap JSON；只读取持久化 `body` 和附件列表，并由共享 viewer 派生页面结构 |
| 编辑态图片预览 | 已上传评论附件使用后端返回的 `attachment.contentUrl`；新建反馈的 pending 附件使用本地 object URL；两者都只是展示状态，不写入正文 |

## 4. 交互

| 操作 | 结果 |
| --- | --- |
| 点击块菜单 `评论` | 打开当前块评论窗口 |
| 点击行内评论入口 | 打开当前块评论窗口 |
| 点击关闭按钮 | 关闭评论窗口 |
| 拖拽标题栏 | 移动评论窗口 |
| 点击评论行 | 选中当前评论行 |
| 点击回复按钮 | 输入框进入回复状态 |
| 回复或行内编辑中点击其他块的评论入口 | 打开新块评论窗口，清空回复草稿和行内编辑状态 |
| 点击 `共 x 条回复` | 进入回复详情视图，仅在 x 大于 0 时出现 |
| 点击返回按钮 | 返回外层评论列表 |
| 点击编辑按钮 | 本人或管理员可在原评论行内编辑 |
| 双击评论正文 | 本人或管理员可在原评论行内编辑 |
| 点击删除按钮 | 本人或管理员可删除，确认文案为 `删除这条评论？` |
| 在编辑器粘贴图片 | 上传图片，成功后在光标处插入图片节点；提交时序列化为附件 token |
| 点击图片按钮 | 打开本地图片选择器，成功后在光标处插入图片节点；提交时序列化为附件 token |
| 点击链接按钮 | 打开内置链接编辑条；只接受 `http://`、`https://` 或站内 `/...` 路径 |
| 输入 `@` | 打开当前评论目标可提及成员候选浮层 |
| 继续输入关键字 | 按姓名和邮箱过滤候选成员 |
| 点击候选或按 Enter | 编辑器显示 `@成员名` 提及节点，光标保留在提及节点后 |
| 按 Esc | 关闭 @ 候选浮层，不清空已输入正文 |
| 点击评论图片 | 打开当前图片的大图预览 |
| 关闭图片预览 | 点击遮罩、关闭按钮或按 `Esc` |
| 点击发送按钮 | 按当前输入状态发送评论、回复或保存编辑 |
| `Enter` | @ 候选浮层未接管且非输入法组合态时，按当前输入状态提交 |
| `Shift + Enter` | 在编辑器中插入换行 |
| `Ctrl / Cmd + Enter` | 兼容旧快捷键，按当前输入状态提交 |

## 5. @ 提及流程

1. 评论入口打开后，按当前 `targetType` / `targetId` 拉取 `/api/comments/mentionable-users`；`targetType` 可以是 `objective`、`result`、`task`、`subtask` 或 `feedback`。
2. 所见即所得编辑器检测光标前最近的 `@关键字`；关键字不能跨空格、换行或已有提及节点。
3. 候选浮层展示 active 成员头像、姓名和邮箱，排除当前用户本人。
4. 选择成员后，编辑器展示可读的 `@成员名` 提及节点，节点属性保存 `{ userId, label }`。
5. 提交或保存编辑时，前端把提及节点序列化为稳定 token：`@[成员名](orf-user:{userId})`。
6. 展示评论时，前端按 token 中的 `userId` 优先映射当前成员名；成员改名后刷新页面显示新名字。
7. 编辑历史评论时，前端把 token 反解析成可读的提及节点；非法 token 降级为普通文本，不产生提及通知。
8. 普通 `@文本` 不高亮、不通知，只作为普通正文。
9. 第一版不因为编辑新增 token 而补发通知。

提及候选浮层是评论富文本编辑器内部能力，不进入全局命令菜单，也不改变成员管理的用户数据所有权。

## 6. 图片上传流程

1. `OrfRichTextEditor` 监听 `paste` 和文件拖放。
2. 用户也可以点击图片按钮选择本地图片。
3. 如果是已存在评论、回复或反馈详情评论，前端调用 `/api/comments/attachments`。
4. 上传接口返回 `{ markdown, attachment }`；`markdown` 是正文事实，`attachment.contentUrl` 只用于编辑态预览。
5. 新建反馈首条正文还没有评论目标，前端先创建 `![文件名](orf-pending-attachment:{clientId})` 和本地 object URL；提交反馈时后端把 pending token 替换为正式附件 token。
6. 上传期间编辑器保留焦点，并在 footer 展示上传中状态。
7. 上传成功后，把 `markdown` 转换为编辑器图片节点插入当前光标位置；如果存在预览 URL，编辑器直接显示图片，否则显示受控占位。
8. 上传失败时展示错误提示，不清空用户已输入正文。
   - `413`：提示图片过大，需要压缩后再上传。
   - `415`：提示只支持 PNG、JPEG、GIF 或 WebP。
   - `400`：提示图片文件无效。
   - `403`：提示没有权限上传这个评论图片。
9. 提交评论时，编辑器图片节点重新序列化为附件 token，正文和图片 token 一起交给现有评论接口。

第一版支持粘贴、拖放和文件选择图片。非图片附件可复用同一附件模型后再扩展。

## 7. 输入状态

| 状态 | 输入框提示 | 提交按钮含义 |
| --- | --- | --- |
| 默认评论 | `添加评论...` | 发送评论 |
| 回复外层评论 | `回复 {作者}...` | 发送回复 |
| 回复详情默认输入 | `添加回复...` | 发送回复 |
| 回复内层评论 | `回复 {作者}...` | 发送回复 |
| 行内编辑评论 | `编辑评论...` | 保存评论 |

## 8. 暂不包含

- 点赞或表情反应。
- 非图片文件附件。
- 图片裁剪、压缩和批量管理。
- 链接卡片预览。
