## 2. 当前页页面结构

### 2.1 核心理念

悬赏大厅是 ORF 的主动贡献入口。

成员通过提出候选悬赏指标、申请挑战悬赏指标、提交战利品并通过验收来证明自己对组织目标的贡献。征召模式用于主线悬赏指标无人挑战时的组织兜底，不作为默认任务分发方式。个人评价统一回到积分结果：谁完成并通过验收的贡献更多，谁的积分更高。

权限口径：页面里的“指挥官定义 / 采纳 / 确认”是产品文案；入口显示和操作执行按管理员权限判断。

页面结构需要突出三件事：

- 当前用户已经获得多少积分贡献。
- 当前用户是否有被指挥官指定且需要接受挑战的征召。
- 当前用户是否有候选悬赏指标被采纳后的优先挑战权。
- 当前还有哪些悬赏指标可以申请挑战。

悬赏大厅只负责提出候选悬赏指标、发现悬赏指标、申请挑战、接受优先挑战和接受征召。挑战中、确认中、待提交、待验收、已结算等执行态统一回到挑战页查看和处理。

默认进入 `可申请挑战悬赏指标` 视图：

- 主体只展示当前可申请挑战的悬赏指标。
- 与当前用户相关的征召展示在主体内容上方。
- 与当前用户相关的优先挑战展示在征召令下方。
- 我的积分贡献展示在页面上方，作为贡献反馈结果。
- 确认中、已挑战、待提交、待验收和已结算悬赏指标不在大厅展开，用户通过 `我的挑战` 跳转到挑战页处理。

### 3.4 布局与视觉要求

悬赏大厅是桌面端 Web 工作台。页面需要表达主动贡献和积分反馈，同时保持可扫描。

| 区域 | 要求 |
| --- | --- |
| 页面头部 | 标题、周期提示和管理员操作保持在页面顶部。 |
| 我的贡献概览 | 使用一行指标摘要展示积分、排名和积分明细入口；不展示挑战中、待提交、待验收、已结算等执行状态。 |
| 征召令 | 当前用户有征召时展示在工具栏上方；多条征召按紧迫程度排列。 |
| 优先挑战 | 当前用户有优先挑战权时展示在征召令下方；默认显示 2 小时倒计时。 |
| 工具栏 | 搜索靠左，筛选和排序靠右；已选筛选条件展示为可移除标签。 |
| 可申请挑战悬赏指标 | 使用卡片列表展示；卡片宽度和高度保持稳定。 |
| 悬赏指标卡片 | 卡片是唯一重复卡片层级；卡片内主操作固定在底部。 |
| 卡片标题 | 标题最多两行，超出省略；目标名称单行省略。 |
| 卡片默认信息 | 默认只展示标题、目标、类型、难度、不确定性分、剩余时间、指标快照和申请挑战。 |
| 卡片辅助信息 | 验收摘要、任务数量、评论数量和更多操作在 hover / focus 或预览抽屉中展示。 |
| 积分展示 | 不确定性分和难度需要在卡片上可见，帮助用户判断贡献收益。 |
| 视觉风格 | 可以使用 ORF fantasy-ui 的面板、徽章、分隔线和图标语言；输入、筛选和列表保持克制，不做重装饰游戏首页。 |

### 3.5 状态口径

悬赏大厅主内容只展示可申请挑战的悬赏指标。

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| 优先挑战中 | 成员提出的候选悬赏指标已被采纳，提出人有 2 小时优先挑战权 | 优先挑战区 |
| 可申请 | 悬赏指标已发布，当前可申请挑战 | 可申请挑战悬赏指标列表 |
| 公共池 | 提出人放弃或超时后的成员提出悬赏指标 | 可申请挑战悬赏指标列表 |
| 征召中 | 主线悬赏指标由指挥官指定当前用户接受挑战 | 征召令 |

确认中、挑战中、待提交、待验收、已结算等状态不在悬赏大厅展示，统一在挑战页处理。

点击 `申请挑战` 后只表示申请意愿；指挥官确认且挑战者接受后，才进入确认期并成为当前挑战者。优先挑战和征召中的 `接受挑战` 会直接成为挑战者并进入确认期。

### 3.6 页面字段口径

| 字段 | 用途 |
| --- | --- |
| `Result.owner` | 当前挑战者；未接受挑战前为空，不承载目标层责任语义。 |
| `Result.finalDueAt` | 悬赏指标最终截止时间；大厅剩余时间、排序和确认期计算都以它为准。 |
| `Task.dueDate` | 任务自身截止时间，不替代悬赏指标最终截止时间。 |
| `Result.source` | 区分指挥官定义和成员提出。 |
| `Result.definer` | 悬赏指标定义人，用于展示提出人和定义分归属。 |
| `Result.priorityChallengeExpiresAt` | 优先挑战倒计时来源。 |
| `Result.priorityDeclinedBy` | 判断提出人是否已放弃优先挑战权。 |
| `Result.assignedChallenger` | 指挥官指定的待接受挑战者；匹配当前用户时展示征召令。 |

## 4. 交互与状态

### 4.1 核心交互

| 交互 | 说明 |
| --- | --- |
| 搜索 | 按关键词过滤可申请挑战悬赏指标 |
| 筛选 | 按类型、来源、难度、目标、不确定性分范围缩小范围 |
| 排序 | 按截止时间、不确定性分、难度、发布时间排序 |
| 提出候选悬赏指标 | 打开候选悬赏指标提交入口 |
| 打开预览 | 点击悬赏指标卡片主体打开预览抽屉 |
| 打开详情 | 从卡片菜单或预览抽屉进入悬赏指标详情 |
| 申请挑战 | 打开申请确认弹窗 |
| 接受优先挑战 | 从优先挑战卡片接受并进入确认期 |
| 放弃优先挑战 | 放弃后悬赏指标进入公共池 |
| 接受挑战 | 从征召卡片接受，成功后成为挑战者并进入确认期 |
| 进入挑战页 | 从页面头部入口跳转到挑战页的我的挑战视图 |
| 打开评论 | 打开当前悬赏指标评论组件 |
| 复制链接 | 复制当前悬赏指标入口链接 |

### 4.2 页面状态

| 状态 | 说明 |
| --- | --- |
| 默认态 | 页面展示贡献概览、征召令和可申请挑战悬赏指标 |
| 加载态 | 贡献概览、征召令和悬赏指标列表展示骨架占位 |
| 空态 | 当前没有可申请挑战悬赏指标，且当前用户没有征召 |
| 筛选空态 | 当前筛选条件下无可申请挑战悬赏指标，保留清空筛选入口 |
| 征召提示态 | 当前用户被指挥官指定接受挑战 |
| 优先挑战态 | 当前用户存在需要接受或放弃的优先挑战 |
| 操作处理中 | 当前卡片主操作显示处理中状态 |
| 浮层打开态 | 页面存在预览抽屉、确认弹窗或评论浮窗 |
| 无权限态 | 操作入口禁用或点击后提示无权限 |

### 4.3 交互细则

| 交互 | 细则 |
| --- | --- |
| 搜索 | 输入时保留当前筛选和排序；清空搜索后恢复当前筛选结果。 |
| 筛选 | 已选筛选条件在工具栏展示为可移除标签。 |
| 卡片点击 | 点击卡片主体打开预览；点击按钮、菜单、评论入口不触发预览。 |
| 卡片 hover / focus | 展示验收摘要、任务数量、评论数量和更多操作入口；默认态保持精简。 |
| 预览抽屉 | 抽屉内展示悬赏指标口径、来源信息、积分口径、任务摘要和操作区。 |
| 申请挑战 | 点击后打开申请确认弹窗；确认后提交申请，等待指挥官确认。 |
| 优先挑战 | 提出人接受后进入确认期；放弃或 2 小时超时后进入公共池，提出人不能再次挑战该悬赏指标。 |
| 接受挑战 | 从征召卡片接受挑战后成为挑战者并进入确认期。 |
| 进入挑战页 | 点击 `我的挑战` 后跳转到挑战页；确认中、挑战中、待提交、待验收和已结算状态由挑战页承接。 |
| 打开评论 | 评论组件绑定当前悬赏指标对象，行为见评论组件文档。 |
| 无权限操作 | 点击时提示原因；不执行乐观更新。 |
| 键盘访问 | 卡片、主操作、菜单和筛选控件都需要可聚焦。 |
