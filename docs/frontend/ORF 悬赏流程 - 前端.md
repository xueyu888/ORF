## 2. 当前页页面结构

### 2.1 核心理念

悬赏大厅是 ORF 的主动贡献入口。

成员通过提出候选悬赏指标、申请挑战悬赏指标、提交战利品并通过验收来证明自己对组织目标的贡献。征召模式用于主线悬赏指标无人挑战时的组织兜底；默认流程以成员主动申请为主。个人评价统一回到积分结果：谁完成并通过验收的贡献更多，谁的积分更高。

页面结构需要突出三件事：

- 当前用户已经获得多少积分贡献。
- 当前用户是否有被指挥官指定且需要接受挑战的征召。
- 当前用户是否有候选悬赏指标被采纳后的优先挑战权。
- 当前还有哪些悬赏指标可以申请挑战。

悬赏大厅提供提出候选悬赏指标、发现悬赏指标、申请挑战、接受优先挑战和接受征召。挑战页承接确认中、挑战中、待提交、待验收、已结算等执行态。

### 2.4 默认视图

默认进入 `可申请挑战悬赏指标` 视图：

- 主体展示当前可申请挑战的悬赏指标。
- 与当前用户相关的征召展示在主体内容上方。
- 与当前用户相关的优先挑战展示在征召令下方。
- 我的积分贡献展示在页面上方，作为贡献反馈结果。
- 用户通过 `我的挑战` 跳转到挑战页处理确认中、已挑战、待提交、待验收和已结算悬赏指标。

### 3.4 轻详情弹层字段

轻详情弹层帮助用户判断是否申请挑战。

| 字段 | 说明 |
| --- | --- |
| 悬赏指标标题、目标、提出人 | 与卡片保持一致 |
| 衡量要求 / 完成标准 | 展示申请前判断所需口径 |
| 难度、不确定性分、剩余时间 | 帮助判断收益和紧迫程度 |
| 当前操作 | 申请挑战、接受挑战或放弃优先挑战 |

### 3.5 布局与视觉要求

悬赏大厅是桌面端 Web 工作台。页面需要表达主动贡献和积分反馈，同时保持可扫描。

| 区域 | 要求 |
| --- | --- |
| 页面头部 | 标题、周期提示、我的挑战和提出候选悬赏保持在页面顶部。 |
| 我的贡献概览 | 展示我的积分和积分明细入口。 |
| 征召令 | 当前用户有征召时展示在工具栏上方；多条征召按紧迫程度排列。 |
| 优先挑战 | 当前用户有优先挑战权时展示在征召令下方；默认显示 2 小时倒计时。 |
| 工具栏 | 包含搜索、难度筛选、目标筛选和排序。 |
| 可申请挑战悬赏指标 | 使用卡片列表展示；卡片宽度和高度保持稳定。 |
| 悬赏指标卡片 | 卡片是唯一重复卡片层级；卡片内主操作固定在底部。 |
| 卡片标题 | 标题最多两行，超出省略；目标名称单行省略。 |
| 卡片默认信息 | 展示标题、目标、提出人、难度、不确定性分、剩余时间和申请挑战。 |
| 轻详情入口 | 卡片主体点击后打开轻详情弹层。 |
| 积分展示 | 不确定性分和难度需要在卡片上可见，帮助用户判断贡献收益。 |
| 视觉风格 | 使用轻量游戏化的面板、徽章、分隔线和图标语言；输入、筛选和列表保持克制。 |

### 3.6 状态口径

悬赏大厅主内容展示可申请挑战的悬赏指标。

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| 优先挑战中 | 成员提出的候选悬赏指标已被采纳，提出人有 2 小时优先挑战权 | 优先挑战区 |
| 可申请 | 悬赏指标已发布，当前可申请挑战 | 可申请挑战悬赏指标列表 |
| 公共池 | 提出人放弃或超时后的成员提出悬赏指标 | 可申请挑战悬赏指标列表 |
| 征召中 | 主线悬赏指标由指挥官指定当前用户接受挑战 | 征召令 |

挑战页展示确认中、挑战中、待提交、待验收、已结算等状态。

点击 `申请挑战` 后表示申请意愿；指挥官确认且挑战者接受后，进入确认期并成为当前挑战者。优先挑战和征召中的 `接受挑战` 会直接成为挑战者并进入确认期。

### 3.7 页面字段口径

| 字段 | 用途 |
| --- | --- |
| `Result.owner` | 当前挑战者；用于挑战页个人视图过滤。 |
| `Result.finalDueAt` | 悬赏指标最终截止时间；大厅剩余时间、排序和确认期计算都以它为准。 |
| `Task.dueDate` | 任务自身截止时间；挑战页任务行展示使用。 |
| `Result.source` | 区分指挥官定义和成员提出。 |
| `Result.definer` | 悬赏指标定义人，用于展示提出人和定义分归属。 |
| `Result.priorityChallengeExpiresAt` | 优先挑战倒计时来源。 |
| `Result.priorityDeclinedBy` | 判断提出人是否已放弃优先挑战权。 |
| `Result.assignedChallenger` | 指挥官指定的待接受挑战者；匹配当前用户时展示征召令。 |

## 4. 交互与状态

### 4.1 核心交互

| 交互 | 说明 |
| --- | --- |
| 搜索 | 按关键词过滤可申请挑战悬赏指标 |
| 筛选 | 按难度、目标缩小范围 |
| 排序 | 按截止时间、不确定性分、难度、发布时间排序 |
| 提出候选悬赏指标 | 打开候选悬赏指标提交入口 |
| 打开轻详情 | 点击悬赏指标卡片主体打开轻详情弹层 |
| 申请挑战 | 打开申请确认弹窗 |
| 接受优先挑战 | 从优先挑战卡片接受并进入确认期 |
| 放弃优先挑战 | 放弃后悬赏指标进入公共池 |
| 接受挑战 | 从征召卡片接受，成功后成为挑战者并进入确认期 |
| 进入挑战页 | 从页面头部入口跳转到挑战页的我的挑战视图 |

### 4.2 页面状态

| 状态 | 说明 |
| --- | --- |
| 默认态 | 页面展示贡献概览、征召令和可申请挑战悬赏指标 |
| 加载态 | 贡献概览、征召令和悬赏指标列表展示骨架占位 |
| 空态 | 可申请列表和征召列表为空 |
| 筛选空态 | 当前筛选结果为空，保留清空筛选入口 |
| 征召提示态 | 当前用户被指挥官指定接受挑战 |
| 优先挑战态 | 当前用户存在需要接受或放弃的优先挑战 |
| 操作处理中 | 当前卡片主操作显示处理中状态 |
| 浮层打开态 | 页面存在轻详情弹层或确认弹窗 |

### 4.3 交互细则

| 交互 | 细则 |
| --- | --- |
| 搜索 | 输入时保留当前筛选和排序；清空搜索后恢复当前筛选结果。 |
| 筛选 | 已选筛选条件在工具栏展示为可移除标签。 |
| 卡片点击 | 点击卡片主体打开轻详情；主操作处理申请流程。 |
| 卡片 hover / focus | 保持可点击和可聚焦状态。 |
| 轻详情弹层 | 展示必要口径和当前操作。 |
| 申请挑战 | 点击后打开申请确认弹窗；确认后提交申请，等待指挥官确认。 |
| 优先挑战 | 提出人接受后进入确认期；放弃或 2 小时超时后进入公共池。 |
| 接受挑战 | 从征召卡片接受挑战后成为挑战者并进入确认期。 |
| 进入挑战页 | 点击 `我的挑战` 后跳转到挑战页；确认中、挑战中、待提交、待验收和已结算状态由挑战页承接。 |
| 键盘访问 | 卡片、主操作、弹层和筛选控件都需要可聚焦。 |
