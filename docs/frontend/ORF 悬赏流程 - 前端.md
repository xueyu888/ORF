## 1. 页面目录

### 1.1 页面关系

```text
ORF 悬赏流程
├─ 悬赏大厅                 ← 当前文档
├─ 悬赏详情                 ← 待拆分文档
├─ 战利品提交               ← 单独文档
└─ 奖励结算                 ← 待拆分文档
```

| --- | --- | --- | --- | --- |
| 悬赏大厅 | 主页面 | 侧边栏悬赏入口 | 本文档 | 成员主动挑战悬赏、接受挑战、查看个人积分贡献 |
| 悬赏详情 | 子页面 / 抽屉 | 从悬赏卡片进入 | 待补充 | 展示单个悬赏的完整口径、行动项、反馈、评论和操作记录 |
| 战利品提交 | 子页面 | 从挑战页已挑战悬赏进入 | [ORF 提交战利品页 - 前端.md](./ORF%20提交战利品页%20-%20前端.md) | 提交当前悬赏的完成说明 |

本文档只描述：

```text
ORF 悬赏流程
```

## 2. 当前页页面结构

### 2.1 核心理念

悬赏大厅是 ORF 的主动贡献入口。

成员通过主动挑战悬赏、提交战利品并通过验收来证明自己对组织目标的贡献。征召模式用于主线悬赏无人挑战时的组织兜底，不作为默认任务分发方式。个人评价统一回到积分结果：谁主动完成并通过验收的贡献更多，谁的积分更高。

页面结构需要突出三件事：

- 当前用户已经获得多少积分贡献。
- 当前用户是否有需要接受挑战的征召。
- 当前还有哪些悬赏可以主动挑战。

悬赏大厅只负责发现悬赏、申请挑战和接受挑战。挑战中、待提交、待验收、已结算等执行态统一回到挑战页查看和处理。

### 2.4 默认视图

默认进入 `可挑战悬赏` 视图：

- 主体只展示当前可主动挑战的悬赏。
- 与当前用户相关的征召展示在主体内容上方。
- 我的积分贡献展示在页面上方，作为主动挑战的反馈结果。
- 已挑战、待提交、待验收和已结算悬赏不在大厅展开，用户通过 `我的挑战` 跳转到挑战页处理。

### 3.4 布局与视觉要求

悬赏大厅是桌面端 Web 工作台。页面需要表达主动贡献和积分反馈，同时保持可扫描。

| 区域 | 要求 |
| --- | --- |
| 页面头部 | 标题、周期提示和管理员操作保持在页面顶部。 |
| 我的贡献概览 | 使用一行指标摘要展示积分、排名和积分明细入口；不展示挑战中、待提交、待验收、已结算等执行状态。 |
| 征召令 | 当前用户有征召时展示在工具栏上方；多条征召按紧迫程度排列。 |
| 工具栏 | 搜索靠左，筛选和排序靠右；已选筛选条件展示为可移除标签。 |
| 可挑战悬赏 | 使用卡片列表展示；卡片宽度和高度保持稳定。 |
| 悬赏卡片 | 卡片是唯一重复卡片层级；卡片内主操作固定在底部。 |
| 卡片标题 | 标题最多两行，超出省略；目标名称单行省略。 |
| 卡片默认信息 | 默认只展示标题、目标、类型、难度、基础积分、剩余时间、指标快照和我要挑战。 |
| 卡片辅助信息 | 验收摘要、行动项数量、评论数量和更多操作在 hover / focus 或预览抽屉中展示。 |
| 积分展示 | 基础积分和难度需要在卡片上可见，帮助用户判断贡献收益。 |
| 视觉风格 | 可以使用 ORF fantasy-ui 的面板、徽章、分隔线和图标语言；输入、筛选和列表保持克制，不做重装饰游戏首页。 |

### 3.5 状态口径

悬赏大厅主内容只展示可主动挑战的悬赏。

| 状态 | 含义 | 展示位置 |
| --- | --- | --- |
| 可挑战 | 悬赏已发布，当前可主动挑战 | 可挑战悬赏列表 |
| 征召中 | 主线悬赏需要当前用户接受挑战 | 征召令 |

挑战中、待提交、待验收、已结算等状态不在悬赏大厅展示，统一在挑战页处理。

## 4. 交互与状态

### 4.1 核心交互

| 交互 | 说明 |
| --- | --- |
| 搜索 | 按关键词过滤可挑战悬赏 |
| 筛选 | 按类型、难度、目标、基础积分范围缩小范围 |
| 排序 | 按截止时间、基础积分、难度、发布时间排序 |
| 打开预览 | 点击悬赏卡片主体打开预览抽屉 |
| 打开详情 | 从卡片菜单或预览抽屉进入悬赏详情 |
| 我要挑战 | 打开挑战确认弹窗 |
| 接受挑战 | 从征召卡片进入挑战确认 |
| 进入挑战页 | 从页面头部入口跳转到挑战页的我的挑战视图 |
| 打开评论 | 打开当前悬赏评论组件 |
| 复制链接 | 复制当前悬赏入口链接 |

### 4.2 页面状态

| 状态 | 说明 |
| --- | --- |
| 默认态 | 页面展示贡献概览、征召令和可挑战悬赏 |
| 加载态 | 贡献概览、征召令和悬赏列表展示骨架占位 |
| 空态 | 当前没有可挑战悬赏，且当前用户没有征召 |
| 筛选空态 | 当前筛选条件下无可挑战悬赏，保留清空筛选入口 |
| 征召提示态 | 当前用户存在需要接受挑战的征召 |
| 操作处理中 | 当前卡片主操作显示处理中状态 |
| 浮层打开态 | 页面存在预览抽屉、确认弹窗或评论浮窗 |
| 无权限态 | 操作入口禁用或点击后提示无权限 |

### 4.3 交互细则

| 交互 | 细则 |
| --- | --- |
| 搜索 | 输入时保留当前筛选和排序；清空搜索后恢复当前筛选结果。 |
| 筛选 | 已选筛选条件在工具栏展示为可移除标签。 |
| 卡片点击 | 点击卡片主体打开预览；点击按钮、菜单、评论入口不触发预览。 |
| 卡片 hover / focus | 展示验收摘要、行动项数量、评论数量和更多操作入口；默认态保持精简。 |
| 预览抽屉 | 抽屉内展示悬赏口径、积分口径、行动项摘要和操作区。 |
| 我要挑战 | 点击后打开确认弹窗；确认后卡片进入操作处理中状态。 |
| 接受挑战 | 从征召卡片接受挑战后进入与 `我要挑战` 相同的确认流程。 |
| 进入挑战页 | 点击 `我的挑战` 后跳转到挑战页；挑战中、待提交、待验收和已结算状态由挑战页承接。 |
| 打开评论 | 评论组件绑定当前悬赏对象，行为见评论组件文档。 |
| 无权限操作 | 点击时提示原因；不执行乐观更新。 |
| 键盘访问 | 卡片、主操作、菜单和筛选控件都需要可聚焦。 |
