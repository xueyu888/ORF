# ORF 提交战利品页 - 前端

## 页面定位

从我的挑战的目标行进入：

```text
/objectives/:objectiveId/loot
```

战利品提交发生在目标层级，不发生在单个指标层级。

## 页面字段

| 字段 | 说明 |
| --- | --- |
| 目标标题 | 只读展示 |
| 指标完成提醒 | 提醒战利品用于证明目标下指标完成或有效证伪 |
| 指标清单 | 展示指标标题、验收标准、难度和不确定性分 |
| 完成说明 | 必填，说明完成或证伪证据 |
| 自测报告 | 可选文本摘要，记录自测覆盖、复核结论或风险说明 |
| 试验收 | `frozen` 目标的挑战者可用同一份完成说明、指标主张和自测摘要发起一次试验收；指挥官在同页反馈 |
| 匿名互评 | `submitted` 目标的普通成员挑战者填写挑战者贡献百分比 |
| 验收指标 | 指挥官选择每个指标验收结论 |
| 互评结果 | 指挥官只读查看匿名互评汇总；分歧时处理贡献比例 |

## 交互

| 操作 | 结果 |
| --- | --- |
| 返回 / 取消 | 回到 `/tasks` |
| 提交试验收 | 普通成员挑战者保存一次试验收请求，目标仍保持已冻结 |
| 提交试验收反馈 | 指挥官反馈“可正式提交”或“需补充”，不改变目标状态 |
| 提交 | 普通成员挑战者保存目标战利品，目标进入待验收 |
| 提交匿名互评 | 保存普通成员挑战者互评结果，等待指挥官验收 |
| 验收并结算 | 指标验收结论和匿名互评结果生成积分流水 |

任务和子任务勾选完成不触发验收。只有目标战利品提交并通过指挥官验收后，才产生完成或结算结果。

试验收不是正式提交：它不生成 `objectiveLoot`，不写入 `lootSubmittedAt`，不进入 `submitted`，也不参与按时/延期判断。目标挑战者仍需点击“正式提交”提交战利品。

## 匿名互评输入规则

- 页面展示和输入单位是百分比，不是接口中的小数比例。
- 每个目标挑战者都必须填写一项，包括当前登录成员自己。
- 每项范围为 `0` 到 `100`，所有挑战者合计必须为 `100%`。
- 自评只用于一致性核查，不直接进入个人结算分；结算贡献比例由其他挑战者对该成员的评价汇总后归一得到。
- 指挥官处理缺评、分歧或申诉时，同样填写最终贡献百分比且合计必须为 `100%`。
