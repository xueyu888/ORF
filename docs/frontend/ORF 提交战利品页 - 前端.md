# ORF 提交战利品页 - 前端

## 页面定位

从我的挑战的目标行进入：

```text
/tasks/objectives/:objectiveId/loot
```

战利品提交发生在目标层级，不发生在单个指标层级。

## 页面字段

| 字段 | 说明 |
| --- | --- |
| 目标标题 | 只读展示 |
| 指标完成提醒 | 提醒战利品用于证明目标下指标完成或有效证伪 |
| 指标清单 | 展示指标标题和只读指标详情；指标详情读取 `Result.detail`，不从评论或证据说明反推 |
| 完成说明 | 必填，说明完成或证伪证据 |
| 自测报告 | 可选文本摘要，记录自测覆盖、复核结论或风险说明 |
| 试验收 | `frozen` 目标的挑战者可用同一份完成说明、指标主张和自测摘要发起一次试验收；指挥官在同页反馈 |
| 匿名互评 | `revisionRequired` 且截止日已到、或 `accepted` 目标的普通成员挑战者按目标指标表提交贡献百分比，或填写弃权说明 |
| 验收指标 | 指挥官按每个指标的完成声明与证据选择验收结论，目标结论由指标结论派生 |
| 互评结果 | 指挥官在逾期惩罚结算或最终结算阶段查看提交状态、原始评分、偏离提醒，并确认本次结算比例 |

## 交互

| 操作 | 结果 |
| --- | --- |
| 返回 / 取消 | 回到 `/tasks` |
| 提交试验收 | 普通成员挑战者保存一次试验收请求，目标仍保持已冻结 |
| 提交试验收反馈 | 指挥官反馈“可正式提交”或“需补充”，不改变目标状态 |
| 提交 | 普通成员挑战者保存目标战利品，`frozen` 或 `revisionRequired` 目标进入待验收 |
| 提交匿名互评 | 页面提交逐指标整数百分比矩阵到 ORF 同源代理；ORF 后端补齐服务端指标和挑战者事实后转发到匿名互评服务，由匿名互评服务统一计算目标级贡献比例 |
| 提交弃权说明 | 成员说明自己做了什么、为什么不了解整体贡献；弃权不参与贡献均值计算 |
| 确认验收通过 / 确认有效证伪 / 确认要求返工 | 指挥官保存指标验收结论；页面从逐指标结论派生目标预告和提交按钮文案，完成或有效证伪时目标进入已验收，不通过时目标进入待返工 |
| 确认惩罚结算 | 待返工目标已到截止日时，指挥官确认贡献比例，生成逾期惩罚积分流水，目标仍需继续返工 |
| 确认结算 | 已验收目标中，指挥官确认最终贡献比例，生成最终结算积分流水，目标进入已结算 |

任务和子任务勾选完成不触发验收。目标战利品提交后必须由指挥官按指标验收；验收不通过会进入待返工。截止日已到且验收不通过时仍会匿名互评并写入惩罚积分；目标最终验收通过后还会再次提醒成员检查互评并完成最终结算。

试验收不是正式提交：它不生成 `objectiveLoot`，不写入 `lootSubmittedAt`，不进入 `submitted`，也不参与按时/延期判断。目标挑战者仍需点击“正式提交”提交战利品。

## 匿名互评输入规则

- 页面展示和输入单位是百分比，不是接口中的小数比例。
- 成员可选择提交评分或弃权说明。
- 提交评分时，页面以表格展示目标下的指标，指标行来自当前目标的 `Result` 读模型；列是当前目标挑战者，包括当前登录成员自己。
- 每个指标行都必须为每个目标挑战者填写一项，单元格初始值为 `0`，范围为 `0` 到 `100` 的整数；提交前校验同一指标行合计必须精确为 `100%`。
- 指标权重由 ORF 后端按当前目标的服务端指标事实补齐并交给匿名互评服务计算：优先使用 `Result.uncertaintyScore` 参与目标基础分的权重；如果当前目标没有指标，则退回为一行“目标整体”；如果指标都没有有效分值，服务端按指标等权汇总。
- 指标行展示当前指标难度等级和指标分，例如 `入门 · 指标分 10 · 权重 25%`。
- 页面不展示也不提交目标最终贡献比例；目标级比例由匿名互评服务按服务端指标权重从逐指标原始行派生。
- 指标级百分比是匿名互评原始明细的一部分；页面提交时只提交逐指标 `metricRows` 或弃权说明。最终结算仍只使用指挥官确认后的公开比例。
- 页面不使用浏览器 `localStorage` 保存业务草稿；输入到一半会自动保存到匿名互评服务的覆盖式服务器草稿。进入页面后通过 `/api/local-settlement/objectives/:objectiveId/reviews/me` 读取当前用户在该目标的服务器草稿和服务器最新提交，草稿优先回填；提交成功后服务器草稿立即清空。历史旧提交如果没有 `metricRows` 或 `metricScores`，只能提示最新目标级比例，不能还原每个指标行。
- 提交弃权时必须填写说明，简述自己大概做了什么，以及为什么无法判断其他人的贡献比例。
- 提交时前端调用 `/api/local-settlement/objectives/:objectiveId/reviews/submit`；自动保存草稿调用 `/api/local-settlement/objectives/:objectiveId/reviews/draft`。
- 自评优先只用于一致性核查；当某个成员暂时只有自评数据时，页面会标注为“仅自评参考”。
- 指挥官结算时通过 `/api/local-settlement/objectives/:objectiveId/summary` 读取共享结算服务汇总，页面展示已评分、已弃权、未提交、每个 reviewer 的目标级评分、逐指标评分明细、相对当前原始均值偏离和超过 `10%` 的提醒。
- 缺评、弃权和超过 `10%` 的偏离都不阻止结算；指挥官确认最终贡献百分比且合计为 `100%` 后即可结算。

后端契约见 [ORF 提交战利品 - 后端.md](../backend/ORF%20提交战利品%20-%20后端.md)。
