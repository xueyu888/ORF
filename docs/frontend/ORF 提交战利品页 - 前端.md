# ORF 提交战利品页 - 前端

## 页面定位

从我的挑战的目标行进入：

```text
/tasks/objectives/:objectiveId/loot
```

战利品提交发生在目标层级，不发生在单个指标层级。

## 页面字段

| 字段 | 说明 |
| --- | --- |
| 目标标题 | 只读展示 |
| 指标完成提醒 | 提醒战利品用于证明目标下指标完成或有效证伪 |
| 指标清单 | 展示指标标题和只读指标详情；指标详情读取 `Result.detail`，不从评论或证据说明反推 |
| 完成说明 | 必填，说明完成或证伪证据 |
| 自测报告 | 可选文本摘要，记录自测覆盖、复核结论或风险说明 |
| 试验收 | `frozen` 目标的挑战者可用同一份完成说明、指标主张和自测摘要发起一次试验收；指挥官在同页反馈 |
| 匿名互评 | `submitted` 目标的普通成员挑战者提交贡献百分比，或填写弃权说明 |
| 验收指标 | 指挥官选择每个指标验收结论 |
| 互评结果 | 指挥官查看提交状态、原始评分、当前均值和偏离提醒，并确认最终结算比例 |

## 交互

| 操作 | 结果 |
| --- | --- |
| 返回 / 取消 | 回到 `/tasks` |
| 提交试验收 | 普通成员挑战者保存一次试验收请求，目标仍保持已冻结 |
| 提交试验收反馈 | 指挥官反馈“可正式提交”或“需补充”，不改变目标状态 |
| 提交 | 普通成员挑战者保存目标战利品，目标进入待验收 |
| 提交匿名互评 | 浏览器本地加密后提交到 ORF 同源代理，由 ORF 转发到共享结算服务；ORF 后端不保存原始互评 |
| 提交弃权说明 | 成员说明自己做了什么、为什么不了解整体贡献；弃权不参与贡献均值计算 |
| 验收并结算 | 指标验收结论和指挥官确认的最终贡献比例生成积分流水 |

任务和子任务勾选完成不触发验收。只有目标战利品提交并通过指挥官验收后，才产生完成或结算结果。

试验收不是正式提交：它不生成 `objectiveLoot`，不写入 `lootSubmittedAt`，不进入 `submitted`，也不参与按时/延期判断。目标挑战者仍需点击“正式提交”提交战利品。

## 匿名互评输入规则

- 页面展示和输入单位是百分比，不是接口中的小数比例。
- 成员可选择提交评分或弃权说明。
- 提交评分时，每个目标挑战者都必须填写一项，包括当前登录成员自己。
- 评分每项范围为 `0` 到 `100`，所有挑战者合计必须为 `100%`。
- 提交弃权时必须填写说明，简述自己大概做了什么，以及为什么无法判断其他人的贡献比例。
- 提交时前端从 ORF 同源代理读取共享结算服务公钥，用 WebCrypto 加密后提交到 `/api/local-settlement/objectives/:objectiveId/reviews`。
- 自评优先只用于一致性核查；当某个成员暂时只有自评数据时，页面会标注为“仅自评参考”。
- 指挥官验收时通过 `/api/local-settlement/objectives/:objectiveId/summary` 读取共享结算服务汇总，页面展示已评分、已弃权、未提交、原始评分、当前均值、相对均分偏离和超过 `10%` 的提醒。
- 缺评、弃权和超过 `10%` 的偏离都不阻止验收；指挥官确认最终贡献百分比且合计为 `100%` 后即可验收并结算。
