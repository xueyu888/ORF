# ORF 挑战交互组件 - 前端

本文档描述挑战页内复用交互组件，不描述页面布局。

## 1. 行操作

行操作绑定目标、指标、任务、子任务。

| 操作 | 说明 |
| --- | --- |
| `+` | 新增当前对象真实拥有的子级对象 |
| 拖拽手柄 | 拖拽排序 |
| 复制链接 | 复制当前行锚点链接 |
| 评论 | 打开评论组件 |
| 编辑 | 进入标题行内编辑 |
| 删除 | 删除当前对象，删除前展示影响范围 |

行操作只在 hover 当前行或菜单打开时显示。每个 hover 工具层最多只有一个 `+`，且 `+` 始终表示“给当前对象新增子级”：

- 目标行有一个 `+`。点击后打开轻量类型选择层，只展示当前权限和状态允许的 `新增/提出指标`、`新增行动项`。用户选定类型后，才在对应分支插入一条 temporary 行。
- 指标行没有 `+`。指标当前没有子级对象，不能用 `+` 创建任务或同级指标。
- 任务行有一个 `+`。点击后直接在当前任务下插入一条 temporary 子任务行。
- 子任务行没有 `+`。

新增指标、提出指标、新增行动项和新增子任务都必须从对应父级的 `+` 发起。没有内容时不渲染“待定义指标 / 待创建行动项”伪子行；点击 `+` 并选择类型后，才插入对应 temporary 行并进入标题行内编辑。已有内容时不自动展示下一条新增行；再次新增必须重新点击对应父级的 `+`。标题保存成功后，temporary 行由后端返回的真实指标、真实行动项或真实子任务进入一次性创建覆盖层，并以 persisted 行形态持续显示到挑战页刷新数据包含同一真实 id；不能把 temporary 行写成第二套业务事实源。

菜单打开时，所属目标卡片进入前景态。层级提升发生在目标卡片层，不在单个菜单上硬提 `z-index`，避免菜单被相邻目标卡片遮挡。

## 2. 权限拦截

前端在执行下列目标、指标和流程操作前检查 `permissionRules`。行动项和子行动项不使用独立权限 key；它们走目标级工作项维护能力，由目标生命周期以及当前用户是否为指挥官或 `Objective.challengers` 正式挑战者共同决定。

| 操作 | 权限 key |
| --- | --- |
| 新增指标 | `result.create` |
| 编辑目标 | `objective.edit` |
| 编辑指标 | `result.edit` |
| 拖拽指标 | `result.edit` |
| 删除目标 | `objective.delete` |
| 删除指标 | `result.delete` |

无权限时只提示，不执行状态修改。

## 3. 拖拽反馈

拖拽支持三种落点：

| 落点 | 含义 |
| --- | --- |
| `before` | 放到目标行前面 |
| `after` | 放到目标行后面 |
| `inside` | 移入目标对象内部 |

拖拽中显示当前拖拽行弱化样式，并高亮可放置位置。

## 4. 删除确认

删除确认必须展示受影响下级数量。

| 删除对象 | 确认内容 |
| --- | --- |
| 目标 | 指标、任务、子任务数量 |
| 指标 | 反馈、证据和评论影响 |
| 任务 | 子任务数量 |
| 子任务 | 当前子任务标题 |

## 5. 更新时间来源

指标行最近更新时间取以下字段的最新值：

| 来源 | 字段 |
| --- | --- |
| 指标自身 | `Result.updatedAt` |
| 指标趋势 | `Result.trend[-1].date` |
| 反馈 | `Feedback.updatedAt` |
| 历史材料 | `Evidence.date` |

`Result.updatedAt` 是指标自身标题、难度、置信度等指标字段的最后修改时间，也是新建指标没有趋势、反馈或历史材料时的基础显示值。前端不展示历史材料入口，但仍允许旧数据参与更新时间计算。

任务行最近更新时间只来自 `Task.updatedAt` 和其子任务 `TaskChecklistItem.updatedAt`。任务不参与指标行更新时间聚合，避免重新形成任务从属指标的隐式关系。
