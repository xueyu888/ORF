# 前端显隐配置

## 是什么

前端显隐配置用于控制固定入口和固定区域是否展示，例如导航入口、页面访问入口、挑战页全量视图入口、个人设置入口和系统管理入口。

唯一数据配置：

```text
src/config/frontendVisibility.config.json
```

唯一代码入口：

```text
src/config/frontendVisibility.ts
```

## 为什么

显隐配置只处理前端展示，不处理业务权限，也不是安全边界。

业务动作是否允许执行，由权限表、当前用户所有权和后端接口校验。

设置入口必须区分个人设置和系统设置：

| 显隐点 | 目标 key | 可见范围 | 路由 |
|---|---|---|---|
| 个人设置入口 | `nav.personalSettings` | `all` | `/settings` |
| 个人设置页面访问 | `page.personalSettings` | `all` | `/settings` |
| 系统管理入口 | `nav.systemManagement` | `admin` | `/system` |
| 系统管理页面访问 | `page.systemManagement` | `admin` | `/system` |
| 系统成员页面访问 | `page.systemMembers` | `admin` | `/system/members` |
| 系统权限页面访问 | `page.systemPermissions` | `admin` | `/system/permissions` |
| 系统设置页面访问 | `page.systemSettings` | `admin` | `/system/settings` |

不得继续用同一个 `settings` key 同时表达个人设置和系统设置；侧边栏只暴露 `systemManagement`，成员、权限和系统设置必须作为系统管理子页面处理。

## 怎么做

组件只能通过以下方法判断显隐：

```text
canShowFrontend()
canShowFrontendPath()
```

新增显隐点时，先在 `frontendVisibility.config.json` 增加 key；如果涉及路由路径，再在 `frontendVisibility.ts` 补充 `frontendVisibilityByPath`。

命令菜单只管理已登录应用内的业务入口；登录 / 注册页属于公共认证路由，不放入 `quickPages`。

不要在组件里单独写 `adminOnlyPaths`、`isAdmin && ...`、`RequireAdmin` 这类显隐规则。

`tests/frontendVisibility.test.ts` 用于防止显隐逻辑绕过统一入口。
