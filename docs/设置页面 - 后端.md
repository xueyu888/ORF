# 设置页面 - 后端

本文只定义后端实现契约。设置业务边界以 [设置边界规则.md](./rules/设置边界规则.md) 为唯一事实源。

## 1. 目标边界

| 设置域 | 写入对象 | 写权限 | 事实源 |
|---|---|---|---|
| 个人设置 | 当前 session 用户 | 已激活登录用户本人 | 当前用户偏好和个人资源。 |
| 系统设置 | 全站配置和系统资源 | `admin` | 系统设置文件、系统背景资源和全局策略。 |
| 用户头像 | 当前 session 用户 | 已激活登录用户本人 | `users.avatar_*` 元数据和对象存储头像文件。 |

当前兼容：视觉背景接口属于系统设置能力；`public/settings/user/*` 只作为旧系统路径读取兼容，不能解释为普通用户个人设置。

## 2. 数据所有权

后端模型必须能区分三类事实：

| 事实 | owner | 说明 |
|---|---|---|
| 系统视觉配置 | `system` | 登录页背景、系统默认 AppShell 皮肤、个人背景策略。 |
| 系统背景资源 | `system` | 管理员上传或工程内置的系统背景。 |
| 个人偏好和个人背景资源 | `userId` | 只属于当前用户本人。 |
| 用户头像资源 | `userId` | 只允许本人上传、替换和删除；同作用域已激活用户可通过后端受控接口读取展示。 |

背景场景：

| 场景 | 设置域 | 说明 |
|---|---|---|
| `login_background` | 系统设置 | 登录页背景；未登录可读取，只有管理员可写。 |
| `app_background` | 系统设置 + 个人设置 | 登录后 AppShell 背景资源池；三槽位为 `topbar`、`sidebar`、`main_content`，后端兼容旧请求名 `sidebar_background`。 |

实现不变量：

- 登录页背景只能引用系统背景资源。
- 个人应用背景可以引用系统启用背景、当前用户自己的个人背景、其他用户当前共享背景，以及当前用户已有历史授权的背景。
- 普通用户不能写入其他用户个人背景；未共享且无历史授权的其他用户背景不可读。
- 个人背景上传不进入系统背景目录或系统默认资源池。
- 背景图片本体必须写入对象存储；后端只在配置 / 偏好里保存 object key 和展示元数据。

## 3. 存储边界

目标存储分层：

| 路径 | 归属 | 说明 |
|---|---|---|
| `public/settings/system/settings.json` | 系统 | 系统设置本地配置，不提交 git。 |
| `public/settings/system/settings.json.example` | 系统 | 系统设置样板，随代码提交。 |
| `settings/backgrounds/{scene}/system/{timestamp}-{uuid}-{file}` | 系统 | 系统背景对象存储 key；系统配置保存元数据和 object key。 |
| `settings/users/{userId}/backgrounds/{timestamp}-{uuid}-{file}` | 用户 | 个人背景对象存储 key；个人偏好保存元数据和 object key。 |
| `public/settings/users/{userId}/preferences.json` | 用户 | 当前用户个人偏好、三槽位配置、共享开关、历史授权和个人背景元数据。 |
| `users/{userId}/avatar/{timestamp}.{ext}` | 用户 | 当前用户头像对象存储 key；DB 只保存元数据，不暴露 key。 |

旧路径兼容：

- `public/settings/user/settings.json` 是旧系统视觉配置路径。
- `public/settings/backgrounds/*` 是旧背景图片路径，已废弃；新上传和读取不能继续依赖仓库图片目录。
- `public/settings/backgrounds/*/user/` 是旧管理员上传系统背景路径。
- 迁移代码可以读取旧配置做兼容，但新个人设置和系统背景上传不能继续写这些旧路径。

## 4. API 分组

目标 API 必须按作用域分组。

个人设置：

| 能力 | 权限 | 约束 |
|---|---|---|
| 读取当前用户偏好 | 已激活登录用户 | 不接受任意 `userId`。 |
| 保存当前用户偏好 | 已激活登录用户 | 只能写当前 session 用户。 |
| 读取当前用户可选 AppShell 背景 | 已激活登录用户 | 返回系统背景 + 本人个人背景 + 他人共享背景 + 本人历史授权背景。 |
| 上传当前用户个人背景 | 已激活登录用户且系统策略允许 | 写入对象存储，元数据写入当前用户偏好。 |
| 删除当前用户个人背景 | 背景所有者本人 | 删除对象存储资源，清除所有用户引用和历史授权；不能删除系统背景或他人背景。 |
| 保存个人背景共享开关 | 已激活登录用户 | 用户级共享策略；关闭共享不撤销历史授权。 |
| 上传当前用户头像 | 已激活登录用户 | 校验图片 MIME、真实文件头和大小，写入当前用户头像资源。 |
| 删除当前用户头像 | 已激活登录用户 | 只清空当前用户头像元数据并删除旧对象。 |

系统设置：

| 能力 | 权限 | 约束 |
|---|---|---|
| 查询登录页系统背景 | 公开读取 | 只返回系统登录背景。 |
| 查询系统 AppShell 槽位背景 | 已激活登录用户 | 按槽位只返回系统启用 AppShell 背景。 |
| 上传系统背景 | `admin` | 写入对象存储，元数据写入系统设置。 |
| 设置系统默认背景 | `admin` | 只能引用系统背景；AppShell 槽位各自保存默认值。 |
| 保存系统背景策略 | `admin` | 不能写入个人偏好。 |
| 保存个人背景策略 | `admin` | 只控制个人上传策略，不写个人资源。 |

当前接口兼容：

- 当前 `/api/settings/visual/*` 属于系统视觉接口。
- 可以保留旧 scene/scope 兼容转发，但不能让它们变成个人设置接口。
- 新个人设置接口不得复用旧系统视觉写接口。

## 5. 权限不变量

- 未登录用户只能读取登录页需要的系统公开资源。
- 非管理员不能写系统设置、系统背景资源或系统默认背景。
- 个人设置写接口只能使用当前 session 用户作为写入对象。
- 个人头像写接口只能使用当前 session 用户作为写入对象，不能接受任意 `userId`。
- 头像读取接口只能返回当前登录用户所在默认作用域内的用户头像；响应不暴露对象存储 key。
- 所有背景引用都必须校验 owner、scene、slot 和 object key 元数据。
- 保存个人偏好时，不允许写入 `login_background`。
- 保存系统配置时，不允许引用个人背景资源。
- 静态背景文件读取接口必须代理对象存储，并按系统公开 / 登录用户 / owner / shared / 历史授权规则校验。

## 6. 当前落地状态

1. 视觉接口已按系统设置能力收敛，并由独立 settings routes 注册。
2. 系统设置写入 `public/settings/system/settings.json`，读取兼容旧 `public/settings/user/settings.json`。
3. 规范兼容场景是 `login_background` 和 `app_background`；其中 `app_background` 是 AppShell 三槽位共享资源池，旧 `sidebar_background` 只作为兼容别名。
4. 规范系统上传 scope 是 `system`；背景图片本体写入对象存储，仓库不再保存背景图片资源。
5. 个人偏好接口写入当前 session 用户；个人背景本体写入对象存储，元数据写入当前用户偏好。
6. 个人背景读取返回系统启用应用背景、当前用户个人背景、其他用户共享背景和当前用户历史授权背景。
7. 用户头像元数据写入 `users.avatar_*`，头像文件写入对象存储；`avatarUrl` 只作为用户和评论读模型派生字段返回。
