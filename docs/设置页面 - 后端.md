# 设置页面 - 后端

本文只定义后端实现契约。设置业务边界以 [设置边界规则.md](./rules/设置边界规则.md) 为唯一事实源。

## 1. 目标边界

| 设置域 | 写入对象 | 写权限 | 事实源 |
|---|---|---|---|
| 个人设置 | 当前 session 用户 | 已激活登录用户本人 | 当前用户偏好和个人资源。 |
| 系统设置 | 全站配置和系统资源 | `admin` | 系统设置文件、系统背景资源、聊天设置和全局策略。 |
| 用户头像 | 当前 session 用户 | 已激活登录用户本人 | `users.avatar_*` 元数据和对象存储头像文件。 |

视觉背景接口属于系统设置能力；运行配置只从 `ORF_SETTINGS_DATA_DIR` 读取。

## 2. 数据所有权

后端模型必须能区分三类事实：

| 事实 | owner | 说明 |
|---|---|---|
| 系统视觉配置 | `system` | 登录页、顶部栏、侧边栏和页面级皮肤默认值、个人背景策略。 |
| 聊天系统配置 | `system` | 聊天附件业务上限；基础设施上传上限只作为承载边界。 |
| 反馈系统配置 | `system` | 单条反馈原始报告的附件总上限；基础设施上传上限只作为承载边界。 |
| 系统背景资源 | `system` | 管理员上传或工程内置的系统背景。 |
| 个人偏好和个人背景资源 | `userId` | 只属于当前用户本人；其中 `display` 保存显示偏好，`filterPreferences[viewKey]` 保存页面筛选偏好，`workspaceLayout` 仅作为旧工作区布局兼容字段保留，`backgrounds[scene]` 保存各皮肤槽位选择、摆放和蒙层强度。 |
| 社区背景副本 | `scopeId + shareId` | 由当前用户明确分享个人图片后创建的独立副本；记录作者仅用于撤回鉴权，不向其他用户展示。 |
| 用户头像资源 | `userId` | 只允许本人上传、替换和删除；同作用域已激活用户可通过后端受控接口读取展示。 |

背景场景：

| 场景 | 设置域 | 说明 |
|---|---|---|
| `login_background` | 系统设置 + 个人设置 | 登录页背景；系统默认未登录可读，个人登录页只能登录后配置并在本机缓存预览。 |
| `topbar_background` | 系统设置 + 个人设置 | 登录后顶部栏皮肤。 |
| `sidebar_background` | 系统设置 + 个人设置 | 登录后侧边栏皮肤。 |
| `page_*_background` | 系统设置 + 个人设置 | 对应页面内容区皮肤。 |

实现不变量：

- 登录页系统默认只能引用系统背景资源；个人登录页皮肤可以引用系统登录背景或当前用户自己的登录页背景。
- 个人槽位配置可以引用共享系统图库或当前用户自己的共享个人图库；其他用户个人图库不可读写。
- 图片文件、取景参数和材质偏好分离：文件归资源目录，`crops[imageId]` 与 `material` 归槽位配置；`crops[imageId]` 保存 `centerX`、`centerY` 和 `zoom`，`zoom` 按 `1..3` 归一化并表示 cover 基础上的放大倍数；v4 `material` 只接受 `tone`、`exposure`、`overlayStrength`、`blurStrength`、`reduceTransparency`，两个强度字段按 `0..1` 归一化。
- 普通用户不能读取或写入其他用户个人背景。
- 个人背景上传不进入系统背景目录或系统默认资源池。
- 社区分享只复制个人背景文件并建立独立记录，不改变个人原图 owner；上传、缓存和保存槽位都不能隐式触发分享。
- 社区分享撤回只写入 `withdrawnAt` 并隐藏公共入口，不能物理删除文件；已保存该背景的槽位引用继续有效。
- 未登录用户不能读取服务端个人背景文件；登录页个人化通过前端本机缓存预览闭环。

## 3. 存储边界

目标存储分层：

| 路径 | 归属 | 说明 |
|---|---|---|
| `.orf/settings/system/settings.json` | 系统 | 系统设置运行时事实源，不提交 git，也不进入任何静态发布目录。 |
| `public/settings/backgrounds/*/default/` | 系统 | 后端内置系统背景，随代码提交并只由鉴权背景接口读取；Vite 已禁用 `publicDir`，这些文件不进入 Web/APK。 |
| `.orf/settings/backgrounds/{scene}/system/` | 系统 | 管理员上传系统背景的运行时事实源；上传来源保留为目录名，但图片可被其它规范槽位选择。 |
| `.orf/settings/users/{userId}/backgrounds/{scene}/` | 用户 | 当前用户个人背景的运行时事实源；上传来源保留为目录名，但图片可被当前用户自己的其它规范槽位选择。 |
| `.orf/settings/communities/{scopeStorageId}/backgrounds/{shareId}/` | 当前 ORF 作用域 | `scopeId` 经安全路径编码后的社区副本文件和元数据；撤回后原地保留，不进入系统背景目录或个人目录。 |
| `users/{userId}/avatar/{timestamp}.{ext}` | 用户 | 当前用户头像对象存储 key；DB 只保存元数据，不暴露 key。 |

存储规则：

- 运行时用户偏好、系统设置和可变背景只允许位于 `ORF_SETTINGS_DATA_DIR`。
- `ORF_SETTINGS_DATA_DIR` 是私有设置存储根，默认 `.orf/settings`；配置为 `public/`、`dist/`、`.artifacts/` 或 Android assets 的子目录时服务拒绝启动。
- 系统设置和个人偏好的默认值由各自服务模块的归一化函数定义，不再维护或发布静态 JSON 样板。
- 当前用户偏好文件不存在时可以生成默认投影；文件存在但读取失败或 JSON 损坏时必须显式失败，不能静默返回整份默认值并伪装成用户偏好。
- 不可变服务端发布包只复制 `public/settings/backgrounds/*/default/` 的内置背景；默认目录是只读发布资产，读取缺失目录时按空集合处理。运行时只在 `ORF_SETTINGS_DATA_DIR` 下维护 `system/`、`backgrounds/*/system/` 和 `users/{userId}/` 私有目录。

## 4. API 分组

目标 API 必须按作用域分组。

个人设置：

| 能力 | 权限 | 约束 |
|---|---|---|
| 读取当前用户偏好 | 已激活登录用户 | 不接受任意 `userId`；响应使用 `Cache-Control: private, no-store`，避免版本升级后命中旧的用户偏好响应。 |
| 保存当前用户偏好 | 已激活登录用户 | 只能写当前 session 用户；`display`、`filterPreferences` 和兼容字段 `workspaceLayout` 按统一 schema 归一化，不能写系统默认、业务数据或权限结果。 |
| 读取当前用户某槽位可选皮肤 | 已激活登录用户 | 按 `scene` 返回共享系统图库 + 本人共享个人图库；响应使用 `Cache-Control: private, no-store`，前端只通过自己的用户/场景读模型与图片缓存加速。 |
| 上传当前用户某槽位个人背景 | 已激活登录用户且系统策略允许 | 按上传入口的 `scene` 写入当前用户个人目录，但该图片会进入当前用户共享图库。 |
| 删除当前用户个人背景 | 背景所有者本人 | 不能删除系统背景或他人背景；删除后清理引用该图片的个人槽位。 |
| 分享当前用户个人背景 | 背景所有者本人 | 创建独立社区副本并立即向当前 ORF 作用域内已激活用户开放；重复分享同一来源保持幂等，撤回后重新分享只恢复原副本。 |
| 撤回本人社区背景 | 社区副本作者 | 只记录撤回时间并隐藏公共入口，不删除文件；已有引用继续可读。 |
| 读取社区背景文件 | 当前 ORF 作用域内已激活用户 | 公开状态均可读；撤回后仅作者或仍保存该副本槽位引用的用户可读。 |
| 上传当前用户头像 | 已激活登录用户 | 校验图片 MIME、真实文件头和大小，写入当前用户头像资源。 |
| 删除当前用户头像 | 已激活登录用户 | 只清空当前用户头像元数据并删除旧对象。 |

系统设置：

| 能力 | 权限 | 约束 |
|---|---|---|
| 查询登录页系统背景 | 公开读取 | 只返回系统登录背景。 |
| 查询非登录槽位系统皮肤 | 已激活登录用户 | 返回共享系统图库中可用于指定 `scene` 的系统皮肤。 |
| 上传系统背景 | `admin` | 按上传入口的 `scene` 写入系统背景目录，但该图片会进入共享系统图库。 |
| 保存系统背景策略 | `admin` | 只能引用系统背景，不能写入个人偏好。 |
| 保存个人背景策略 | `admin` | 只控制个人上传策略，不写个人资源。 |
| 查询聊天设置 | `admin` | 返回聊天附件业务上限和当前基础设施承载上限。 |
| 保存聊天设置 | `admin` | 只能写聊天附件业务上限，且不得超过基础设施承载上限。 |
| 查询反馈设置 | 已激活登录用户 | 返回反馈附件总上限和当前基础设施承载上限，供新建反馈页上传前提示；不包含可写能力。 |
| 保存反馈设置 | `admin` | 只能写单条反馈原始报告的附件总上限，且不得超过基础设施承载上限。 |

当前接口兼容：

- 当前 `/api/settings/visual/*` 属于系统视觉接口。
- 新个人设置接口不得复用旧系统视觉写接口。

## 5. 权限不变量

- `default`、`system` scope 的系统背景图片是公开视觉资源：未登录用户可读取任一规范槽位下的图片，以保证登录页共享系统图库中的跨槽位图片能够直接显示；`personal` scope 仍必须按当前 session 用户严格鉴权。
- 社区背景不是未登录公开资源；它必须通过当前 session 的 ORF 作用域校验，且撤回状态还要校验作者或既有引用。
- 未登录用户除上述系统背景图片和登录页系统背景查询外，不能读取其他系统设置、个人配置或个人背景资源。
- 非管理员不能写系统设置、系统背景资源或系统默认背景。
- 个人设置写接口只能使用当前 session 用户作为写入对象。
- 个人显示偏好只能写入当前用户偏好文件；工作台缩放、CSS token、DOM data 属性和桌面窗口缩放都是前端派生结果，不回写后端。
- 页面筛选偏好只能写入当前用户偏好文件的 `filterPreferences[viewKey]`；后端只校验通用记录结构，具体筛选槽位、合法值、默认值和 URL 深链优先级由页面模型负责，筛选后的业务列表不保存。当前已接入的页面视图 key 为 `challenge.plan` 和 `feedback.issueList`。
- 兼容旧个人工作区布局偏好只能写入当前用户偏好文件；目标、行动项、筛选条件、定位高亮和业务权限不写入该字段，当前前端不再用它恢复聊天目标/行动项工作区。
- 个人头像写接口只能使用当前 session 用户作为写入对象，不能接受任意 `userId`。
- 头像读取接口只能返回当前登录用户所在默认作用域内的用户头像；响应不暴露对象存储 key。
- 所有背景引用都必须校验 owner 和规范存储来源；任一规范槽位图片可用于任一规范槽位。
- 保存个人偏好时允许写入 `login_background`，但该配置只属于当前用户；未登录页不能直接向后端读取它。
- 保存系统配置时，不允许引用个人背景资源。

## 6. 当前落地状态

1. 视觉接口已按系统设置能力收敛，并由独立 settings routes 注册。
2. 系统设置写入 `.orf/settings/system/settings.json`；旧静态运行时路径在启动期无损迁移到私有根，静态服务不再读取或发布它们。
3. 规范场景是 `login_background`、`topbar_background`、`sidebar_background` 和 `page_*_background`。
4. 规范系统上传 scope 是 `system`。
5. 个人偏好接口写入当前 session 用户；`display` 字段统一保存工作台缩放、界面字号、内容字号、界面密度和高对比度，`filterPreferences` 按页面视图 key 保存用户主动选择的筛选偏好，`workspaceLayout` 字段仅保留为旧工作区布局兼容字段。
6. 系统背景图库按 `scene` 共享：`default`、`system` 图片允许公开读取；个人背景读取按 `scene` 返回当前用户共享个人图库，其他用户个人背景不可读写。
7. 用户头像元数据写入 `users.avatar_*`，头像文件写入对象存储；`avatarUrl` 只作为用户和评论读模型派生字段返回。
8. 聊天附件上限写入系统设置的 `chat.attachmentMaxBytes`，默认 2GiB；`ORF_INFRA_UPLOAD_MAX_BYTES` 是基础设施承载上限，默认 10GiB，不反向定义聊天业务规则。
9. 反馈附件总上限写入系统设置的 `feedback.attachmentMaxBytes`，默认 2GiB；缺失字段在读取时归一化，不迁移、覆盖或删除旧设置数据。
10. 社区背景采用作用域隔离的独立文件副本和元数据记录；分享与撤回只扩展设置 API 服务层，不修改个人偏好结构、系统背景 scope 或数据库业务模型。
