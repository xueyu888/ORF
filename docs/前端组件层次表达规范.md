# 前端组件层次表达规范

## 1. 组件树只写三类东西

```text
页面区域
业务对象
关键交互
```

不写：

```text
Wrapper
Box
Container
纯布局层
无职责 List
```

## 2. 重复对象用 `[]`

```text
Card[]
Item[]
Step[]
Option[]
```

`[]` 表示同级有多个。

## 3. 命名公式

```text
业务语义 + 组件形态
```

例如：

```text
UserCard
ProjectItem
TaskItem
MetricCard
FilterPanel
SearchToolbar
```

不要写：

```text
DataBox
MainWrapper
CommonContainer
ListItem
ContentBlock
```

## 4. 常用后缀

```text
Page      页面
Layout    总布局
Sidebar   侧边栏
Main      主内容区
Header    顶部区域
Section   页面分区
Panel     功能面板
Card      卡片
Item      重复业务项
Toolbar   工具栏
Tabs      标签页
Filters   筛选区
Info      信息区
```

## 5. `List` 和 `Row` 少用

`List` 只有承担独立职责才写，比如排序、分页、空状态、批量操作。

否则：

```text
Item[]
```

不要：

```text
ItemList
└─ Item
```

`Row` 只有明确是表格行结构时才写。否则用：

```text
Info
Header
Item
```

## 6. 外部布局

外部布局描述用户进入当前视图后，第一时间可见的内容。

必须完整写清楚可见区域、可见组件、可见字段、字段顺序、父子关系和排列关系。

## 7. 内部布局

内部布局描述用户操作后才可见的内容。

凡是需要点击、展开、hover、切换、打开弹窗或进入详情后才出现的内容，都属于内部布局。

内部布局必须写清楚触发方式、出现位置、可见字段和字段顺序。

## 8. 链接

外部布局遇到内部布局时，只写入口，不展开细节，并链接到对应内部布局章节。

判断标准：

> 不操作页面时，用户第一眼能不能看到？

# 通用模板

```text
Page
└─ Layout
   ├─ Sidebar
   └─ Main
      ├─ Header
      ├─ Toolbar
      └─ Section[]
         ├─ SectionHeader
         └─ Item[]
            ├─ ItemInfo
            └─ ChildItem[]
```

记住一句话：

> 组件树表达业务结构，不表达包装结构。
