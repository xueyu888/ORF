# 设置页面 - 前端

本文只定义前端实现契约。设置业务边界以 [设置边界规则.md](./rules/设置边界规则.md) 为唯一事实源。

## 1. 目标路由

| 页面 | 路由 | 入口 | 可见范围 | 职责 |
|---|---|---|---|---|
| 个人设置 | `/settings` | 侧边栏用户头像菜单 | 所有 `active` 用户 | 当前用户偏好和账号信息展示。 |
| 系统设置 | `/system/settings` | 系统管理页内子页面 | `admin` | 全站默认视觉、登录页背景、系统背景资源和策略。 |

当前实现：`/settings` 承载个人设置；系统级能力统一进入 `/system`，再由 `/system/members`、`/system/permissions`、`/system/settings` 分别承载成员、权限和系统设置。旧 `/settings/system` 只保留兼容跳转。

## 2. 显隐契约

| 显隐点 | 目标 key | 可见范围 | 路由 |
|---|---|---|---|
| 个人设置入口 | `nav.personalSettings` | `all` | `/settings` |
| 个人设置页面访问 | `page.personalSettings` | `all` | `/settings` |
| 系统管理入口 | `nav.systemManagement` | `admin` | `/system` |
| 系统管理页面访问 | `page.systemManagement` | `admin` | `/system` |
| 系统成员页面访问 | `page.systemMembers` | `admin` | `/system/members` |
| 系统权限页面访问 | `page.systemPermissions` | `admin` | `/system/permissions` |
| 系统设置页面访问 | `page.systemSettings` | `admin` | `/system/settings` |

实现要求：

- 组件只能通过 `canShowFrontend()` 和 `canShowFrontendPath()` 判断入口和页面显隐。
- 不能用同一个 `settings` key 同时表达个人设置和系统设置。
- 前端隐藏系统管理入口只是体验优化，后端仍必须拒绝非管理员系统写入。

## 3. 个人设置页面契约

个人设置只读写当前用户事实源。

必须包含：

| 设置项 | 前端行为 |
|---|---|
| 账号信息 | 展示姓名、邮箱、角色、状态；当前不提供自助改名。 |
| 默认进入页面 | 只能选择当前用户可访问的登录后页面。 |
| 侧边栏偏好 | 保存当前用户自己的展开、折叠或密度偏好。 |
| 通知展示偏好 | 保存当前用户自己的通知展示方式。 |
| 个人头像 | 上传、替换、删除或查看当前用户自己的头像原图；未上传或图片加载失败时继续使用姓名首字母占位。 |
| AppShell 皮肤 | 选择系统启用皮肤或本人上传皮肤；AppShell 外壳（侧边栏 + 顶部栏）优先使用个人偏好，顶部栏配色跟侧边栏一致并向右延伸，页面内容区不直接消费该皮肤。 |
| 个人背景上传 | 上传只写入当前用户资源，不进入系统背景资源库。 |

禁止包含：

- 登录页背景配置。
- 系统默认 AppShell 皮肤配置。
- 系统背景资源上传、删除、启用、禁用。
- 成员、角色、权限或全局策略写入。

个人背景展示和回退规则不在本文重复定义，必须引用设置边界规则中的唯一解析规则。

侧边栏用户区规则：

- 全局搜索入口统一放在 AppShell 顶部栏，侧边栏用户区不承载搜索入口。
- 用户头像和用户名区域打开用户菜单。
- 用户菜单包含 `个人设置` 和 `退出登录`；当前用户有头像时包含 `查看头像`。
- 侧边栏头像菜单只负责入口聚合，不写入用户头像事实源或个人偏好。

## 4. 系统设置页面契约

系统设置只读写系统事实源。

当前应承接现有视觉设置能力：

| 设置项 | 前端行为 |
|---|---|
| 登录页背景 | 管理 `login_background`，只允许管理员写入。 |
| 系统默认 AppShell 皮肤 | 管理登录后侧边栏 + 顶部栏默认皮肤；当前前端兼容使用场景 `app_background`。 |
| 系统背景资源 | 管理系统背景上传、默认选择和配置。 |
| 个人背景策略 | 管理是否允许个人上传、大小限制、数量限制等策略。 |

禁止包含：

- 当前用户个人偏好。
- 当前用户个人背景上传入口。
- 把管理员个人偏好保存为系统默认。

## 5. 前端状态归属

| 状态 | 归属 | 说明 |
|---|---|---|
| `personalPreferences` | 当前用户 | 默认页面、侧边栏、通知和个人 AppShell 皮肤偏好。 |
| `currentUser.avatarUrl` | 当前用户投影 | 由用户头像事实源派生，只用于展示，不保存到个人偏好。 |
| `personalBackgroundList` | 当前用户 | 当前用户上传的个人背景。 |
| `systemAppBackgroundList` | 系统只读资源 | 已登录用户可选择的系统 AppShell 皮肤；当前接口场景名仍为 `app_background`。 |
| `systemVisualSettings` | 系统配置 | 登录页背景、系统默认 AppShell 皮肤和系统背景策略。 |
| 页面选中态、菜单开关、原图预览、上传中、图片加载失败、loading、错误提示 | 当前页面临时状态 | 不作为业务事实源。 |

状态不变量：

- 个人设置保存成功只能更新当前用户偏好。
- 个人头像保存成功只能更新当前用户头像事实和用户投影，不能写入个人偏好或系统设置。
- 系统设置保存成功只能更新系统配置。
- 打开时切换、定时切换的运行时位置不写入系统配置或个人偏好。

## 6. 当前落地状态

1. `SettingsPage` 是系统管理内的系统设置页，路由为 `/system/settings`。
2. `PersonalSettingsPage` 是个人设置页，路由为 `/settings`。
3. 显隐 key 已拆成 `personalSettings`、`systemManagement` 和系统管理子页面 key。
4. 登录后 AppShell 皮肤当前兼容使用场景 `app_background`；AppShell 通过个人背景接口优先读取当前用户偏好，并只用于侧边栏 + 顶部栏的 L 型外壳。
5. 个人默认进入页面、侧边栏默认状态、Toast 通知偏好和个人背景选择已走个人设置接口，不能复用系统设置写接口。
6. 个人头像入口在个人设置页账号信息区；上传、删除和原图预览只作用于当前登录用户，展示层统一使用用户头像组件并回退到首字母占位。
7. 侧边栏用户区通过头像菜单承载个人设置、退出登录和查看头像；全局搜索入口统一在顶部栏展示。
