# 权限与用户管理

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

前端固定入口和区域显隐以 `src/config/frontendVisibility.config.json` 为唯一数据配置，并通过 `src/config/frontendVisibility.ts` 统一读取。

## 权限设计原则

权限只描述全局业务动作，不描述前端显隐。

权限只配置管理员和成员存在差异的动作。管理员默认拥有全部权限；成员默认权限显式配置。

前端显隐由 [前端显隐配置.md](../frontend/前端显隐配置.md) 管理，不进入权限表。

权限不表达对象状态判断。是否为提出人、是否在优先期、悬赏是否可申请等对象状态，由业务守卫处理。

权限 key 使用扁平结构，例如 `result.create`、`challenge.assign`、`comment.manage`。

代码中的权限 key 清单以 `src/config/permissions.ts` 为唯一配置来源。

前端可以基于权限控制按钮可见性、可用性和只读态；后端接口必须重新校验权限。

## 权限清单

管理员默认拥有全部权限，不逐项保存。成员默认权限按下表配置。

| 权限 key | 含义 | 成员默认 | 使用位置 |
| --- | --- | --- | --- |
| `objective.create` | 新建目标 | 关闭 | 悬赏大厅、全局新建入口 |
| `objective.edit` | 编辑目标 | 关闭 | 目标页、挑战页目标行 |
| `objective.delete` | 删除目标 | 关闭 | 目标页、挑战页目标行 |
| `result.create` | 新建悬赏指标 | 关闭 | 悬赏大厅、目标页 |
| `result.edit` | 编辑悬赏指标口径 | 关闭 | 目标页、挑战页悬赏指标行 |
| `result.delete` | 删除悬赏指标 | 关闭 | 目标页、挑战页悬赏指标行 |
| `result.reviewCandidate` | 采纳或拒绝候选悬赏指标 | 关闭 | 候选悬赏指标处理 |
| `challenge.assign` | 指定挑战者 | 关闭 | 挑战分配 |
| `challengeApplication.review` | 处理挑战申请 | 关闭 | 挑战申请确认 |
| `task.delete` | 删除行动项 | 关闭 | 挑战页 |
| `subtask.delete` | 删除子行动项 | 关闭 | 挑战页 |
| `settlement.review` | 验收或结算 | 关闭 | 奖励结算 |
| `comment.manage` | 管理所有评论 | 关闭 | 评论组件 |
