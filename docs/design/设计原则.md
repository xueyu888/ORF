# ORF 系统框架

## 核心理念

- 目标导向：所有工作围绕明确目标展开。
- 结果导向：关注可验证结果，不奖励单纯忙碌。
- 数据驱动：用指标、证据和证伪报告判断结果。
- 不确定性导向：奖励把不确定性变成确定性的能力。

## 价值导向

ORF 的价值不是让成员填写更多表格，而是把目标、结果和反馈放进同一个可运行系统。

- 目标必须能被拆成可执行、可验证、可反馈的结果。
- 任务只能说明做了事，结果才能说明产生了价值。
- 反馈必须改变执行；没有调整的反馈不算有效反馈。
- 系统和 AI 应承担信息整理、状态归纳和异常提示，减少管理员处理重复信息的成本。
- 管理员应主要处理目标取舍、关键验收、异常分歧和资源调整。
- 积分用于奖励有效结果、有效证伪和对不确定性的推进，不用于奖励单纯工作量。

## 基础流程

```text
设定悬赏目标
→ 拆解指标
→ 申请挑战 / 征召
→ 确认挑战者
→ 目标重估
→ 目标冻结
→ 提交战利品
→ 目标验收
→ 积分结算
```

指挥官是业务称呼，权限系统中等同管理员。

## 核心规则

- 挑战者绑定到目标，不绑定到指标。
- 任务绑定到目标，不绑定到指标；当前不表达任务对指标的影响。
- 目标冻结默认冻结目标下所有指标。
- 战利品在目标层级提交，用于证明指标完成或有效证伪。
- 完成时间按战利品提交时间判断。
- 任务和子任务只表示执行进度，不自动触发验收或结算。

## 积分规则

```text
目标总分 = 已验收指标不确定性分之和
目标结算积分 = 目标总分 × 完成系数
成员积分 = 目标结算积分 × 贡献比例
```

指标定义分只作为后续扩展预留，当前不单独发放；排行榜只读取后端写入的目标级 `pointLedger`。

不确定性分：

| 等级 | 分值 | 判断标准 |
| --- | ---: | --- |
| 入门 | 10 | 路径清楚，有现成方案 |
| 进阶 | 30 | 方向清楚，但复杂度更高 |
| 破局 | 90 | 需要定义新方法、新标准或新验证口径 |
| 渡劫 | 270 | 关键假设不确定，可能推翻原目标 |
| 飞升 | 810 | 平台级、行业级或方法论级突破 |

完成系数：

| 目标结果 | 系数 | 判断口径 |
| --- | ---: | --- |
| 按时完成 | 100% | 目标截止前提交战利品并通过验收 |
| 延期完成 | 50% | 超过目标截止时间后提交战利品并通过验收 |
| 按时有效证伪 | 100% | 目标截止前提交有效证伪报告 |
| 延期有效证伪 | 50% | 超过目标截止时间后提交有效证伪报告 |
| 目标被有效推翻 | 100% | 指挥官确认目标本身不成立 |
| 主动放弃 | 0% | 无有效战利品或证伪报告 |
| 超预期完成 | 150% | 管理员确认明显超过验收标准 |

个人贡献比例由目标级匿名互评确定。详细规则见：

- [积分结算规则.md](../rules/积分结算规则.md)
- [贡献评价与积分分配规则.md](../rules/贡献评价与积分分配规则.md)
