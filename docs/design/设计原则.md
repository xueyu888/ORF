# ORF系统框架

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

## 核心理念：
1. **目标导向**：所有的工作都应该围绕着明确的目标展开，确保每个任务都为实现目标服务。
2. **结果导向**：关注结果而不是过程，确保每个任务的完成都能为目标的实现做出贡献。
3. **数据驱动**：通过数据来评估目标的完成度，确保评估的客观性和准确性。这里的数据主要是指标的完成度和证伪报告。
4. **不确定性导向**：ORF 奖励的是把不确定性变成确定性的能力。


## 基础概念：
1. **目标**：一个明确的方向
2. **指标**：衡量目标完成度的标准，要能够可观测，可衡量，有明确的截止日期，并且具有挑战性
3. **任务**：为了完成目标而需要完成的具体工作

## 基础流程：
1. **目标设定**：主管设定目标和指标，明确截止日期
2. **指标领取**：团队成员可以根据自身能力和当前负载主动领取指标，但不能随意领取与职责、能力或资源明显不匹配的指标；无人领取的指标，由主管根据目标优先级和团队情况进行安排。
3. **ORF重估**：在评估窗口内，主管和团队成员共同评估目标是否仍然成立，必要时调整指标、调整时间或推翻目标。
4. **目标冻结**：评估窗口结束后，目标和指标进入冻结状态，不再调整，直到目标完成或者目标证伪。
5. **目标验收**：主管根据验收标准、交付结果和证伪报告进行完成评级，并计算积分。

## 积分规则

ORF 的积分由不确定性分和完成系数组成：

**最终积分 = 不确定性分 × 完成系数**

积分不是按工作量、耗时或主观辛苦程度计算，而是奖励把不确定性转化为确定性的结果。

### 1. 不确定性分

不确定性分用于评估任务的交付不确定性。等级越高，代表路径越不清晰、依赖越复杂、验证成本越高，完成后的价值也越高。

系统落地时，不确定性等级直接使用下表五档。已有数据需要在迁移或验收时重新评级。

| 等级 | 分值 | 判断标准 |
| --- | ---: | --- |
| 入门 | 1 | 路径非常清楚，有现成方案可以参考。大部分指标的积分默认为 1。 |
| 进阶 | 3 | 方向清楚，有成熟参考方案，不需要创造新方法。但复杂度明显更高。 |
| 破局 | 9 | 没有现成答案，需要定义新的判断标准、评估口径、业务规则或验证方法，并通过实际数据证明可行。 |
| 渡劫 | 27 | 关键假设本身不确定，可能推翻原目标；需要跨业务、数据、模型、产品多方验证，失败概率高。 |
| 飞升 | 81 | 需要形成行业级、平台级或方法论级突破，完成后显著改变现有能力边界。 |


### 2. 完成系数

完成系数用于评估最终结果。完成必须通过验收；证伪或推翻目标必须形成证伪报告，不能只基于口头说明。

| 结果 | 系数 | 说明 |
| --- | ---: | --- |
| 按时完成 | 100% | 截止前通过验收 |
| 延期完成 | 50% | 超过截止时间后通过验收 |
| 按时指标证伪 | 100% | 截止前提交证伪报告，证明指标在原理上无法达成 |
| 延期指标证伪 | 50% | 超过截止时间后提交证伪报告，完成指标证伪 |
| 重估阶段内目标推翻 | 100% | 在重估阶段内提交证伪报告，证明目标本身不成立 |

| 主动放弃 | 0% | 无有效证据，主动放弃 |
| 超预期完成 | 150% | 明显超过验收标准 |


字段说明：
- **结果**：任务最终状态，包括完成、未完成、指标证伪、评估窗口内目标推翻和主动放弃。
- **系数**：最终积分的乘数。
- **说明**：判断该结果状态的验收标准。

### 3. 特殊说明

1. **指标证伪**：如果通过数据、实验或明确外部约束证明指标在原理上无法达成，并提交证伪报告，视为有效交付；没有证伪报告，不计为有效交付。
2. **目标推翻**：目标推翻只能发生在评估窗口内。
3. **目标优先级调整**：仅调整优先级、延期或暂缓执行，不属于目标推翻，也不触发证伪积分。
4. **评估窗口后处理**：评估窗口结束后，不再认定目标推翻，只能按指标证伪、完成或未完成处理。
5. **主动放弃**：没有有效证据支撑，或没有提交证伪报告，只是主观放弃，完成系数为 0%。
