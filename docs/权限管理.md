# 权限管理

## 认证边界

- Ory Kratos 负责注册、登录、密码和 session。
- 登录页仍然是 ORF 自己的账号密码表单，不向用户展示 Ory。
- ORF 后端提交账号密码到 Ory，并通过 Ory `/sessions/whoami` 校验登录态。
- ORF 数据库只保存业务用户、团队、角色和权限。
- 未通过 Ory session，不能访问 ORF `/api` 业务接口。
- Ory 用户按 `traits.email` 映射到 ORF `users.email`。
- 数据库不可用时，Ory 登录成功也不能进入 ORF。
- 不保留本地文件库或内存库 fallback；认证数据只使用 `.env` 指向的 PostgreSQL。

## 本地 Ory

```bash
npm run ory:dev
npm run server:dev
npm run dev
```

`ory:dev` 会读取 `.env` 中的 `DATABASE_URL`，没有时使用 `REMOTE_DATABASE_URL`。Ory 和 ORF 后端使用同一个数据库连接；mTLS 证书会复制到 `ory/.runtime/` 后挂载进容器，该目录不提交。

本地容器只启动 Kratos public/admin 服务，不启动 Ory 自带登录 UI，也不启动邮件测试服务。

本地 Ory 密码登录只校验最小可用账号密码流程，不依赖外部泄露密码检查服务。

Ory 启动前会检查当前数据库用户是否能执行迁移。这个用户至少需要在 `public` schema 建表：

```sql
GRANT USAGE, CREATE ON SCHEMA public TO <database_user>;
```

本地访问优先使用 `http://127.0.0.1:5173`，避免 `localhost` 和 `127.0.0.1` 的 cookie 域不一致。

## 当前规则

- 输入系统默认进入登录页；Ory session 有效时进入计划页。
- 只有管理员能看到和访问用户权限页。
- 用户权限页只管理用户、邮箱和角色。
- 至少保留一个管理员；最后一个管理员不能被降级或删除。

## 权限模型

```text
can(user, stage, action, resource)
```

| 项 | 值 |
| --- | --- |
| `stage` | 目标设定 / 指标领取 / ORF 重估 / 目标冻结 |
| `action` | 查看 / 创建 / 编辑 / 删除 |
| `resource` | 目标 / 指标 / 任务 / 子任务 |

拖拽调整顺序或父对象属于编辑。删除是独立权限。

## 默认权限

管理员默认拥有全部权限。

| 阶段 | 普通成员权限 |
| --- | --- |
| 目标设定 | 查看目标、指标 |
| 指标领取 | 查看目标、指标 |
| ORF 重估 | 编辑目标、指标、任务、子任务；创建任务、子任务 |
| 目标冻结 | 查看目标、指标；创建、编辑任务、子任务 |
