# ORF 任务管理页面 - 前端

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

本文档只记录前端展示规则、前端派生状态和组件定位。

后端返回字段、枚举和数据关系见 [ORF 任务管理页面 - 后端.md](./ORF%20任务管理页面%20-%20后端.md)。

- `成员管理` 和 `权限管理` 只对管理员显示；页面切换只通过侧边栏完成。
- 侧边栏必须支持折叠为图标栏；折叠态只显示图标，保留设置、菜单入口、搜索和当前登录人头像；当前登录人头像仍可点击切换用户，图标需要提供可识别的 `title` / `aria-label`。

## 1. 层级结构

ORF 任务管理页固定四层结构：

```text
目标
└─ 指标
   └─ 任务
      └─ 子任务
```

树形线条统一由 `<HierarchyTreeOverlay>` 根据 DOM 锚点绘制；`<HierarchyRootCell>` 固定目标根节点，`<HierarchyCell>` 只负责不同深度的内容缩进。

树线规则：

- 树线只根据当前可见父子关系计算；折叠后的隐藏任务和子任务不参与几何计算。
- 每个节点只用主图标作为锚点：目标旗帜、指标方块、任务勾选框、子任务勾选框。
- 线条颜色固定为 `#d0d5dd`；缩进步长固定为 `28px`；圆角横线视觉长度固定为 `20px`。
- 指标、任务、子任务主图标锚点分别为 `56px / 84px / 112px`，对应分支竖线轨道为 `36px / 64px / 92px`。
- 父节点到子节点只允许一条竖线加一条圆角横线；横线终点贴到子节点主图标左边缘，不能穿过图标或进入图标内部。
- 父级竖线只延伸到最后一个可见子节点，不继续穿过下一个兄弟块。
- 新增、删除、拖拽、折叠、展开、刷新后，都必须按当前 DOM 和父子关系重新测量树线。
- 树线压住图标、连接到旧位置、跨越非父子节点，视为几何算法错误。

实现约束：

- 树线几何常量统一放在 `HIERARCHY_TREE_METRICS`：`indentStep = 28`、`branchLength = 20`。
- 块操作入口和折叠 / 展开入口必须复用同一组锚点与偏移，不能单独写左侧偏移。
- 目标卡片内部不显示横向分隔线；目标行、指标行、任务行、子任务行之间只靠树线、缩进和 hover 底色表达层级。

## 1.1 计划模式

计划页不再使用单独的大块流程条展示任务管理阶段。阶段作为目标当前所处的 ORF 工作阶段，放在每个目标框的目标行内，用一个类似 Word 审阅模式的图标按钮表达。

计划模式固定四阶段：

```text
目标设定
指标领取
ORF 重估
目标冻结
```

展示规则：

- 阶段按钮位于目标风险标签右侧、负责人头像组左侧。
- 阶段按钮只显示阶段进度圆点、当前阶段名称和下拉图标，不显示 `计划模式` 文案，也不显示状态胶囊。
- 按钮整体使用中性底色和边框，不随阶段改变颜色。
- 阶段进度圆点使用不同颜色和不同圆环进度表达当前阶段位置。
- 点击按钮后弹出四阶段列表，可切换当前目标的 ORF 阶段。
- 阶段列表是固定弹出菜单，不提供拖拽移动入口。
- 当前阶段之前的阶段显示为已完成，当前阶段显示为进行中，之后的阶段显示为待确认。
- 不再单独显示 `主管确认` 阶段；主管相关动作不作为计划模式阶段展示。
- ORF 阶段不占据页面主体内容块，也不放在筛选工具栏中。
- 当前实现中，目标阶段先存在计划页前端本地状态，按目标 ID 记录，默认值为 `ORF 重估`；刷新页面后恢复默认值。若后续需要长期保存，需要在后端目标数据契约中增加阶段字段。
- 当前实现中，阶段会参与前端权限判断；任务和子任务能否勾选仍由阶段和权限规则共同决定。

## 1.2 块操作

目标、指标、任务、子任务行 hover 时显示块操作入口；同一时间只能显示一个块操作入口，菜单打开时其它行 hover 不再显示块操作入口。鼠标所在行需要有可见但克制的底色，明确当前操作对象。

| 操作 | 展示和行为 |
| --- | --- |
| `+` | 快速新增下级或同级对象。 |
| `GripVertical` | 按住拖拽排序；点击打开块菜单。目标行不支持拖拽，但仍可打开菜单。 |
| `ChevronDown` / `ChevronRight` | 折叠 / 展开，仅有子级的指标和任务显示；它是独立 disclosure 入口，不和 hover 操作组合并。 |

布局规则：

- hover 操作组包含 `+`、`GripVertical`，放在折叠 / 展开入口左侧。
- 折叠 / 展开入口贴在当前行主图标左侧，平时隐藏，只在 hover 当前行或当前行菜单打开时显示。
- 有折叠入口的行，hover 后从左到右为：hover 操作组、独立折叠 / 展开入口、当前行主图标。
- 没有折叠入口的行，仍保留同宽隐形前置槽，不能让主图标向左补位。
- 前置槽宽度固定为 `32px`：`24px` 箭头槽 + `8px` 图标间距；hover 操作组右边缘对齐前置槽左边缘。
- hover 操作组使用细边框和小背景层，遮挡下方树线和内容，避免图标与树线重叠。

新增规则：

| 点击位置 | 新增内容 |
| --- | --- |
| 目标行 `+` | 在该目标下添加指标。 |
| 指标行 `+` | 在该指标下添加任务。 |
| 任务行 `+` | 在该任务下添加子任务。 |
| 子任务行 `+` | 在当前子任务下方添加同级子任务。 |

编辑规则：

- 支持两种入口：点击 `GripVertical` 打开的块菜单中的 `编辑`，或双击目标 / 指标 / 任务 / 子任务对应行。
- 两种入口进入同一种编辑状态；编辑对象必须是当前行对应的块。
- 没有编辑权限时，块菜单中的 `编辑` 不显示，双击行不进入编辑。
- 勾选框、状态下拉、阶段按钮、折叠 / 展开按钮保持各自点击行为，不因为双击而进入行编辑。
- 派生状态不直接编辑，例如目标进度、指标展示状态、子任务展示状态，应由底层字段计算得到。

| 对象 | 可编辑内容 |
| --- | --- |
| 目标 | 标题、状态等目标字段。 |
| 指标 | 标题、负责人、指标数值、后端原始状态等指标字段。 |
| 任务 | 标题、状态、完成情况等任务字段。 |
| 子任务 | 标题、完成情况等子任务字段。 |

块菜单固定包含：复制链接、编辑、评论、删除。排序通过 hover 操作层的块手柄完成；块菜单是固定弹出菜单，不提供浮窗拖拽条或移动能力。

评论规则：

- 评论绑定到当前块：目标、指标、任务、子任务都可以打开评论面板。
- 点击 `评论` 后从右侧打开轻量评论栏，不打断当前计划页上下文。
- 评论栏使用窄栏、弱阴影、少卡片和分隔线组织线程。
- 第一版先做块级线程，不做富文本局部文字选区评论。
- 评论可解决和重新打开；已解决线程保留用于回看讨论结论。

拖拽规则：

- 拖拽属于编辑操作，不是删除后重新创建。
- 拖拽后对象身份不变，评论、历史记录和完成状态保留。
- 目标：不支持拖拽。
- 指标：只能在同一目标内调整顺序，不支持拖到其他目标。
- 任务：可以在同一指标内调整顺序，也可以拖到其他指标下。
- 子任务：可以在同一任务内调整顺序，也可以拖到其他任务下。
- 不允许指标、任务、子任务之间互相转换。

删除规则：

- 删除需要独立权限。
- 删除有下级的对象时，前端需要二次确认，并提示受影响的下级对象数量。

| 2 | 目标标题 | `objective.title` | 已完成时划线变灰。 |
| 3 | 目标风险标签 | `objective.status` | 显示正常 / 有风险。 |
| 4 | ORF 阶段按钮 | `<PlanModeControl>` | 位于风险标签右侧、负责人头像组左侧；显示阶段进度圆点、当前阶段名称和下拉图标。 |

| 顺序 | 字段 | 数据 / 组件 | 前端展示规则 |
| --- | --- | --- | --- |

| 2 | 折叠 / 展开入口 | `<ChevronDown>` / `<ChevronRight>` | 指标有任务时才显示；只控制指标下方任务展开 / 折叠。 |

| 5 | 负责人 | `result.owner` / `<PersonValue>` | 一个指标只显示一个负责人。 |

## 3. 前端派生状态

| 对象 | 展示状态 | 派生来源 |
| --- | --- | --- |
| 目标 | 无独立状态图标 | 只通过目标进度条表达完成情况。 |
| 指标 | 待办 / 进行中 / 待验收 / 已完成 | `indicatorStatus(result, tasks)`。 |
| 任务 | 待办 / 进行中 / 已完成 | `task.status` 归一化后显示。 |
| 子任务 | 待办 / 进行中 / 已完成 | `item.done` 和所在任务状态共同决定。 |

状态视觉规则：

- 完成态不要使用高饱和亮色强调；高亮颜色保留给待办、进行中、待验收、风险等仍需处理的状态。
- 状态标签：待办、进行中、待验收、风险、正常等未完成 / 需关注状态使用淡底色和 1px 边框增强扫视识别，不使用额外小圆点；已完成状态去掉底色，使用低强调灰色文字。
- 已完成：标题划线并变灰；已完成的目标、指标、任务、子任务行不增加整行灰底。
- 目标保留旗子图标，完成情况只通过进度条表达；指标保留正方形颜色块；任务和子任务保留圆形勾选框。
- 只有目标显示进度条；指标、任务、子任务不显示进度条。

## 4. 前端进度计算

目标进度由指标平均得到；指标下有任务时，指标进度由任务平均得到；任务下有子任务时，任务进度由子任务平均得到。

```text
s(待办) = 0
s(进行中) = 0.5
s(已完成) = 1

p(子任务) = s(子任务状态)

p(任务) =
  平均值(p(子任务[]))，如果任务下有子任务
  s(任务状态)，如果任务下没有子任务

p(指标) =
  平均值(p(任务[]))，如果指标下有任务
  指标自身完成率，如果指标下没有任务

p(目标) = 平均值(p(指标[]))

目标进度条 = round(p(目标) × 100%)
```

指标自身完成率由 `resultProgress(result)` 计算。
