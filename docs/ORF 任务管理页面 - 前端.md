# ORF 任务管理页面 - 前端

本文档只记录前端展示规则、前端派生状态和组件定位。

后端返回字段、枚举和数据关系见 [ORF 任务管理页面 - 后端.md](./ORF%20任务管理页面%20-%20后端.md)。

前端任务数据通过同源 `/api` 访问后端；后端不可用时保留本地状态兜底。

## 0. 全局侧边栏

侧边栏当前只保留以下入口：

```text
自定义 ORF Logo | ORF Flow | 折叠图标

work
- 计划
- 周复盘

report
- 反馈
- 统计

admin
- 成员管理
- 权限管理

搜索

设置

当前登录人：头像 + 姓名
```

品牌 Logo 使用前端资源 `src/assets/brand/orf-logo.png`，侧边栏和登录页保持同一份设计稿。

说明：

- `计划` 对应任务管理页。
- `反馈` 是单纯的反馈记录，不要求立即建立任务；未来反馈可能转化为工作目标。
- `统计` 用于统计历史目标完成情况和每个人的积分情况。
- `成员管理` 和 `权限管理` 只对管理员显示；`成员管理` 位于 `权限管理` 上方。
- `成员管理` 展示原权限管理页中的用户管理内容，负责用户列表、角色切换、用户详情和新增 / 编辑 / 删除入口。
- `权限管理` 展示原权限管理页中的角色权限内容，负责管理员 / 成员角色权限矩阵。
- `成员管理` 和 `权限管理` 页面内部不再展示互相切换的页签按钮，页面切换只通过侧边栏完成。
- `成员管理` 页头右侧只展示用户数量和角色数量；`权限管理` 页头右侧只展示权限数量。两个页面的页头统计区都靠右放置，并保持相同对齐位置。
- 设置只作为底部图标入口，不放入普通菜单分组。
- 侧边栏必须支持折叠为图标栏；折叠态只显示图标，保留设置、菜单入口、搜索和当前登录人头像，图标需要提供可识别的 `title` / `aria-label`。

## 0.1 全局顶部栏

顶部栏当前只保留全局导航和快速创建入口：

```text
当前页面路径 / 标题
搜索目标、结果、任务、反馈...
新建反馈
新建目标
```

说明：

- `新建反馈` 是全局快速记录入口，用来捕获临时问题、线上信号、评估失败、用户反馈或复盘发现；反馈不要求立即进入本次目标或任务，但后续可以转化为目标、指标或任务。
- `新建目标` 是全局创建目标入口。
- 权限快捷图标、演示按钮和顶部栏用户头像不在顶部栏展示。
- ORF 阶段不放在顶部栏或页面工具栏，放到每个目标框的目标行内。

## 1. 层级结构

ORF 任务管理页固定四层结构：

```text
目标
└─ 指标
   └─ 任务
      └─ 子任务
```

目标框内的树形线条使用 `<HierarchyCell>` 和 `<HierarchyTreeOverlay>` 复用。所有层次化线条都必须使用这套样式。

树线样式规则：

- 竖线必须连续，不按单行切成断裂短线。
- 当前节点用圆角弯线连接到内容字段。
- 线条颜色固定为 `#d0d5dd`。
- 缩进步长固定为 `28px`。
- 目标 → 指标、指标 → 任务、任务 → 子任务的圆角分支线必须共用等距轨道；相邻竖线轨道间距固定为 `28px`，不能因为图标尺寸、折叠入口或块操作入口不同而忽宽忽窄。
- 每一级圆角横线的视觉长度固定为 `20px`，终点贴到子级主图标左边缘。
- 目标行不画树线，指标行开始画树线。
- 树线只能走在主图标左侧的 gutter 内，不能穿过目标、指标、任务、子任务图标。

| 层级 | 对象 | 树形深度 | 说明 |
| --- | --- | ---: | --- |
| 1 | 目标 | 0 | 目标行不画树形线，是树根。 |
| 2 | 指标 | 1 | 指标行开始画树形线。 |
| 3 | 任务 | 2 | 任务行向指标缩进一层。 |
| 4 | 子任务 | 3 | 子任务行向任务缩进一层。 |

树形几何准则：

- 树线只根据当前可见树结构计算，不根据历史拖拽位置计算。
- 每个节点只用主图标作为锚点：目标旗帜、指标方块、任务勾选框、子任务勾选框。
- 父节点到子节点只允许一条竖线加一条圆角横线；横线终点贴到子节点主图标左边缘。
- 树线竖向轨道和主图标锚点必须成组调整：指标、任务、子任务的锚点按 `28px` 等差缩进，分支竖线位于对应锚点左侧 `20px`。
- 目标根节点的主图标中心必须固定在第一层分支竖线轨道上；目标行不预留折叠 / 展开槽，不能套用指标行、任务行的前置槽布局。
- 横线不能进入子节点主图标内部；若父节点中心线离子节点图标太近，竖线必须向左避让到 gutter。
- 父级竖线只延伸到最后一个可见子节点，不继续穿过下一个兄弟块。
- 折叠后只计算可见节点；隐藏的任务和子任务不参与树线几何。
- 新增、删除、拖拽、折叠、展开、刷新后，都必须按当前 DOM 和父子关系重新测量树线。
- 如果树线压住图标、连接到旧位置、跨越非父子节点，视为几何算法错误。

实现约束：

- `<HierarchyRootCell>` 固定目标根节点的主图标锚点；目标行不得手写目标旗帜、隐形前置槽或 `data-hierarchy-anchor`。目标根节点不预留折叠 / 展开前置槽。
- `<HierarchyCell>` 只负责不同深度的内容缩进；树线统一由 `<HierarchyTreeOverlay>` 根据 DOM 锚点绘制。
- 树线几何常量统一放在 `HIERARCHY_TREE_METRICS`：`indentStep = 28`、`branchLength = 20`。
- 指标、任务、子任务主图标锚点分别为 `56px / 84px / 112px`，对应分支竖线轨道为 `36px / 64px / 92px`。
- 块操作入口、折叠 / 展开入口必须根据同一组锚点对齐，不能单独写一套左侧偏移。

## 1.1 计划模式

计划页不再使用单独的大块流程条展示任务管理阶段。阶段作为目标当前所处的 ORF 工作阶段，放在每个目标框的目标行内，用一个类似 Word 审阅模式的图标按钮表达。

计划模式固定四阶段：

```text
目标设定
指标领取
ORF 重估
目标冻结
```

展示规则：

- 阶段按钮位于目标风险标签右侧、负责人头像组左侧。
- 阶段按钮只显示阶段进度圆点、当前阶段名称和下拉图标，不显示 `计划模式` 文案，也不显示状态胶囊。
- 按钮整体使用中性底色和边框，不随阶段改变颜色。
- 阶段进度圆点使用不同颜色和不同圆环进度表达当前阶段位置。
- 点击按钮后弹出四阶段列表，可切换当前目标的 ORF 阶段。
- 阶段列表是固定弹出菜单，不提供拖拽移动入口。
- 当前阶段之前的阶段显示为已完成，当前阶段显示为进行中，之后的阶段显示为待确认。
- 不再单独显示 `主管确认` 阶段；主管相关动作不作为计划模式阶段展示。
- ORF 阶段不占据页面主体内容块，也不放在筛选工具栏中。
- 当前实现中，目标阶段先存在计划页前端本地状态，按目标 ID 记录，默认值为 `ORF 重估`；刷新页面后恢复默认值。若后续需要长期保存，需要在后端目标数据契约中增加阶段字段。
- 当前实现中，阶段会参与前端权限判断；任务和子任务能否勾选仍由阶段和权限规则共同决定。

## 1.2 块操作

目标、指标、任务、子任务行 hover 时显示块操作入口：

- `ChevronDown` / `ChevronRight`：折叠 / 展开，仅有子级的指标和任务显示；它是独立的 disclosure 入口，不和 `+`、块手柄合并成一组。
- `+`：快速新增。
- `GripVertical` / 块手柄：按住拖拽排序，点击打开块菜单。
- 块操作入口贴近当前行图标，目标、指标、任务、子任务保持一致距离。
- 折叠 / 展开入口贴在当前行图标左侧，平时隐藏；选中有子级的指标或任务时才显示。
- 指标行的折叠 / 展开入口不能占用布局宽度，避免有子级和无子级指标的图标错位。
- `+` 和块手柄作为块操作组，放在折叠 / 展开入口左侧，保持紧凑。
- `+` / 块手柄操作组使用细边框，明确它是 hover 操作层。
- 有折叠入口的行，hover 后从左到右为：`+` / 块手柄操作组、独立折叠 / 展开入口、当前行图标。
- 没有子级的行，hover 后只显示 `+` / 块手柄操作组，不显示折叠 / 展开占位。
- `+` 和块手柄之间保持紧凑间距；入口出现时用小背景层遮挡下方树线和内容。
- 同一时间只能显示一个块操作入口；菜单打开时，其它行 hover 不再显示块操作入口。
- 树形层级线条：目标连接指标、指标连接任务、任务连接子任务都需要完整连接；每一级横线使用 `20px` 视觉长度，并贴到子级图标边缘。
- 目标卡片内部不显示横向分隔线；目标行、指标行、任务行之间只靠树线、缩进和 hover 底色表达层级。
- 鼠标所在的目标、指标、任务、子任务行需要有可见但克制的底色，明确当前操作的是哪一行；底色需要比卡片 hover 色稍深。

操作层与图标间距定义：

- 开始点：当前行主图标左侧前置操作槽的左边缘。有折叠 / 展开箭头时，开始点是箭头按钮左边缘；没有箭头时，开始点是同宽隐形箭头槽的左边缘。
- 结束点：当前行主图标左边缘。目标的主图标是目标旗帜图标，指标的主图标是指标方块，任务和子任务的主图标是圆形勾选框。
- 开始点到结束点的距离固定为 `32px`：`24px` 箭头槽 + `8px` 图标间距。
- `+` / 块手柄操作组的右边缘对齐开始点。这样无论某行是否显示折叠 / 展开箭头，操作组、箭头槽和主图标之间的水平节奏都一致。
- 没有折叠 / 展开箭头的目标、无子任务的任务、子任务，也必须保留这段隐形前置槽；不能让主图标向左补位。

`+` 规则：

- 目标行：在该目标下添加指标。
- 指标行：在该指标下添加任务。
- 任务行：在该任务下添加子任务。
- 子任务行：在当前子任务下方添加同级子任务。

块菜单固定包含：复制链接、评论、删除。排序通过 hover 操作层的块手柄完成：按住块手柄拖拽到合法位置。块菜单是固定弹出菜单，不提供浮窗拖拽条或移动能力。

评论规则：

- 评论绑定到当前块：目标、指标、任务、子任务都可以打开评论面板。
- 点击 `评论` 后从右侧打开轻量评论栏，不打断当前计划页上下文。
- 评论栏参考 Notion / 飞书文档评论的轻量视觉：窄栏、弱阴影、少卡片、用分隔线组织线程。
- 评论栏展示当前块标题、打开线程、已解决线程和评论输入框。
- 第一版先做块级线程，不做富文本局部文字选区评论。
- 评论可解决和重新打开；已解决线程保留用于回看讨论结论。

拖拽规则：

- 拖拽属于编辑操作，不是删除后重新创建。
- 拖拽后对象身份不变，评论、历史记录和完成状态保留。
- 目标：不支持拖拽。
- 指标：只能在同一目标内调整顺序，不支持拖到其他目标。
- 任务：可以在同一指标内调整顺序，也可以拖到其他指标下。
- 子任务：可以在同一任务内调整顺序，也可以拖到其他任务下。
- 不允许指标、任务、子任务之间互相转换。

删除规则：

- 删除需要独立权限。
- 删除有下级的对象时，前端需要二次确认，并提示受影响的下级对象数量。

子任务不显示进度条。任务到子任务的树形横线必须贴到子任务勾选框左边缘，不在图标前留空，也不穿过图标。

## 3. 前端派生状态

| 对象 | 展示状态 | 派生来源 |
| --- | --- | --- |
| 目标 | 无独立状态图标 | 只通过目标进度条表达完成情况。 |
| 指标 | 待办 / 进行中 / 待验收 / 已完成 | `indicatorStatus(result, tasks)`。 |
| 任务 | 待办 / 进行中 / 已完成 | `task.status` 归一化后显示。 |
| 子任务 | 待办 / 进行中 / 已完成 | `item.done` 和所在任务状态共同决定。 |

状态视觉规则：

- 完成态不要使用高饱和亮色强调；高亮颜色保留给待办、进行中、待验收、风险等仍需处理的状态。
- 状态标签：待办、进行中、待验收、风险、正常等未完成 / 需关注状态使用淡底色和 1px 边框增强扫视识别，不使用额外小圆点；已完成状态去掉底色，使用低强调灰色文字。
- 已完成：标题划线并变灰；已完成的目标、指标、任务、子任务行不增加整行灰底。
- 目标：保留旗子图标；目标完成情况仍以进度条为准，图标颜色不反向强调完成态。
- 指标：保留正方形颜色块，颜色表达状态。
- 任务、子任务：保留圆形勾选框，勾选框表达完成。
- 只有目标显示进度条；指标、任务、子任务不显示进度条。

## 4. 前端进度计算

目标进度由指标平均得到；指标下有任务时，指标进度由任务平均得到；任务下有子任务时，任务进度由子任务平均得到。

```text
s(待办) = 0
s(进行中) = 0.5
s(已完成) = 1

p(子任务) = s(子任务状态)

p(任务) =
  平均值(p(子任务[]))，如果任务下有子任务
  s(任务状态)，如果任务下没有子任务

p(指标) =
  平均值(p(任务[]))，如果指标下有任务
  指标自身完成率，如果指标下没有任务

p(目标) = 平均值(p(指标[]))

目标进度条 = round(p(目标) × 100%)
```

指标自身完成率由 `resultProgress(result)` 计算。
