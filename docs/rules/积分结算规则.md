# 积分结算规则

## 计分对象

- 积分按悬赏目标结算。
- `Objective` 是积分分配对象。
- `Objective.objectiveBasePoints` 是目标基础分事实源；`Result` 不再提供目标分数。
- 目标参与成员身份来自 `Objective.challengerUserIds`；`Objective.challengers` 只是显示名投影。
- `pointLedger.userId` 只在目标所属默认作用域内解析，避免底层存储 scope 间同名成员污染积分流水。
- 个人贡献比例由目标级匿名互评产生，规则见 [贡献评价与积分分配规则.md](./贡献评价与积分分配规则.md)。
- 核算后的 `pointLedger` 是公开积分结果；普通成员和管理员都可以按季度、年度和全部时间查看积分榜。

## 时间字段

| 字段 | 含义 |
| --- | --- |
| `Objective.acceptedAt` | 挑战者接受目标挑战时间 |
| `Objective.finalDueAt` | 目标截止时间 |
| `Objective.lootSubmittedAt` | 目标战利品提交时间 |

按时或延期只看 `lootSubmittedAt`，不看接受时间或验收时间。目标分数在指挥官验收通过、目标进入 `accepted` 并打开最终匿名互评后锁定；在此之前指挥官仍可修改。

重估和冻结状态见 [ORF 悬赏目标流程设计.md](./ORF%20悬赏目标流程设计.md)。

## 公式

```text
目标基础分 = Objective.objectiveBasePoints

目标结算积分 = 目标基础分 × 结算事件倍率

成员结算积分 = 目标结算积分 × 贡献比例

成员总积分 = pointLedger 中该成员积分之和
```

## 目标基础分

目标基础分由指挥官直接设置为正整数。系统不再使用“简易 / 入门 / 进阶”等等级为指标换算分数，也不再从指标积分汇总目标基础分。

分数可以在目标候选、发布、申请、征召、重估、冻结和战利品已提交待验收阶段修改。目标经指挥官验收通过进入 `accepted` 后，系统打开最终匿名互评并锁定目标基础分；最终结算、排行榜和账本都读取锁定后的 `Objective.objectiveBasePoints`。

目标分数为 `0` 的历史或未设置数据按“待定分”展示；进入 `accepted` 前必须补成正整数，否则验收通过会被拒绝。

## 统计口径

- 当前排行榜积分只读取 `pointLedger` 中的目标结算积分；完成率不是积分事实源，由 `src/domain/reportsLeaderboard` 按成员参与的结算目标派生，并结合目标状态和正式验收历史判断。
- 演示、seed、E2E 和手工测试数据必须通过独立 team/scope 隔离；排行榜模型不得通过成员名、目标名或原因文本猜测并过滤非正式数据。

候选指标的优先参与规则未定，见 [ORF 悬赏目标流程设计.md](./ORF%20悬赏目标流程设计.md)。

## 结算事件倍率

结算事件倍率用于结算事件。验收不通过但已经到达截止日时，先触发独立的 `deadlinePenalty` 事件，按目标基础分 `50%` 写入惩罚积分，目标仍需继续完成；后续返工通过后，`finalCompletion` 只关闭最终结算状态，不补回已扣掉的分。当前实现字段 `completionMultiplier` 承载该倍率。

| 目标结果 | 系数 | 规则 |
| --- | ---: | --- |
| 按时完成 | 100% | `acceptedResult = completed` 且 `lootSubmittedAt <= finalDueAt` |
| 延期完成 | 50% | `acceptedResult = completed` 且 `lootSubmittedAt > finalDueAt` |
| 按时有效证伪 | 100% | `acceptedResult = falsified` 且 `lootSubmittedAt <= finalDueAt` |
| 延期有效证伪 | 50% | `acceptedResult = falsified` 且 `lootSubmittedAt > finalDueAt` |
| 目标被有效推翻 | 100% | `acceptedResult = overturned`，且指挥官确认目标本身不成立 |
| 主动放弃 | 0% | 无有效战利品或证伪报告 |
| 超预期完成 | 150% | 管理员确认明显超过验收标准 |

## 验收

目标验收时，管理员确认：

- 每个指标的验收结果。
- 目标结果由指标验收结论汇总；全部指标完成则目标完成。
- 验收不通过时，目标进入 `revisionRequired`；若已到截止日且 `deadlinePenalty` 尚未结算，仍要匿名互评并执行惩罚结算；惩罚结算后必须重新提交并再次验收，通过后才进入最终互评和 `finalCompletion` 结算。
- 如果同一目标此前已有 `deadlinePenalty`，最终通过后的 `finalCompletion` 事件写入 `0` 分；本期扣掉的分不补回。
- 最终验收通过时，目标进入 `accepted`，锁定目标基础分，并提醒挑战者可重新检查匿名互评是否需要调整。
- 指挥官确认本次结算事件的贡献比例；页面默认值来自共享匿名互评结算服务返回的当前均值。
- 缺评、弃权、分歧或申诉只提示指挥官，不阻止指挥官提交合法比例并结算。
- ORF 后端只保存 `objectiveAcceptanceReviews`、`objectiveSettlementEvents`、核算后的结算字段和追加式 `pointLedger`，不保存新提交的匿名互评原始数据；指挥官验收页通过代理实时读取的原始明细不进入 ORF 业务数据库。

任务和子任务勾选状态不计分，也不自动产生验收结果。排行榜积分读取后端生成的 `pointLedger`；排行榜完成率以有积分流水的成员-目标为统计对象，目标必须最终结算且验收历史中没有 `acceptedResult = abandoned` 才计作完成。验收不通过代表截止验收未通过，后续返工通过只影响最终积分结算，不抹掉完成率中的未完成记录。
