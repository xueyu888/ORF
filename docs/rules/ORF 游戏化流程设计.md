# ORF 游戏化流程设计


## 目标

本文档定义 ORF 悬赏指标流程的游戏化表达方式。

ORF 中的 `Result` 在产品层表达为“悬赏指标”。用户通过悬赏大厅查看、挑战、重估、执行、提交证据并获得结算。

该设计的目标不是把 ORF 做成娱乐系统，而是用游戏化方式增强悬赏指标流转的参与感、确定性和反馈闭环。

## 核心原则

1. 悬赏指标不是普通任务，任务必须挂在悬赏指标下面。
2. 悬赏指标必须可执行、可量化、可验证。
3. 难度在发布悬赏指标时公开，不由挑战者自评。
4. 挑战者可以重估悬赏指标合理性。
5. 只有重估导致悬赏指标内容变化时，难度才可以调整。
6. 主线悬赏指标必须有人负责。
7. 支线悬赏指标可以无人挑战。
8. 奖励结算基于难度和完成结果，不奖励单纯忙碌。

## 核心术语

| ORF 语义 | 游戏化术语 | 说明 |
| --- | --- | --- |
| Objective | 目标 | 当前阶段要改变的方向 |
| Result | 悬赏指标 | 可执行、可量化、可验证的结果口径 |
| Task | 任务 | 悬赏指标下面的具体执行动作 |
| TaskChecklistItem | 子任务 | 任务下面的最小勾选项 |
| 关键悬赏指标 | 主线悬赏指标 | 必须完成，直接支撑目标达成 |
| 可选悬赏指标 | 支线悬赏指标 | 可选完成，用于优化、探索或额外收益 |
| 悬赏指标列表 | 悬赏大厅 | 用户查看和参与悬赏指标的入口 |
| 申请负责 | 我要挑战 | 成员表达希望负责该悬赏指标 |
| 悬赏指标负责人 | 挑战者 | 被确认负责悬赏指标的人 |
| 交付证据 | 战利品 | 证明悬赏指标完成或证伪的材料 |
| 验收 | 通关验收 | 根据验收标准判断结果是否有效 |
| 积分计算 | 奖励结算 | 根据难度和完成结果计算积分 |

## 悬赏指标类型

### 主线悬赏指标

主线悬赏指标是必须完成的悬赏指标，直接支撑目标达成。

规则：

- 发布后进入悬赏大厅。
- 成员可以点击“我要挑战”。
- 主管或发布者确认挑战者。
- 如果无人挑战，进入征召。
- 征召后由主管指定挑战者。
- 被征召的挑战者仍然可以重估悬赏指标合理性。

### 支线悬赏指标

支线悬赏指标是可选悬赏指标，用于探索、优化、改进或额外收益。

规则：

- 发布后进入悬赏大厅。
- 成员可以点击“我要挑战”。
- 主管或发布者确认挑战者。
- 无人挑战时可以继续挂起、过期关闭或后续重新发布。
- 支线悬赏指标不进入征召。

## 核心流程

```text
发布悬赏指标 → 我要挑战 → 确认挑战者 → 重估悬赏指标 → 开始挑战 → 提交战利品 → 奖励结算
```
