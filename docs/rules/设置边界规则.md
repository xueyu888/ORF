# 设置边界规则

本文是设置领域的业务事实源。前端、后端和测试文档只引用这里的边界，不重复定义个人设置、系统设置和背景解析规则。

## 1. 目标契约

ORF 设置拆成两个正交作用域：

| 设置域 | 路由 | 可见范围 | 写入事实源 | 职责 |
|---|---|---|---|---|
| 个人设置 | `/settings` | 所有 `active` 用户 | 当前用户偏好 | 只影响当前用户本人。 |
| 系统设置 | `/settings/system` | `admin` | 系统配置 | 影响全站默认、系统资源和全局策略。 |

硬约束：

- `/settings` 不能承载系统写入动作。
- `/settings/system` 不能承载当前用户个人偏好。
- 普通成员可以进入个人设置，但不能进入系统设置。
- 管理员同时拥有个人设置和系统设置；管理员个人偏好不能自动写成系统默认。

## 2. 背景分层

背景允许个性化，但必须按场景和所有权分层。

| 层级 | 场景 | 写权限 | 影响范围 |
|---|---|---|---|
| 系统登录背景 | 登录页 `login_background` | `admin` | 所有未登录用户和登录页 |
| 系统应用背景默认值 | 登录后应用背景默认值 | `admin` | 没有个人偏好的登录用户 |
| 个人应用背景偏好 | 登录后应用背景偏好 | 当前用户 | 当前用户本人 |

唯一解析规则：

```text
登录页背景 = system.loginBackground

登录后应用背景 =
  currentUser.personalAppBackground
  ?? system.defaultAppBackground
  ?? builtInFallback
```

不变量：

- 登录页发生在认证前，不能读取个人偏好。
- 个人背景只在登录后的 AppShell、侧边栏和工作台类页面生效。
- 普通成员不能写系统背景、系统默认背景或系统背景资源库。
- 个人上传背景只属于当前用户，不进入系统资源库。
- 背景资源和偏好必须能区分 owner：`system` 或 `userId`。

## 3. 设置范围

个人设置只影响当前用户：

| 设置项 | 结论 |
|---|---|
| 账号信息展示 | 个人设置，只读。 |
| 默认进入页面 | 个人设置。 |
| 侧边栏偏好 | 个人设置。 |
| 通知展示偏好 | 个人设置。 |
| 登录后应用背景选择、模式、上传 | 个人设置，受系统策略约束。 |
| 自助改名 | 未定，需要单独产品决策。 |
| 修改角色、权限、登录页背景 | 不是个人设置。 |

系统设置影响全站默认、策略或共享资源：

| 设置项 | 结论 |
|---|---|
| 登录页背景 | 系统设置。 |
| 系统默认应用背景 | 系统设置。 |
| 系统背景资源库 | 系统设置。 |
| 个人背景上传策略 | 系统设置。 |
| 成员管理、权限管理、ORF 全局规则 | 系统设置。 |

## 4. 权限不变量

- 前端显隐只处理入口体验，不是安全边界。
- 后端接口必须分别校验个人设置和系统设置权限。
- 个人设置写接口只能修改当前 session 用户自己的偏好和资源。
- 系统设置写接口必须要求 `admin`。
- 未登录用户只能读取登录页所需的系统公开资源。
- 已登录用户可以读取系统启用的应用背景和自己的个人背景，不能读取其他用户的个人背景。

## 5. 当前实现与兼容

当前视觉设置属于系统设置，已按下表收敛：

| 当前概念 | 目标概念 |
|---|---|
| `/settings` 承载视觉设置 | 已改为 `/settings/system` 承载系统设置。 |
| 侧边栏用户区 `设置` 只对管理员可见 | 已改为个人设置入口对所有 `active` 用户可见。 |
| `login_background` | 系统登录背景，继续系统级管理。 |
| `sidebar_background` | 旧系统默认应用背景别名；规范场景已统一为 `app_background`。 |
| `public/settings/user/*` 保存管理员上传背景 | 只作为旧系统路径兼容读取，不能作为普通用户个人设置路径。 |
| 普通成员不可见设置 | 普通成员不可见系统设置，但可见个人设置。 |

后续新增个人背景写入时，必须继续同时更新前端路由、后端接口、测试用例和 issue 结论。
