# 设置边界规则

本文是设置领域的业务事实源。前端、后端和测试文档只引用这里的边界，不重复定义个人设置、系统设置和背景解析规则。

## 1. 目标契约

ORF 设置拆成两个正交作用域：

| 设置域 | 路由 | 可见范围 | 写入事实源 | 职责 |
|---|---|---|---|---|
| 个人设置 | `/settings` | 所有 `active` 用户 | 当前用户偏好 | 只影响当前用户本人。 |
| 系统设置 | `/system/settings` | `admin` | 系统配置 | 影响全站默认、系统资源和全局策略。 |

硬约束：

- `/settings` 不能承载系统写入动作。
- `/system/settings` 不能承载当前用户个人偏好。
- 普通成员可以进入个人设置，但不能进入系统设置。
- 管理员同时拥有个人设置和系统设置；管理员个人偏好不能自动写成系统默认。

## 2. 显示尺度分层

界面大小、字号、密度和对比度允许按用户个性化，但必须仍然是同一套 AppShell 显示模型。

| 设置项 | 写权限 | 影响范围 | 说明 |
|---|---|---|---|
| 工作台缩放 | 当前用户 | 当前用户登录后的整体工作台 | Web 端映射到根字号缩放；桌面端优先映射到 Electron 窗口缩放。 |
| 界面字号 | 当前用户 | 当前用户登录后的导航、按钮、表单和通用控件 | 作为界面排版基准，不直接修改业务事实。 |
| 内容字号 | 当前用户 | 当前用户阅读/输入的正文类内容 | 作用于评论、反馈正文、聊天正文和富文本输入等内容区域。 |
| 界面密度 | 当前用户 | 当前用户登录后的控件高度、行高、间距 | 只改变显示密度，不改变业务列表、分页或权限结果。 |
| 高对比度 | 当前用户 | 当前用户登录后的色彩 token 和焦点可见性 | 使用统一 token 覆盖，不新建独立主题事实源。 |
| 工作区布局 | 当前用户 | 当前用户登录后的可分离工作区打开状态和尺寸 | 当前只保存聊天目标/行动项侧栏状态和宽度；不保存目标、行动项、筛选条件或定位高亮。 |

唯一解析规则：

```text
AppShell 显示偏好 =
  currentUser.displayPreferences
  ?? builtInDisplayFallback

页面显示状态 =
  AppShellDisplayTokens(AppShell 显示偏好)
```

不变量：

- 显示偏好只属于当前用户，不是系统默认，不影响其他用户。
- 显示偏好是业务事实源；CSS 变量、DOM data 属性、桌面窗口缩放和页面排版结果都是派生数据。
- 页面和组件只能消费统一显示 token，不能各自保存另一套字号、缩放、密度或高对比度规则。
- 移动端只消费同一显示偏好和响应式布局，不能另起移动端显示事实源。

## 3. 背景分层

背景允许个性化，但必须按场景和所有权分层。

| 层级 | 场景 | 写权限 | 影响范围 |
|---|---|---|---|
| 系统登录背景 | 登录页 `login_background` | `admin` | 没有本机个人登录页缓存时的登录页 |
| 个人登录页皮肤 | 登录页 `login_background` 的当前用户偏好 | 当前用户 | 只在用户登录后可配置；登出页只读取本机缓存预览 |
| 系统顶部栏皮肤默认值 | 登录后 AppShell 顶部栏 `topbar_background` | `admin` | 没有个人偏好的登录用户 |
| 系统侧边栏皮肤默认值 | 登录后 AppShell 侧边栏 `sidebar_background` | `admin` | 没有个人偏好的登录用户 |
| 个人顶部栏/侧边栏皮肤偏好 | `topbar_background`、`sidebar_background` | 当前用户 | 当前用户本人 |
| 页面级皮肤 | 页面自己的内容区皮肤，例如 `page_bounties_background`、`page_tasks_background`、`page_work_logs_background` | `admin` 默认 + 当前用户覆盖 | 默认只影响对应页面内容区；设置页保存时可把当前配置一次性写入全部或部分页面 |
| 聊天主内容区背景 | `/chat` 主工作台背景 | 当前用户聊天主题 | 聊天页不参与普通页面级皮肤；切换到聊天路由时由 AppShell 立即铺设聊天主题背景，避免背景图闪烁并保证阅读区稳定。 |

图库边界：

- 任一规范皮肤槽位上传的系统图片会进入共享系统图库，登录页、顶部栏、侧边栏和页面内容区都可选择。
- 任一规范皮肤槽位上传的个人图片只进入当前用户自己的共享个人图库，不能被其他用户读取或引用。
- 旧 `page_chat_background` 目录里的图片只作为历史图库来源兼容读取，可被其它规范槽位选择；它不再是可配置的页面级皮肤槽位。
- 图片资产共享不改变槽位事实源；每个槽位仍保存自己的 `backgrounds[scene]` 配置、`crops[imageId]` 和 `overlayOpacity`。
- 页面“应用页面”只是一次保存动作的目标集合，不作为长期隐藏分组规则；保存后被写入的页面槽位仍可独立调整。

唯一解析规则：

```text
登录页背景 =
  localDevice.cachedPersonalLoginBackground
  ?? system.loginBackground
  ?? builtInFallback

AppShell 顶部栏皮肤 =
  currentUser.personalTopbarSkin
  ?? system.defaultTopbarSkin
  ?? builtInFallback

AppShell 侧边栏皮肤 =
  currentUser.personalSidebarSkin
  ?? system.defaultSidebarSkin
  ?? builtInFallback

页面级皮肤 =
  currentUser.personalPageSkin[page]
  ?? system.defaultPageSkin[page]
  ?? page.builtInFallback

聊天主内容区背景 =
  currentUser.chatTheme
  ?? builtInChatThemeFallback
```

不变量：

- 登录页发生在认证前，不能直接读取服务端个人偏好；已登录用户保存的个人登录页皮肤只能通过本机缓存预览在登出页生效。
- 图片资源只表达文件事实；取景中心、背景放大和蒙层强度属于某个槽位对某张图的使用配置，取景保存为该槽位 config 的 `crops[imageId]`，蒙层保存为该槽位 config 的 `overlayOpacity`；`zoom` 范围为 `1..3`，`zoom=1` 表示 cover 后刚好铺满，蒙层强度范围为 `0..1`。
- 顶部栏、侧边栏和每个页面内容区都是独立槽位；同一张图片可被多个槽位引用，但每个槽位拥有自己的摆放参数和蒙层强度。
- 登录页、顶部栏、侧边栏和每个页面内容区必须使用同一个固定 frame 背景槽位渲染模型：frame 负责裁剪，`centerX`、`centerY` 和 `zoom` 只派生 frame 内的 cover-crop 取景，`zoom` 必须按 cover 基础上的 `1..3` 放大倍数生效，不能移动槽位本体导致跨槽位互相影响，也不能露出 fallback 底色。
- 页面内容区不把顶部栏或侧边栏皮肤当作业务背景事实源；普通页面内容区必须使用对应页面级皮肤槽位。
- 聊天主内容区不使用 `page_*_background` 槽位，不能在设置页保留不生效的聊天页面皮肤入口；它的背景由聊天主题唯一决定，顶部栏和侧边栏皮肤仍按各自槽位独立生效。
- 普通成员不能写系统背景、系统默认背景或系统背景资源库。
- 个人上传背景只属于当前用户，不进入系统资源库。
- 背景资源和偏好必须能区分 owner：`system` 或 `userId`。

## 4. 设置范围

个人设置只影响当前用户：

| 设置项 | 结论 |
|---|---|
| 账号信息展示 | 个人设置，只读。 |
| 默认进入页面 | 个人设置。 |
| 侧边栏偏好 | 个人设置。 |
| 通知展示偏好 | 个人设置。 |
| 工作区布局偏好 | 个人设置，只影响当前用户。 |
| 工作台缩放、界面字号、内容字号、界面密度、高对比度 | 个人设置。 |
| 登录页、顶部栏、侧边栏和普通页面级皮肤选择、模式、上传、拖动、缩放、蒙层强度 | 个人设置，受系统策略约束；聊天主内容区不参与普通页面级皮肤。 |
| 自助改名 | 未定，需要单独产品决策。 |
| 修改角色、权限、登录页背景 | 不是个人设置。 |

系统设置影响全站默认、策略或共享资源：

| 设置项 | 结论 |
|---|---|
| 登录页背景 | 系统设置。 |
| 系统默认登录页、顶部栏、侧边栏和页面级皮肤 | 系统设置。 |
| 系统背景资源库 | 系统设置。 |
| 个人背景上传策略 | 系统设置。 |
| 成员管理、权限管理、ORF 全局规则 | 系统管理；其中全局策略和默认值属于系统设置。 |

## 5. 权限不变量

- 前端显隐只处理入口体验，不是安全边界。
- 后端接口必须分别校验个人设置和系统设置权限。
- 个人设置写接口只能修改当前 session 用户自己的偏好和资源。
- 系统设置写接口必须要求 `admin`。
- 未登录用户只能读取登录页所需的系统公开资源。
- 已登录用户可以读取系统启用背景和自己的个人背景，不能读取其他用户的个人背景。
- 未登录用户不能读取服务端个人背景文件；登录页个人化只能来自本机缓存预览。

## 6. 当前实现与兼容

当前视觉设置属于系统设置，已按下表收敛：

| 当前概念 | 目标概念 |
|---|---|
| `/settings` 承载视觉设置 | 已改为 `/system/settings` 承载系统设置；旧 `/settings/system` 只做兼容跳转。 |
| 侧边栏用户区 `设置` 只对管理员可见 | 已改为个人设置入口对所有 `active` 用户可见。 |
| 字号、图标和控件大小只由页面局部 CSS 决定 | 已改为个人显示偏好驱动 AppShell 全局显示 token。 |
| 聊天目标/行动项侧栏打开状态只存在页面内 | 已改为 `workspaceLayout` 个人偏好保存布局状态；目标和行动项事实仍来自任务管理模型。 |
| `login_background` | 系统登录背景 + 当前用户个人登录页皮肤；未登录只读取系统默认或本机缓存。 |
| `topbar_background` | 顶部栏皮肤槽位。 |
| `sidebar_background` | 侧边栏皮肤槽位。 |
| `page_*_background` | 普通页面内容区皮肤槽位；设置时可把当前页面配置一次性应用到全部或部分页面，聊天主内容区除外。 |
| `app_background` | 旧 AppShell 单槽位兼容名，只能作为顶部栏/侧边栏旧资源和旧偏好的读取来源，不能继续定义页面内容区，也不能作为新的个人偏好写入口。 |
| `public/settings/user/*` 保存管理员上传背景 | 只作为旧系统路径兼容读取，不能作为普通用户个人设置路径。 |
| 普通成员不可见设置 | 普通成员不可见系统设置，但可见个人设置。 |

个人偏好和个人背景资源已写入 `public/settings/users/{userId}/...`，并由当前 session 用户作为 owner。后续扩展新的设置项时，必须继续同时更新前端路由、后端接口、测试用例和 issue 结论。
