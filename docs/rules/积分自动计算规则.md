# 积分自动计算规则

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

本文档记录积分自动计算的后端规则口径、字段和判定条件。

前端展示、交互和 UI 状态见 [积分自动计算规则 - 前端.md](../frontend/积分自动计算规则%20-%20前端.md)。

## 计分对象
积分按指标计算。
每个指标由管理员分配负责人并设定截止时间。
指标截止时间不得超过目标截止时间。
指标积分由不确定性分、指标定义分和完成系数组成。指标定义分奖励把目标拆成有效指标；指标被完成或有效证伪时，按不确定性分和完成系数结算。

## 时间规则
resultStartAt = 指标分配时间
resultDueAt = 指标截止时间
objectiveDueAt = 目标截止时间
orfReestimateDueAt = resultStartAt + (resultDueAt - resultStartAt) × 30%
resultDueAt ≤ objectiveDueAt

## 积分公式
definitionPoints = 2

resultPoints = uncertaintyScore × completionMultiplier

memberPoints = sum definitionPoints where result.definer = member and result.acceptedResult in (completed, falsified)
  + sum resultPoints where result.owner = member

## 不确定性分
| 等级 | 不确定性分 | 判断标准 |
| --- | ---: | --- |
| 入门 | 10 | 路径非常清楚，有现成方案可以参考。大部分指标的不确定性分默认为 10。 |
| 进阶 | 30 | 方向清楚，有成熟参考方案，不需要创造新方法。但复杂度明显更高。 |
| 破局 | 90 | 没有现成答案，需要定义新的判断标准、评估口径、业务规则或验证方法，并通过实际数据证明可行。 |
| 渡劫 | 270 | 关键假设本身不确定，可能推翻原目标；需要跨业务、数据、模型、产品多方验证，失败概率高。 |
| 飞升 | 810 | 需要形成行业级、平台级或方法论级突破，完成后显著改变现有能力边界。 |

## 指标定义分
指标定义分固定为 2 分。

指标定义分在正式指标完成或有效证伪后发放给指标定义人。

指标定义分不随不确定性等级变化，也不受完成系数、完成时间或后续执行人影响。

如果候选指标被合并后采纳，由管理员在采纳或验收时确认指标定义分归属；未进入正式指标，或正式指标最终未完成且未有效证伪，不产生指标定义分。

## 完成系数
| 结果 | 系数 | 判定 | 规则 |
| --- | ---: | --- | --- |
| 按时完成 | 100% | 自动 | acceptedResult = completed, acceptedAt ≤ resultDueAt |
| 延期完成 | 50% | 自动 | acceptedResult = completed, acceptedAt > resultDueAt |
| 按时指标证伪 | 100% | 管理员确认 |  |
| 延期指标证伪 | 50% | 管理员确认 |  |
| 重估阶段内目标推翻 | 100% | 管理员确认 |  |
| 主动放弃 | 0% | 管理员确认 |  |
| 超预期完成 | 150% | 管理员确认 |  |
