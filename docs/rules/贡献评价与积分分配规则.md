# 贡献评价与积分分配规则

## 口径

- 匿名互评只发生在目标层级。
- 参与成员身份来自 `Objective.challengerUserIds`，且只能是普通成员挑战者；`Objective.challengers` 只是显示名投影。
- 指标不绑定成员，也不直接决定个人贡献比例。
- 主管不参与普通互评，只处理分歧、异常和申诉。

## 总分

设目标包含 `m` 个已验收指标，难度分为 `w_1 ... w_m`：

$$
V = \sum_{k=1}^{m} w_k,\quad P = V \cdot a,\quad M_j = P \cdot c_j
$$

| 符号 | 含义 |
| --- | --- |
| `V` | 目标总分 |
| `a` | 完成系数 |
| `P` | 可分配积分 |
| `c_j` | 成员 `j` 的贡献比例 |
| `M_j` | 成员 `j` 的目标结算积分 |

`j` 只遍历目标中的普通成员挑战者，主管/管理员不进入分配集合。

## 触发

默认每个目标结算时做一次匿名互评。结算周期结束时，也可由管理员发起目标级结算。

目标结算前，不把单个指标积分绑定到成员。

## 输入

成员 `i` 提交对所有参与成员的贡献评价：

$$
0 \le x_{ij} \le 1,\quad \sum_{j=1}^{n} x_{ij} = 1
$$

`x_ii` 为自评，只用于核查，不直接计分。

页面输入使用百分比展示，范围为 `0` 到 `100`，同一份评价必须覆盖所有目标挑战者且合计为 `100%`。浏览器本地加密后提交到 ORF 同源代理，由 ORF 转发到共享匿名互评结算服务；结算服务和 ORF 结算接口使用标准比例，范围为 `0` 到 `1`，同一份评价必须合计为 `1`。

## 计算

单人参与：

$$
c_1 = 1
$$

两人参与：

$$
h_1 = x_{21},\quad h_2 = x_{12},\quad H = h_1 + h_2
$$

若 `H > 0` 且 `|H - 1| <= 0.10`：

$$
c_1 = \frac{h_1}{H},\quad c_2 = \frac{h_2}{H}
$$

否则触发主管核查。

三人及以上：

$$
q_j = \frac{\sum_{i \ne j} x_{ij}}{n - 1},\quad Q = \sum_{j=1}^{n} q_j
$$

$$
D = \max_j(\max_{i \ne j}(x_{ij}) - \min_{i \ne j}(x_{ij}))
$$

若 `Q > 0` 且 `D <= 0.10`：

$$
c_j = \frac{q_j}{Q}
$$

否则触发主管核查。

## 异常

以下情况触发主管核查：

- 评价缺失。
- 单份评价合计不为 100%。
- 成员申诉。
- 两人评价偏差超过 10 个百分点。
- 三人及以上最大他评差值超过 10 个百分点。
- 明显恶意压分或互相抬分。

主管可要求补评、剔除无效评价、修正异常评价后重算，或维持系统结果。

## 后端契约

| 数据 | 规则 |
| --- | --- |
| 共享结算服务 | 保存普通成员挑战者提交的加密互评，解密后按目标汇总标准比例 |
| ORF 后端 | 只认证、校验权限和代理 encrypted envelope；不解密、不保存新提交的匿名互评原始数据，结算时只接收汇总后的贡献比例和公开积分结果 |
| 汇总结果 | 单挑战者自动 `100%`；多挑战者由共享结算服务按最新互评记录汇总 |
| 重复提交 | 允许同一 reviewer 多次提交，共享结算服务保留历史；汇总和结算只读取该 reviewer 最新一条记录 |
| 缺评 | 不能自动结算，指挥官可处理后结算 |
| 分歧 | 任一成员收到的他评最大差值超过 `10%` 时进入分歧处理 |
| 指挥官处理 | 只在缺评、分歧、申诉等异常下提交处理后的贡献比例和说明 |
| 匿名边界 | 原始互评只在成员浏览器和共享结算服务明文出现；ORF 后端只处理加密 envelope 和公开结算比例，不进入读模型 |
| 积分可见性 | 核算后的 `pointLedger` 是公开积分事实源，可按季度、年度和全部时间查看 |
