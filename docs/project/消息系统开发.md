# 消息系统开发

## 定位

消息系统是 ORF 的系统级收件箱，用来承接会阻塞流程推进的业务事件。

它不属于悬赏大厅、我的挑战、反馈或成员管理中的任一页面；业务模块只产生领域事件，消息系统负责把事件投递给接收人并维护已读状态。

## 当前事件

| 事件 | 触发动作 | 接收人 | 跳转 |
| --- | --- | --- | --- |
| `challenge.application.created` | 成员申请挑战 | 当前作用域 active 指挥官 | `/tasks` |
| `objective.recruitment.created` | 指挥官征召成员 | 被征召 active 成员 | `/bounties` |
| `objective.loot.submitted` | 挑战者提交战利品 | 当前作用域 active 指挥官 | `/objectives/:objectiveId/loot` |

## 数据模型

消息持久化在 `notifications` 表：

| 字段 | 说明 |
| --- | --- |
| `team_id` | 默认作用域隔离 |
| `recipient_user_id` | 接收人 |
| `actor_user_id` / `actor_name` | 触发人 |
| `kind` | 事件类型 |
| `title` / `body` | 展示文案 |
| `target_type` / `target_id` / `target_href` | 关联对象和跳转位置 |
| `read_at` | 已读时间，空值表示未读 |
| `metadata` | 少量展示辅助数据，不承载业务真相 |

业务真相仍在原业务表里，例如 `Objective.challengeApplications`、`Objective.assignedChallengers`、`objectiveLoot`。消息不能反向驱动业务状态。

## 后端边界

| 文件 | 职责 |
| --- | --- |
| `server/repositories/notificationRepository.ts` | 消息创建、查询、已读状态 |
| `server/repositories/orfRepository.ts` | 在业务 mutation 成功后调用消息投递 |
| `server/app.ts` | `/api/notifications`、已读接口和当前用户作用域校验 |
| `server/db/schema.ts` / `drizzle/*` | `notifications` 表结构 |

接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/notifications` | 当前用户消息列表和未读数 |
| `PATCH /api/notifications/:notificationId/read` | 标记单条消息已读 |
| `PATCH /api/notifications/read-all` | 标记当前用户全部消息已读 |

所有读取和写入都按当前登录用户和默认作用域收敛。用户不能读取或标记别人的消息。

## 前端边界

| 文件 | 职责 |
| --- | --- |
| `src/components/NotificationBell.tsx` | 顶部栏铃铛、未读数、最近消息浮层 |
| `src/pages/NotificationsPage.tsx` | 完整消息页 |
| `src/state/OrfProvider.tsx` | 消息拉取、轮询、已读状态更新 |
| `src/config/navigation.ts` | 命令菜单可搜索消息页；不加入侧边栏分组 |

消息入口放在顶部栏，不作为侧边栏一级导航。侧边栏保留主要业务空间；消息是横切状态入口。

## 测试口径

- 后端流程测试必须验证关键业务动作会生成正确接收人的消息。
- API 测试必须验证消息按当前用户隔离，不能读取或标记别人的消息。
- `e2e/notifications/notification-center.spec.ts` 验证顶部栏铃铛、未读数、消息浮层、完整消息页和已读动作。
- 前端静态测试必须验证消息入口在顶部栏，不回到侧边栏主导航。
- 真实流程测试扩展时，应验证申请、征召和战利品提交后对应角色能看到未读消息并跳转到关联页面。
