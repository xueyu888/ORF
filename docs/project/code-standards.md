# ORF 代码规范

## 接口访问约定

前端数据统一通过同源 `/api` 请求后端接口，例如 `/api/tasks`。
前端不直接写死后端域名或端口，开发和生产环境由代理或网关转发到实际后端服务。

本文件只记录项目当前明确采用的代码原则。后续根据实际开发情况继续追加、修改或删除。

## 原则

1. **模块封装**: 业务模块优先用 `class` 包裹，保持模块边界清晰。问题应尽量限制在模块内部，不要让一个模块的问题扩散到其他模块。
4. **代码简洁**: 代码尽可能简洁，能少写就少写。
2. **层级分明**: 代码层级要清楚，模块之间不要互相污染。
6. **禁止硬编码**: 可变化的内容都应该可配置。
7. **配置即功能**: 功能差异应优先通过配置表达。

## 使用方式

业务代码变更时，应检查是否违反以上原则。新的代码规范只在确认有实际价值后再加入本文件。

## 测试约定

- 快速测试使用 Node 内置 test runner，通过 `npm test` 执行。
- 业务状态、权限、日期、排序、评论和数据来源优先写纯函数或状态层测试。
- Playwright 只覆盖关键用户旅程和跨层数据来源回归，通过 `npm run test:e2e` 执行。
- 完整验收使用 `npm run verify`，包含构建、快速测试和端到端测试。
