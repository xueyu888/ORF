# 原生聊天已读规则

## 事实源

- 聊天主消息已读位置事实源是 `chat_channel_members.last_read_at`、`last_read_message_id` 和 `manually_unread`；`last_viewed_at` 是该读状态最后一次变更的版本时间，不直接表示未读位置。
- 前端消息列表里的未读分隔线、跳转目标和观察计时只是展示状态或临时 UI 状态，不能替代服务端事实源。
- 话题回复未读事实源是 `chat_thread_follows.last_viewed_at`，不随主消息流自动已读一起清理。
- 话题内具名 `@用户` 或广播 `@所有人` 会在消息写入事务内为被提及者创建或恢复 `chat_thread_follows.following = true`；push 重试只重试系统外提醒，不重复改变关注事实，realtime 不持久化也不重试。
- 历史提及如果缺少 `chat_thread_follows` 行，服务端按“从未阅读的隐式关注”投影到未读计数、话题收件箱和跳转目标；只有用户打开话题或显式标记已读时才补齐游标，不做全局清零或静默迁移。
- 普通聊天消息不写入系统通知事件；聊天提醒只走聊天未读读模型、实时事件、推送和本地通知。
- 系统通知事件的已读事实源是 `notification_receipts.read_at`；聊天里的系统频道只是 `notification_deliveries.channel = 'chat'` 的投影。
- 系统频道作为聊天投影仍有自己的 `chat_channel_members` 已读游标，用于聊天侧栏未读和滚动定位；它不能反向定义通知事件是否存在。

## 主消息流规则

1. 用户进入会话时，如果存在主消息未读，消息流自动定位到第一条未读消息附近。
2. 用户进入会话时，如果不存在主消息未读，消息流自动滚动到最新消息。
3. 进入会话本身不等于已读，不能因为打开频道就把主消息已读游标推进到最新。
4. 主消息进入消息滚动区视口并稳定停留约 1 秒，才算被用户看到。
5. 已读游标按用户实际看到的位置逐步推进：如果 A-E 未读，用户看到并停留到 C 后切走，则 A-C 已读，D-E 继续未读。
6. 用户读到最后一条主消息未读并稳定停留后，该频道主消息未读清空。
7. 用户进入频道后新来的主消息不并入旧的阅读任务；它只在自己进入视口并稳定停留后才推进已读。
8. `read.changed` 只使 bootstrap 中的频道/话题已读投影失效，不得触发主消息窗口或已打开话题正文对账、未读重定位或滚动到最新；否则话题读取推进游标后会再次读取自身，形成反馈循环。用户滚动位置不能由已读状态反向定义。

## 话题回复边界

- 主消息流自动已读只处理 `root_message_id IS NULL` 的主消息。
- 主消息提及数、话题提及数和已关注话题未读数是三个独立派生量；总 `mentionCount` 只能由前两者相加，不能反向充当主消息流未读。
- 话题收件箱列表本身不推进游标；打开具体话题时，`chat_thread_follows.last_viewed_at` 只推进到本次实际返回给用户的最后一条消息时间，不能推进到服务器墙钟时间，以免把查询后并发到达、尚未展示的回复误标为已读。重复读取同一批消息时不得重写 `updated_at` 或再次广播 `read.changed`。
- 手动“全部标记已读”可以同时清理主消息和话题未读，但它是显式用户动作，不属于进入频道后的自动行为。
- “跳到未读”有明确目标类型：主消息目标加载主消息上下文；话题提及目标直接打开最早未读提及所在话题并聚焦具体回复。聚合角标不得再由前端猜测跳转目标。

## 前端职责

- `ChatPage` 只组合当前频道、消息流和右侧面板，不直接判断已读语义。
- `useChatFeedState` 管理当前主消息流的读取、滚动和已读推进。
- 主消息视口模式只有 `followingLatest` 和 `browsingHistory`：用户向上滚动、定位未读/搜索消息时进入历史阅读；用户主动回到严格底部时才恢复跟随最新。后台对账、已读回执、反应变化和内容尺寸变化不得改变用户视口模式。
- 用户滚动和程序滚动必须可区分；异步消息对账只能在提交结果时读取当前视口模式，不能沿用请求开始前的跟随判断。历史阅读窗口发生可见数据变化时，只恢复更新前的当前可见消息锚点。
- 可见性和停留时间判断应保持在独立模型中，输入为消息、当前未读锚点和滚动容器，输出为可以推进到的主消息。
- 频道读模型同时携带主消息位置游标、主读状态版本 `chat_channel_members.last_viewed_at` 和话题读状态版本 `threadReadAt`。用户“标记为未读”可以合法回退位置游标，因此实时事件新旧只能比较读状态版本，不能比较位置游标；断线恢复以重新拉取的服务端读模型对账。

## 后端职责

- `PATCH /api/chat/channels/:channelId/read` 支持两种模式：
  - 不传 `messageId`：显式标记当前频道主消息到最新；可选 `includeThreads` 清理话题未读。
  - 传 `messageId`：只把主消息已读游标推进到该消息，不推进到更新的消息，也不清理话题未读。
- 后端必须拒绝不存在、已删除、非当前频道或非主消息的 `messageId`。
- `GET /api/chat/channels/:channelId/unread-target` 按 `surface=main|threadMention` 返回具名目标；主消息返回消息上下文，话题提及返回 `rootMessageId` 和具体 `targetMessageId`。
- 兼容旧客户端的 `/unread-context` 在不存在主消息未读、但存在话题提及时返回对应根消息上下文，避免滚动发布期间继续出现 404；新客户端不依赖该回退来定位具体回复。
- `includeThreads` 除推进已有话题游标外，还会为当前频道历史上缺失游标的提及话题惰性创建关注行并推进到本次用户动作时间；已有的显式取消关注状态保持不变。
