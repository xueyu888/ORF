# 成果归属区间：实现与迁移核验

## 已确认契约

成果归属为包含首尾的纯日期区间，与验收和入账时间独立。结算事件是区间事实源，个人积分通过事件关联取得区间。统计采用自然周（周一至周日）、自然月、自然季度、自然年和自定义起止日期；完整包含才计入周期，相交跨界的成果单列、不分摊。全部汇总保留所有积分。

## 实现范围

- `src/domain/achievementPeriod.ts` 定义具名区间、日期合法性校验、计划周期建议及包含/相交关系。
- 结算 API 必填 `achievementPeriod`，与事件和个人账本原有事务共同写入。移除从验收日期推导归属及最终验收移动旧积分归属的路径。
- 管理员更正接口校验团队范围及预期旧区间，写 `settlement_period_corrections` 审计，不改变分数或原时间。
- 统计读模型从事件展开区间；排行榜、完成率和排名比较复用同一个区间过滤。缺失区间不退回验收或入账时间猜测。
- 结算表单显式选择起止日期；统计提供直接的周期选择，保留进入本轮之前已有的日期弹窗修改。结算日历只展示真实入账日期，不控制成果筛选。
- 已有 `tests/reportsLeaderboard.test.ts` 更新自然周期断言并增加跨界、未知归属、跨月补录验证。未改动 `testd` 或 `testd-doc`，未新增永久测试文件。

旧账本关联恢复工具：`scripts/restore-historical-settlement-links.mjs --manifest=<审核清单>`，同样默认只预览。核对明确的原流水快照、团队管理员、目标状态、月份、历史时间及金额，在事务中创建恢复记录、关联流水并写审计；只更新流水的事件外键，绝不插入积分或推进目标状态。重复执行验证既有恢复记录并跳过写入。工具没有常规结算入口，不作为跳过互评的业务接口。
