# 评论功能自动化实现计划

## 1. 目标

根据已确认的评论功能黑盒规格、测试用例和黑盒执行计划，把评论功能测试落到当前工程的可执行自动化方案中。

本计划可以读取当前工程，但不修改黑盒预期去迁就当前实现。

本计划不生成测试代码。

未来测试代码统一放到：

```text
tests/testing/comment/
```

不使用：

```text
tests/comment/
```

## 2. 当前工程可用入口

| 项目 | 当前工程事实 | 自动化用途 |
|---|---|---|
| 前端入口 | `/tasks` 是评论功能所在页面 | 浏览器自动化从登录后访问 `/tasks` 开始 |
| 未登录拦截 | 未登录访问受保护页面会跳转到 `/auth` | 覆盖未登录不能进入评论页面 |
| 登录页 | `/auth` 提供登录和注册表单 | 多用户测试可通过 UI 登录 / 注册 |
| 评论入口 | 行块菜单中有 `评论` 菜单项 | 自动化通过用户操作打开评论区 |
| 评论数量入口 | 有评论数量时显示评论数量按钮 | 自动化可用于回访已有评论 |
| 评论区 | 打开后显示目标上下文、空状态或评论列表 | 自动化断言页面可见结果 |
| 测试工具 | 已安装 `@playwright/test`，但当前没有 Playwright 配置和 npm 脚本 | 需要后续补充测试运行配置 |

## 3. 当前实现与黑盒规格的主要差距

| 缺口编号 | 黑盒规格 | 当前工程观察 | 影响用例 | 分类 |
|---|---|---|---|---|
| GAP-001 | 评论需要跨用户可见 | 当前评论没有后端评论接口和数据库持久化 | CMT-BB-019 | 实现缺口 |
| GAP-002 | 评论需要跨设备或浏览器可见 | 当前评论主要依赖浏览器本地状态 | CMT-BB-020 | 实现缺口 |
| GAP-003 | 评论最大长度为 500 字符 | 当前输入未看到 500 字符限制 | CMT-BB-023、CMT-BB-024 | 实现缺口 |
| GAP-004 | 保存失败时需要失败反馈和重试入口 | 当前评论提交没有外部保存请求链路和失败状态 | CMT-BB-029 | 实现缺口 |
| GAP-005 | 删除失败时需要反馈和状态一致 | 当前删除没有外部删除请求链路和失败状态 | CMT-BB-030 | 实现缺口 |
| GAP-006 | 评论权限跟随目标对象权限 | 当前评论入口和评论操作未看到独立权限拦截 | CMT-BB-017 | 实现缺口 |
| GAP-007 | 管理员可管理他人评论 | 当前评论操作没有区分自己和他人，也没有管理员专属规则 | CMT-BB-039、CMT-BB-040 | 实现缺口 |
| GAP-008 | 重复提交最多产生一条有效评论 | 当前提交后没有外部 loading / pending 防重状态 | CMT-BB-007 | 高风险，需自动化验证 |

这些差距不改变黑盒测试预期。自动化执行时应将对应失败记录为实现缺口。

## 4. 自动化技术方案

| 层级 | 方案 | 说明 |
|---|---|---|
| 浏览器黑盒测试 | Playwright | 模拟用户登录、进入 `/tasks`、点击评论入口、输入、提交、断言可见结果 |
| 手工补充 | 人工执行 | 首轮确认文案、回复关系、移动端视觉、失败反馈体验 |
| 多用户测试 | Playwright 多 browser context 或多账号手工 | 验证用户 A 创建后用户 B 可见 |
| 多设备 / 多浏览器测试 | Playwright 不同 context 或真实浏览器 | 验证跨环境可见 |
| 失败模拟 | 后续需有真实后端接口或可控代理 | 当前评论无外部保存接口，失败场景只能记录实现缺口 |

## 7. 定位策略

自动化测试应优先使用用户可感知定位：

- 页面路径：`/tasks`、`/auth`
- 文案：`评论`、`暂无评论`、`暂无回复`、`回复详情`
- 表单提示：`添加评论...`、`添加回复...`、`回复 {作者}...`、`编辑评论...`
- 按钮可访问名称：`打开块菜单`、`关闭评论窗口`、`回复评论`、`删除评论`、`编辑评论`、`发送评论`、`发送回复`、`保存评论`
- 评论正文文本和作者名
- 删除确认文案：`删除这条评论？`

避免把 CSS class、内部属性、内部对象 id 作为主要断言。必要时可作为辅助定位，但测试结论仍以用户可见结果为准。

## 9. 自动化执行分组

### 9.1 当前自动化执行范围

当前覆盖：

```text
CMT-BB-001 ~ CMT-BB-040
```

只要有用户可见入口、浏览器 context、权限模拟、离线模拟或会话失效模拟能把场景打出来，就纳入自动化执行。不能因为预计失败而排除。

### 9.2 需要真实环境复验

```text
CMT-BB-019
CMT-BB-020
CMT-BB-035
CMT-BB-039
CMT-BB-040
```

这些用例已在自动化中执行，但后续仍需要在真实账号、真实后端、真实权限和真实跨浏览器环境中复验。

### 9.3 预计直接失败并记录实现缺口

```text
CMT-BB-017
CMT-BB-019
CMT-BB-020
CMT-BB-024
CMT-BB-029
CMT-BB-030
CMT-BB-035
```

原因：

- 评论权限未跟随目标对象权限。
- 评论未落到后端共享数据。
- 没有 500 字符限制。
- 没有评论保存 / 删除失败状态和重试入口。
- 评论操作不重新校验登录状态。

## 10. 数据准备策略

| 数据需求 | 建议方式 | 说明 |
|---|---|---|
| 基础对象 | 使用现有演示数据 | 当前工程已有目标、悬赏、行动项、子行动项 |
| 无评论对象 | 每个测试开始使用隔离浏览器环境 | 避免前一用例污染 |
| 已有评论 | 测试内通过用户操作创建 | 保持黑盒路径 |
| 有回复评论 | 测试内先创建外层评论，再创建回复 | 保持黑盒路径 |
| 相似对象 A/B | 如果现有数据不足，需通过用户可见创建流程准备 | 不建议直接改内部状态 |
| 多用户 | 通过注册 / 登录流程准备账号 | 需要后端和认证服务稳定 |
| 长文本 | 测试代码常量生成 | 只作为用户输入 |

如果为了效率必须预置数据，应在测试报告中说明预置方式，并确保断言仍基于用户可见结果。

## 11. 运行方式建议

当前 `package.json` 已有：

```text
npm run dev
npm run server:dev
npm run build
npm test
```

当前没有专门的 Playwright 脚本。后续建议新增：

```text
npm run test:comment:blackbox
```

建议命令含义：

```text
playwright test tests/testing/comment/comment.blackbox.spec.ts
```

运行前置环境：

```text
1. 启动后端 API
2. 启动认证服务和数据库
3. 启动前端 dev server
4. 执行评论黑盒测试
```

## 12. 报告规则

自动化执行后输出：

```text
reports/testing/comment.test-report.md
```

报告必须包含：

- 执行命令。
- 环境状态。
- 覆盖用例。
- 通过用例。
- 失败用例。
- 未执行用例。
- 实现缺口。
- 规格不清项。
- 环境问题。
- 门禁结论。

失败分类使用：

```text
实现缺口 / 规格不清 / 测试代码问题 / 环境问题
```

## 13. 不允许事项

- 不把测试代码放到 `tests/comment/`。
- 不修改黑盒用例来适配当前实现。
- 不用内部函数调用结果代替页面可见断言。
- 不把当前本地保存能力解释为跨用户、跨设备持久化。
- 不把没有失败状态的实现解释为“失败场景不需要测”。
- 不把没有评论权限模型的实现解释为“评论不需要权限”。
