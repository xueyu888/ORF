# 评论功能黑盒规格

## 1. 功能目标

评论功能用于让用户围绕一个业务对象进行讨论、补充说明和处理反馈。

用户应能够：

- 在一个可评论对象上打开评论区。
- 查看该对象已有评论。
- 发表新的外层评论。
- 回复已有评论。
- 查看某条评论下的回复。
- 编辑自己发出的评论。
- 删除自己发出的评论。
- 在关闭、刷新或重新打开后继续看到已保存的评论。

本规格只定义用户期望和外部可观察行为，不以当前源码、内部函数、接口形态或存储方式作为依据。

## 2. 使用对象

| 使用对象 | 状态 / 权限 | 期望能力 |
|---|---|---|
| 已登录普通用户 | 对目标对象有评论权限 | 查看、发表、回复、编辑自己的评论、删除自己的评论 |
| 已登录管理员 | 对目标对象有管理权限 | 查看全部评论，必要时管理评论 |
| 未登录用户 | 无有效登录状态 | 不能发表、编辑、删除评论；是否可查看评论待确认 |
| 无权限用户 | 对目标对象无评论权限 | 不能发表、编辑、删除评论；是否可查看评论待确认 |

待确认：

- 未登录用户是否允许只读查看评论。（未登录用户应该无法进入到评论页面）
- 管理员是否允许编辑或删除他人评论。（允许）
- 评论权限是否跟随目标对象的查看、编辑权限。（跟随）

## 3. 功能范围

### 包含

- 打开和关闭评论区。
- 按目标对象隔离评论。
- 空状态展示。
- 外层评论列表。
- 回复列表或回复详情。
- 新增评论。
- 回复评论。
- 编辑评论。
- 删除评论。
- 删除前确认。
- 评论数量展示。
- 基础输入校验。
- 基础安全处理。
- 评论在用户预期的数据范围内保留。

### 不包含

- 点赞、表情反应。
- `@` 提及。
- 图片、文件、语音评论。
- 富文本编辑器。
- 评论搜索。
- 评论置顶。
- 评论审核流。
- 批量删除。
- 通知推送。
- 随机测试。

## 4. 可评论对象

| 对象 | 期望行为 |
|---|---|
| 目标 | 可以打开独立评论区，评论只属于该目标 |
| 悬赏 | 可以打开独立评论区，评论只属于该悬赏 |
| 行动项 | 可以打开独立评论区，评论只属于该行动项 |
| 子行动项 | 可以打开独立评论区，评论只属于该子行动项 |

同名、同标题或相似内容的对象也必须保持评论隔离。

## 5. 输入条件

| 输入 | 合法情况 | 非法 / 边界情况 | 期望处理 |
|---|---|---|---|
| 评论正文 | 非空文本 | 空字符串、纯空白 | 不提交，并保持用户可继续输入 |
| 评论正文 | 普通文本、多行文本、emoji | 超长文本 | 是否限制长度待确认；不得导致界面崩溃 |
| 评论正文 | 包含 URL 或标点 | script、HTML 片段 | 不执行危险内容，按安全文本处理 |
| 回复目标 | 已存在且可见的评论 | 目标已删除或不可见 | 不应提交到不存在的目标，用户应看到可恢复状态 |
| 编辑内容 | 非空文本 | 清空后提交 | 不应保存为空评论 |
| 删除操作 | 用户确认删除 | 用户取消删除 | 确认后删除；取消后不删除 |

待确认：

- 评论最大长度。（500字符）
- 是否允许只包含 emoji。（允许）
- URL 是否需要自动链接。（不需要）
- 是否允许编辑历史可见。(不可见)

## 6. 状态与外部条件

| 条件 | 可能情况 | 期望行为 |
|---|---|---|
| 用户状态 | 已登录 / 未登录 / 登录过期 | 未授权操作应被阻止，并给出可理解反馈 |
| 权限状态 | 可评论 / 只读 / 无权访问 | 操作入口和执行结果应符合权限 |
| 数据状态 | 无评论 / 有评论 / 有回复 | 正确展示空状态、评论列表、回复入口和回复列表 |
| 网络或保存结果 | 成功 / 失败 / 超时 | 成功后展示结果；失败后提示并保留必要输入 |
| 页面状态 | 打开 / 关闭 / 切换目标 / 刷新 | 不串评论；已保存评论应按规格保留 |
| 删除状态 | 删除外层评论 / 删除回复 | 删除结果应清楚，关联回复处理规则待确认 |

待确认：

- 删除外层评论时，回复是一起删除、保留为孤儿回复，还是阻止删除。（一起删除）
- 评论保存失败时是否需要重试按钮。（需要）
- 评论是否要求跨浏览器、跨设备、多人共享。（需要）

## 7. 成功行为

- 用户打开某个对象的评论区时，可以看到该对象标题或明确上下文。
- 没有评论时，显示明确空状态。
- 有评论时，显示评论作者、正文、时间和可执行操作。
- 用户输入合法评论并提交后，新评论出现在该对象评论区。
- 用户回复评论后，回复与被回复评论形成清晰关系。
- 用户进入回复查看区域后，可以看到外层评论和其下回复。
- 用户编辑评论后，评论正文更新为新内容。
- 用户删除评论并确认后，该评论不再展示。
- 用户取消删除后，评论保持不变。
- 评论数量与当前对象实际可见评论数量一致。
- 用户关闭并重新打开评论区后，已保存评论仍可见。

## 8. 失败行为

- 空评论、纯空白评论不能提交。
- 未授权用户不能成功发表、编辑或删除评论。
- 保存失败时，用户应知道失败，并能继续编辑或重试。
- 删除失败时，评论不应从用户视角永久消失。
- 切换评论对象时，不应把 A 对象的评论显示到 B 对象。
- 危险内容不应执行。
- 超长文本不应破坏页面布局或遮挡关键操作。

## 9. 安全与约束

- 评论正文中的脚本不得执行。
- 评论正文中的 HTML 不得以不安全方式插入页面。
- 用户不能通过前端输入伪造他人身份。
- 用户不能越权编辑或删除他人评论，除非管理员规则明确允许。
- 重复点击提交不应产生重复评论。
- 评论区不应泄露用户无权访问对象的评论。

## 10. 验收标准

开发门禁阶段必须满足：

- P0 黑盒用例全部通过。
- P1 黑盒用例通过，或标记为待确认规格并说明风险。
- 核心路径：打开评论区、发表评论、回复、编辑、删除、重新查看评论成立。
- 基础非法输入被阻止。
- 基础安全场景成立。
- 不根据当前实现降低黑盒预期。
