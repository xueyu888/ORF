# 评论功能黑盒执行计划

## 1. 执行目标

从用户可接触入口、用户操作和页面可见结果出发，验证评论功能是否满足已确认的黑盒规格和用例。

本计划不依赖源码、内部函数、内部状态或内部存储方式。

本计划不生成测试代码。

## 2. 黑盒观察原则

测试时只观察以下结果：

- 用户能否进入或不能进入评论相关页面。
- 用户能否打开或关闭评论区。
- 页面是否显示正确对象上下文。
- 页面是否显示空状态、评论列表、回复、评论数量。
- 用户操作后页面是否出现正确反馈。
- 评论是否出现、更新、消失、保持。
- 权限、失败、危险输入、长文本、小屏幕等场景是否给出用户可理解结果。

测试时不观察以下内容：

- 内部函数是否被调用。
- 内部状态变量如何变化。
- 内部接口路径。
- 内部存储方式。
- 内部组件结构。

## 3. 测试入口

| 入口 | 用户动作 | 期望 |
|---|---|---|
| 评论页面入口 | 用户登录后进入可评论对象所在页面 | 能看到可评论对象列表或详情 |
| 对象评论入口 | 用户在目标、悬赏、行动项或子行动项上触发评论入口 | 打开该对象评论区 |
| 评论数量入口 | 用户点击某对象的评论数量 | 打开该对象评论区，并显示对应评论 |
| 回复入口 | 用户在一条评论上触发回复 | 进入回复输入状态或回复区域 |
| 回复查看入口 | 用户打开某条评论的回复区域 | 显示该评论及其回复 |
| 编辑入口 | 用户触发自己评论的编辑操作 | 进入编辑状态，并可保存 |
| 删除入口 | 用户触发删除操作 | 出现删除确认 |

如果某个入口在当前产品中不存在，应在执行报告中记录为实现缺口或规格不一致，不修改黑盒预期。

## 4. 测试环境

| 环境项 | 要求 | 用途 |
|---|---|---|
| 普通用户 A | 已登录，对测试对象有评论权限 | 核心新增、回复、编辑、删除 |
| 普通用户 B | 已登录，对同一测试对象有查看权限 | 跨用户可见 |
| 无权限用户 C | 已登录，但对某对象无评论权限 | 权限限制 |
| 管理员用户 | 已登录，有管理权限 | 管理他人评论 |
| 未登录访问 | 无有效登录状态 | 未登录不能进入评论页面 |
| 浏览器或设备 A | 用户 A 的一个使用环境 | 创建评论 |
| 浏览器或设备 B | 同一用户的另一个使用环境 | 跨设备或跨浏览器验证 |
| 小屏幕环境 | 手机宽度或窄窗口 | 移动端可操作性 |
| 失败模拟环境 | 可制造保存失败、删除失败、超时 | 失败恢复和重试 |

## 5. 测试数据

| 数据 | 要求 | 覆盖用例 |
|---|---|---|
| 无评论对象 | 目标、悬赏、行动项、子行动项至少各一个可评论对象 | CMT-BB-001 |
| 有评论对象 | 至少一条外层评论 | CMT-BB-002 |
| 相似对象 A/B | 标题相同或相似，均可评论 | CMT-BB-003 |
| 有回复对象 | 一条评论下至少一条回复 | CMT-BB-009 |
| 普通文本 | 非空短文本 | CMT-BB-004 |
| 空输入 | 不输入任何内容 | CMT-BB-005 |
| 纯空白输入 | 空格、换行、制表符 | CMT-BB-006 |
| 多行文本 | 至少两行正文 | CMT-BB-021 |
| emoji 文本 | 只包含 emoji，以及 emoji 与文字混排 | CMT-BB-022 |
| 500 字符文本 | 正好 500 字符 | CMT-BB-023 |
| 501 字符文本 | 超过上限 | CMT-BB-024 |
| URL 文本 | 包含 `https://example.com` 等 URL | CMT-BB-025 |
| 危险文本 | script 或 HTML 片段 | CMT-BB-015 |
| 长标题对象 | 标题明显超过普通长度 | CMT-BB-033 |

## 6. P0 手工执行步骤

| 用例 | 执行方式 | 用户步骤 | 可见通过标准 |
|---|---|---|---|
| CMT-BB-001 | 手工 / 浏览器自动化 | 登录用户打开无评论对象的评论区 | 看到对象上下文、空状态、输入入口 |
| CMT-BB-002 | 手工 / 浏览器自动化 | 登录用户打开已有评论对象的评论区 | 看到作者、正文、时间、操作入口 |
| CMT-BB-003 | 手工 / 浏览器自动化 | 先打开 A 查看评论，再打开相似对象 B | B 不显示 A 的评论 |
| CMT-BB-004 | 手工 / 浏览器自动化 | 输入合法评论并提交 | 新评论出现在当前对象评论区 |
| CMT-BB-005 | 手工 / 浏览器自动化 | 空输入直接提交 | 不新增评论，仍可继续输入 |
| CMT-BB-006 | 手工 / 浏览器自动化 | 输入空格或换行后提交 | 不新增评论，仍可继续输入 |
| CMT-BB-007 | 手工 / 浏览器自动化 | 输入合法评论后快速重复提交 | 最多出现一条有效评论，页面不崩溃 |
| CMT-BB-008 | 手工 / 浏览器自动化 | 对一条评论输入回复并提交 | 回复成功，能从被回复评论处看到回复 |
| CMT-BB-009 | 手工 / 浏览器自动化 | 打开一条评论的回复区域 | 看到外层评论和其下回复，关系清晰 |
| CMT-BB-010 | 手工 / 浏览器自动化 | 编辑自己的评论并保存 | 目标评论变成新正文，其他评论不变 |
| CMT-BB-011 | 手工 / 浏览器自动化 | 编辑时清空正文并保存 | 评论不变为空白，仍可继续编辑 |
| CMT-BB-012 | 手工 / 浏览器自动化 | 点击删除自己的评论 | 出现删除确认 |
| CMT-BB-013 | 手工 / 浏览器自动化 | 在删除确认中确认 | 评论不再展示，数量变化 |
| CMT-BB-014 | 手工 / 浏览器自动化 | 在删除确认中取消 | 评论仍然可见，数量不变 |
| CMT-BB-015 | 手工 / 浏览器自动化 | 输入危险文本并提交 | 危险内容不执行，页面不异常 |
| CMT-BB-016 | 手工 / 浏览器自动化 | 未登录访问评论页面或评论入口 | 无法进入评论页面，看到登录或未登录反馈 |
| CMT-BB-017 | 手工 / 浏览器自动化 | 无权限用户尝试查看、发表、编辑或删除 | 操作不成功，不产生评论变化，看到权限反馈 |
| CMT-BB-018 | 手工 / 浏览器自动化 | 发表评论后刷新或重新打开同一对象 | 已保存评论仍可见 |
| CMT-BB-019 | 多用户环境 | 用户 A 评论后，用户 B 打开同一对象 | 用户 B 能看到用户 A 的评论 |
| CMT-BB-020 | 多设备 / 多浏览器环境 | 用户在环境 A 评论后，在环境 B 打开同一对象 | 已保存评论仍可见 |

## 7. P1 手工执行步骤

| 用例 | 执行方式 | 用户步骤 | 可见通过标准 |
|---|---|---|---|
| CMT-BB-021 | 手工 / 浏览器自动化 | 输入多行评论并提交 | 多行内容可读展示，评论区不破坏 |
| CMT-BB-022 | 手工 / 浏览器自动化 | 输入只包含 emoji 的正文并提交 | 评论成功保存和展示，无乱码 |
| CMT-BB-023 | 手工 / 浏览器自动化 | 输入正好 500 字符并提交 | 评论提交成功 |
| CMT-BB-024 | 手工 / 浏览器自动化 | 输入 501 字符或更长正文并提交 | 不新增评论，看到长度超限反馈 |
| CMT-BB-025 | 手工 / 浏览器自动化 | 输入包含 URL 的正文并提交 | URL 作为普通文本展示，不自动链接 |
| CMT-BB-026 | 手工 / 浏览器自动化 | 分别回复多条评论 | 每条回复出现在正确评论下 |
| CMT-BB-027 | 手工 / 浏览器自动化 | 回复某条回复 | 用户能看出回复对象 |
| CMT-BB-028 | 手工 / 浏览器自动化 | 删除有回复的外层评论并确认 | 外层评论和其下回复一起删除 |
| CMT-BB-029 | 失败模拟环境 | 保存失败或超时时提交评论 | 看到失败反馈，输入可恢复，有重试入口 |
| CMT-BB-030 | 失败模拟环境 | 删除失败或超时时确认删除 | 看到失败反馈，数据状态不误导用户 |
| CMT-BB-031 | 手工 / 浏览器自动化 | 在 A 输入未提交草稿后切换到 B | B 不显示 A 的已保存评论，草稿不误提交到 B |
| CMT-BB-032 | 手工 / 浏览器自动化 | 小屏幕打开评论区并执行核心操作 | 不明显溢出，关键操作可点击 |
| CMT-BB-033 | 手工 / 浏览器自动化 | 打开长标题对象评论区 | 能识别上下文，关键操作不遮挡 |
| CMT-BB-034 | 手工 / 浏览器自动化 | 查看带评论和回复的对象评论数量 | 数量与规格定义一致 |
| CMT-BB-035 | 登录状态模拟环境 | 打开评论区后登录过期，再尝试操作 | 操作失败，有登录状态反馈，输入不无故丢弃 |
| CMT-BB-036 | 手工 / 浏览器自动化 | 编辑评论后再次查看该评论 | 只看到当前正文，没有编辑历史入口或历史版本 |

## 8. P2 执行步骤

| 用例 | 执行方式 | 用户步骤 | 可见通过标准 |
|---|---|---|---|
| CMT-BB-037 | 手工 / 浏览器自动化 | 输入合法正文后使用键盘快捷方式提交 | 评论按规格提交 |

## 9. 执行方式分类

### 适合手工测试

- 规格首次确认。
- UI 文案是否符合预期。
- 删除确认是否容易理解。
- 回复关系是否清晰。
- 长标题、长正文、小屏幕是否影响使用。
- 失败反馈和重试入口是否符合体验预期。

### 适合浏览器自动化

- 打开评论区。
- 空状态和已有评论展示。
- 新增、回复、编辑、删除。
- 空输入、空白输入、500 字符、501 字符。
- script / HTML 不执行。
- 评论对象隔离。
- 刷新或重新打开后评论保留。
- URL 不自动链接。
- 编辑历史不可见。
- 键盘提交。

### 需要多用户 / 多设备环境

- 用户 A 评论后用户 B 可见。
- 同一用户在不同浏览器或设备可见。
- 无权限用户不能查看或操作。
- 管理员编辑或删除他人评论。

### 需要失败模拟环境

- 保存失败。
- 保存超时。
- 删除失败。
- 删除超时。
- 登录过期。

## 10. 执行记录要求

每次执行需要记录：

- 执行人。
- 执行时间。
- 测试环境。
- 用户角色。
- 使用设备或浏览器。
- 覆盖用例编号。
- 通过、失败、跳过、阻塞。
- 失败截图或录屏。
- 失败时的用户可见表现。
- 初步分类：规格不清、实现缺口、测试环境问题、测试步骤问题。

## 11. 门禁判定

开发门禁要求：

- P0 用例 `CMT-BB-001` 到 `CMT-BB-020` 全部通过。
- P1 用例 `CMT-BB-021` 到 `CMT-BB-036` 通过，或失败项明确记录为风险。
- 不能因为当前实现缺失而修改黑盒预期。
- 如果无法准备多用户、多设备或失败模拟环境，需要在报告中标记为未覆盖风险。

可用结论：

```text
允许推送
不允许推送
需要补充测试
需要澄清规格
```

## 12. 输出报告

执行后输出：

```text
reports/testing/comment.test-report.md
```

报告至少包含：

- 执行范围。
- 环境说明。
- 通过用例。
- 失败用例。
- 未执行用例。
- 实现缺口。
- 剩余风险。
- 门禁结论。
