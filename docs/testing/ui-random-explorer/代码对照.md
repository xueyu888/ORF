# UI 随机探索测试工程代码对照

这套测试工程位于：

```text
e2e/
scripts/run-ui-explorer-parallel.ts
tests/*explorer*.test.ts
```

它的职责是做通用 UI 随机探索，不替代业务 E2E。业务 E2E 证明某条业务链路正确；UI 随机探索寻找页面状态、状态转移、异常、路径逃逸和未探索前沿。

## 入口层

```text
e2e/ui-random-explorer.spec.ts
```

职责：

```text
读取配置
安装测试场景
运行 explorer
写 result.json 和 report.html
附加写 repeatable-regions.json 和 repeatable-regions.html
用 severeFailureCount 判断测试是否失败
```

它不生成事件、不判断状态、不写报告细节，只负责把测试工程串起来。

## 场景层

```text
e2e/_explorer/authenticatedAppScenario.ts
```

职责：

```text
拦截 /api/**
模拟已登录会话
返回受控业务数据
维护评论等测试内存态
```

这里的“假后端”不是无状态 mock。评论接口会在 Playwright Node 进程里维护 `comments` 内存变量，前端提交评论后收到 `commentThread`，再进入 React 状态并显示到 DOM。

## 安全边界层

```text
e2e/_explorer/safetyBoundaryConfig.ts
e2e/_explorer/safety.ts
```

职责：

```text
定义测试类型
定义目标入口
定义步数预算
定义时间预算
定义允许路径
定义禁止路径
定义禁止操作
定义禁止点击的目标文本
```

默认测试类型是：

```text
stateExploration
```

默认安全场景是：

```text
authenticatedApp
```

默认入口是：

```text
/tasks
```

## 目标采集层

```text
e2e/_explorer/targetCollector.ts
```

职责：

```text
扫描当前页面可交互 DOM
抽象成 UiTarget
生成目标签名
按组件 selector 限定采集范围
```

目标签名按：

```text
routePattern + DOM 目标特征
```

形成。`/tasks` 的设置按钮和 `/bounties` 的设置按钮即使外观相同，也会被算作不同目标，因为它们是两条不同路径入口。

## 事件模型层

```text
e2e/_explorer/eventGenerator.ts
e2e/_explorer/eventExecutor.ts
e2e/_explorer/eventIdentity.ts
e2e/_explorer/payloads.ts
```

职责：

```text
Target -> Candidate Event
Event -> Playwright 操作
Event -> 规范化事件签名
payloadKind -> 实际输入文本
```

事件只表达通用 UI 行为：

```text
click
doubleClick
hover
focus
insertText
clear
pressKey
modifiedKey
selectOption
wheel
backgroundClick
refresh
back
wait
repeatedClick
```

事件层不出现 `submitComment`、`login`、`approveTask` 这类业务动作。

## 状态抽象层

```text
e2e/_explorer/stateNormalizer.ts
e2e/_explorer/stateAbstractorRegistry.ts
e2e/_explorer/repeatableRegionDetector.ts
e2e/_explorer/stableHash.ts
```

职责：

```text
浏览器端采集 DOM snapshot
Node 端识别可重复增长区域
Node 端选择状态抽象策略
稳定序列化状态抽象
生成状态 ID
```

`stateExploration` 不把每个可重复区域条目直接放入状态 ID。它先把可重复区域汇总成评论存在性、业务标签集合和 ORF 层级集合；普通列表和布局重复只记录到 `repeatableRegions`，供第二阶段局部测试使用。

状态 ID 来自：

```text
StateDomSnapshot
  -> StateAbstractor
  -> StateAbstraction
  -> stableStringify
  -> sha256 前 12 位
  -> S-xxxxxxxxxxxx
```

默认抽象器是：

```text
stateExploration
```

它用于第一类测试：状态探索测试。

## 覆盖图层

```text
e2e/_explorer/coverageGraph.ts
```

职责：

```text
记录状态节点
记录状态转移
记录每个状态里的候选事件
记录目标覆盖
记录 payload 覆盖
计算覆盖摘要
给调度器提供历史反馈
```

这里的状态内候选覆盖按：

```text
stateId -> eventSignature
```

统计。规范化候选覆盖按：

```text
operation + 组件结构 + 参数类别
```

跨状态合并同类事件。

## 调度层

```text
e2e/_explorer/eventScheduler.ts
e2e/_explorer/seededRandom.ts
```

职责：

```text
根据历史覆盖给候选事件加权
优先尝试未测事件
提高未覆盖 target / payload 的权重
降低连续无变化和路径逃逸事件的权重
保证 seed 下可复现
```

它不理解业务，只看探索收益。

## 运行层

```text
e2e/_explorer/explorerRunner.ts
e2e/_explorer/repeatableRegionRunner.ts
e2e/_explorer/runnerSupport.ts
e2e/_explorer/screenshotCollector.ts
```

职责：

```text
进入目标页
循环采集状态
采集目标
生成候选事件
调度一个事件
执行事件
采集 after 状态
首次发现状态时保存状态截图
发生异常时保存异常截图
写入覆盖图
必要时 reset
达到最大步数或最大时间后结束主流程
主流程结束后自动触发可重复组件局部测试
共享页面 reset、诊断监听、replay command 转义等运行支撑能力
```

`explorerRunner.ts` 连接全局状态探索各层，但不拥有状态抽象、目标采集、事件生成、报告格式这些细节。

`repeatableRegionRunner.ts` 只处理第二类测试：

```text
从 stateTable 收集可重复区域
按组件作用域和业务上下文去重
根据 transitionTable 和 candidates 还原代表状态
只采集组件 selector 内部目标
只执行组件内部 target 事件
事件导致离开组件时恢复代表状态
```

它不参与全局状态图构建，避免把局部组件验证和整站状态探索混成一个职责。

## 报告层

```text
e2e/_explorer/reporter.ts
```

职责：

```text
写 result.json
写 report.html
写 repeatable-regions.json
写 repeatable-regions.html
归档 screenshots/states 和 screenshots/issues
合并并行 worker 结果
渲染按起点和聚合方向边展示的状态图
按 eventSequence 渲染探索路径回放
把异常卡片定位到状态图中的对应回放步骤
把被测对象放在报告顶部，把安全边界和状态抽象等测试环境放在报告后部
渲染覆盖指标
列出经过业务语义过滤的可重复增长区域
列出可重复组件局部测试对象和事件样本
输出 replay command
```

报告中的“可重复区域”来自 `repeatableRegionDetector.ts`。检测器会过滤 topbar、sidebar、surface、space-y、通用 card/container 等布局容器；第一类报告展示剩余区域在全局状态探索中的位置，并显示组件名和父组件名；第二类报告展示这些区域内部执行了哪些组件作用域事件。

## 并行层

```text
scripts/run-ui-explorer-parallel.ts
```

职责：

```text
启动 Vite
启动多个 Playwright worker
收集每个 worker 的 result.json
合并为一个总报告
```

并行 worker 使用不同 seed 后缀，最后由 reporter 重新合并状态、转移和覆盖指标。
