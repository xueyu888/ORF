# ORF Flow 界面设计总览

本文档作为界面设计入口和全局视觉规范。具体页面的字段、流程、权限和交互细节由对应页面文档维护。

页面级规则必须写在对应页面文档中。已有页面文档时，以页面文档为准；本文件只保留链接和跨页面通用规则。

## 1. 文档关系

| 文档 | 作用 |
| --- | --- |
| [产品界面设计文档](product/orf-flow-ui-design.md) | ORF Flow 整体页面结构、路由、跳转关系和页面目标。 |
| [前端原型产品规格](product/orf-flow-frontend-prototype.md) | 产品定位、对象关系、功能范围、技术要求和验收标准。 |
| [ORF 任务管理页面](ORF%20任务管理页面.md) | `/tasks` 任务管理页的详细布局、字段、流程状态、权限和视觉规则。 |
| [设计原则](设计原则.md) | 更高层的产品和交互原则。 |

维护规则：

1. 涉及单个页面的结构、字段顺序、折叠规则、流程状态、权限规则，写到对应页面文档。
2. 涉及全局主题、设计变量、侧边栏、顶栏、通用卡片和状态样式，写到本文档。
3. 一个规则只能有一个主文档。其他文档需要使用链接引用，不重复粘贴。
4. 新增页面时，如果页面规则超过 1 屏，应新增独立页面文档，并在本文件登记。

## 3. 全局设计变量

所有页面和组件共用同一套基础设计变量。变量源文件是 `src/config/designTokens.ts`，运行时通过 `applyDesignTokens()` 注入到 `:root` 的 CSS 变量中，CSS 默认值同步维护在 `src/styles.css`。

以后调整基础样式时，优先改 `src/config/designTokens.ts`，不要在页面组件里继续新增零散的硬编码尺寸或颜色。

| 用途 | 配置项 | CSS 变量 | 当前值 |
| --- | --- | --- | --- |
| 页面背景 | `color.appBg` | `--orf-bg-app` | `#f7f7f5` |
| 页面/卡片背景 | `color.pageBg` / `color.cardBg` | `--orf-bg-page` / `--orf-bg-card` | `#ffffff` |
| 边框颜色 | `color.border` | `--orf-border` | `#d5d5d2` |
| 强边框颜色 | `color.borderStrong` | `--orf-border-strong` | `#c9c9c5` |
| 卡片圆角 | `radius.card` | `--orf-radius-card` | `8px` |
| 控件圆角 | `radius.control` | `--orf-radius-control` | `6px` |
| 状态标签圆角 | `radius.statusTag` | `--orf-radius-status-tag` | `999px` |
| 卡片内边距 | `space.cardPadding` | `--orf-card-padding` | `16px` |
| 页面横向边距 | `space.pagePaddingX` | `--orf-page-padding-x` | `28px` |
| 页面纵向边距 | `space.pagePaddingY` | `--orf-page-padding-y` | `24px` |
| 行高 | `size.rowHeight` | `--orf-row-height` | `48px` |
| 树形缩进 | `size.treeIndent` | `--orf-tree-indent` | `28px` |
| 顶栏高度 | `size.topbarHeight` | `--orf-topbar-height` | `76px` |
| 侧边栏宽度 | `size.sidebarWidth` | `--orf-sidebar-width` | `280px` |
| 侧边栏品牌/工作区高度 | `size.sidebarHeaderHeight` | `--orf-sidebar-header-height` | `108px` |

使用规则：

1. 卡片使用统一卡片样式，圆角和边框由设计变量控制。
2. 卡片内容内边距使用 `.orf-card-padding`。
3. 状态、分类、周期等胶囊标签使用 `.orf-status-tag`。
4. 表格和树形行的最小高度使用 `--orf-row-height`。
5. 任务树的层级缩进和连线使用 `--orf-tree-indent` / `--orf-tree-line`。
6. 顶栏、侧边栏、任务流程组件的尺寸和颜色都要从设计变量派生。

## 5. 全局侧边栏规范

侧边栏参考 tability / Squarepoint 风格，整体使用青绿色系，不使用黑紫色侧栏。

侧边栏配色：

| 用途 | 颜色要求 |
| --- | --- |
| 主背景 | 深青绿色，接近 `#075856` / `#085f5e` |
| 顶部品牌区背景 | 更深青绿色，接近 `#064f4f` |
| 当前工作区高亮背景 | 偏亮青绿色块，接近 `#2a6f6d` |
| 当前选中菜单项背景 | 深青绿色高亮，接近 `#064b4b` |
| 分割线 | 比背景略深的青绿色线，接近 `rgba(0, 0, 0, 0.18)` |
| 图标颜色 | 浅青色，接近 `#74d2d6` |
| 主要文字 | 白色或接近白色，接近 `#f4fbfb` |
| 次级文字和分组标题 | 浅青灰，接近 `#b7d8d8` |

侧边栏布局：

1. 宽侧栏宽度约 `280px`，窄图标侧栏宽度约 `88px`。
2. 顶部是品牌区：左侧深色小方形 logo + 产品名，右侧设置图标。
3. 品牌区下面是工作区 / 组织入口，高度比普通菜单项更高，使用较亮青绿色背景。
4. 菜单按分组展示，分组标题使用全大写小字和较大字距，例如 `WORK`、`REPORTS`、`ORG`。
5. 菜单项为整行点击区域，左侧图标，右侧文字；图标颜色比正文更亮。
6. 当前选中菜单项使用深色块高亮，左侧不需要额外竖线。
7. 菜单项和分组之间使用 `1px` 分割线，不使用卡片阴影。
8. 窄侧栏模式只保留居中的图标按钮，背景和高亮色沿用同一套青绿色规范。

## 6. 页面规则拆分要求

当某个页面出现以下任一情况时，需要拆独立页面文档：

1. 页面包含独立业务流程，例如 `/tasks` 的 ORF 流程状态。
2. 页面字段顺序会影响实现和验收。
3. 页面有独立权限、折叠、筛选或状态机规则。
4. 页面参考图、参考组件或视觉要求较多。
5. 页面规则开始和本文档的全局规范混在一起，导致维护困难。

独立页面文档创建后，需要在“页面文档索引”中登记。本文档只保留页面文档链接和跨页面通用规则。
