# 结构化测试代码生成约束

## 1. 目标

本文档用于约束测试用例最终生成的测试代码。

核心目标是让测试代码严格遵循统一状态模型：

```text
B -> Setup -> S0 -> Action -> S1 -> Clean -> B
```

测试用例本身只声明状态和动作，不手写执行流程。

执行流程由通用执行器统一控制。

---

## 2. 核心原则

测试代码必须显式区分两类内容：

```text
状态：B、S0、S1
动作：Setup、Action、Clean
```

其中：

- B：测试开始前和 Clean 后都必须满足的基准状态。
- Setup：把 B 构造成 S0。
- S0：Action 发生前必须满足的状态。
- Action：本用例真正要验证的业务动作。
- S1：Action 发生后系统进入的目标状态。
- Clean：清理本次测试影响，使系统回到 B。

状态和动作不能混在一起。

---

## 3. 生成代码必须使用通用执行器

测试流程不能直接写在 `.spec.ts` 中。

不推荐：

```ts
await B(ctx);

const setupState = await setup(ctx);
await S0(ctx, setupState);

const actionResult = await action(ctx, setupState);
await S1(ctx, setupState, actionResult);

await clean(ctx, setupState);
await B(ctx);
```

必须改为：

```ts
await runStateCase(loginSuccessCase, ctx);
```

执行顺序由 `runStateCase` 固定。

---

## 4. 推荐目录结构

```text
e2e/
├── _framework/
│   ├── state-case.types.ts
│   └── state-case.runner.ts
│
└── auth/
    └── login/
        ├── login.spec.ts
        ├── login.case.ts
        ├── login.states.ts
        ├── login.actions.ts
        ├── login.context.ts
        └── login.helpers.ts
```

## 5. 通用类型

`state-case.types.ts`：

```ts
export type StateCase<TContext, TSetupState, TActionResult> = {
  id: string;
  title: string;

  B: (ctx: TContext) => Promise<void>;

  setup: (ctx: TContext) => Promise<TSetupState>;

  S0: (ctx: TContext, setupState: TSetupState) => Promise<void>;

  action: (
    ctx: TContext,
    setupState: TSetupState,
  ) => Promise<TActionResult>;

  S1: (
    ctx: TContext,
    setupState: TSetupState,
    actionResult: TActionResult,
  ) => Promise<void>;

  clean: (
    ctx: TContext,
    setupState: TSetupState,
  ) => Promise<void>;
};
```

---

## 6. 通用执行器

`state-case.runner.ts`：

```ts
import type { StateCase } from "./state-case.types";

export async function runStateCase<TContext, TSetupState, TActionResult>(
  testCase: StateCase<TContext, TSetupState, TActionResult>,
  ctx: TContext,
) {
  let setupState: TSetupState | null = null;

  await testCase.B(ctx);

  try {
    setupState = await testCase.setup(ctx);

    await testCase.S0(ctx, setupState);

    const actionResult = await testCase.action(ctx, setupState);

    await testCase.S1(ctx, setupState, actionResult);
  } finally {
    if (setupState) {
      await testCase.clean(ctx, setupState);
    }

    await testCase.B(ctx);
  }
}
```

## 7. 用例声明文件

`login.case.ts` 只声明用例结构。

```ts
import type { StateCase } from "../../_framework/state-case.types";
import { action, clean, setup } from "./login.actions";
import { B, S0, S1 } from "./login.states";
import type {
  ActionResult,
  SetupState,
  TestContext,
} from "./login.context";

export const loginSuccessCase: StateCase<
  TestContext,
  SetupState,
  ActionResult
> = {
  id: "auth.login.success",
  title: "普通成员可以使用正确邮箱和密码登录 ORF",

  B,
  setup,
  S0,
  action,
  S1,
  clean,
};
```

---

## 8. 测试入口文件

`login.spec.ts` 只作为 Playwright 测试入口。

```ts
import { test } from "@playwright/test";
import { runStateCase } from "../../_framework/state-case.runner";
import { loginSuccessCase } from "./login.case";
import { closeLoginTestDb } from "./login.helpers";
import type { TestContext } from "./login.context";

test.describe("登录测试用例", () => {
  test.afterAll(async () => {
    await closeLoginTestDb();
  });

  test(loginSuccessCase.title, async ({ context, page }) => {
    const ctx: TestContext = { context, page };

    await runStateCase(loginSuccessCase, ctx);
  });
});
```

`.spec.ts` 中不得直接调用：

```text
B
setup
S0
action
S1
clean
```

---

## 9. 状态文件

`login.states.ts` 只放状态断言。

推荐命名：

```ts
export async function B(ctx: TestContext) {}

export async function S0(
  ctx: TestContext,
  setupState: SetupState,
) {}

export async function S1(
  ctx: TestContext,
  setupState: SetupState,
  actionResult: ActionResult,
) {}
```

状态函数只确认状态成立，不负责制造状态。

---

## 10. 动作文件

`login.actions.ts` 只放状态迁移动作。

推荐命名：

```ts
export async function setup(
  ctx: TestContext,
): Promise<SetupState> {}

export async function action(
  ctx: TestContext,
  setupState: SetupState,
): Promise<ActionResult> {}

export async function clean(
  ctx: TestContext,
  setupState: SetupState,
): Promise<void> {}
```

动作函数负责改变状态，不负责核心状态断言。

---

## 11. 上下文文件

`login.context.ts` 放共享常量和类型。

例如：

```text
TEST_EMAIL
TEST_PASSWORD
TEST_USER_ID
TEST_TEAM_ID
TestContext
SetupState
ActionResult
```

测试数据、状态类型、动作结果类型不得散落在多个文件中。

---

## 12. Helper 文件

`login.helpers.ts` 放底层实现。

例如：

```text
数据库操作
API 请求
cookie 查询
storage 查询
session 查询
health check
关闭数据库连接
```

helper 中不表达测试流程。

---

## 13. 生成代码约束

生成代码时必须满足：

```text
1. 必须有 state-case.types.ts
2. 必须有 state-case.runner.ts
3. 每个用例必须有 xxx.case.ts
4. xxx.case.ts 必须声明 StateCase
5. xxx.spec.ts 只能调用 runStateCase
6. B、S0、S1 必须放在 states.ts
7. setup、action、clean 必须放在 actions.ts
8. SetupState、ActionResult 必须放在 context.ts
9. 底层 DB / API / cookie / storage 操作必须放在 helpers.ts
10. Clean 必须由 runner 在 finally 中执行
11. Clean 后必须重新执行 B
```

---

## 14. 最终结构

```text
case.ts
声明测试用例由哪些状态和动作组成。

spec.ts
接入 Playwright，只调用 runStateCase。

runner.ts
固定执行 B -> Setup -> S0 -> Action -> S1 -> Clean -> B。

states.ts
放 B、S0、S1。

actions.ts
放 setup、action、clean。

context.ts
放共享常量和类型。

helpers.ts
放底层实现。
```

---

## 15. 一句话约束

测试用例不直接编排流程。

测试用例只声明：

```text
B
Setup
S0
Action
S1
Clean
```

实际流程统一由 `runStateCase` 执行。

## 16. 测试报告生成约束

测试代码生成时，必须支持运行一次 Playwright 测试后自动生成一次测试报告。

也就是说，执行：

```bash
npm test
```

或：

```bash
npm run test:e2e
```

后，应自动生成一份本次测试报告。

---

### 16.1 报告生成方式

测试报告不应由每个测试用例单独生成。

报告生成应统一放在 Playwright reporter 或测试框架层。

推荐方式：

```text
runStateCase 负责记录阶段；
custom reporter 负责生成报告文件。
```

---

### 16.2 runner 必须记录阶段

`runStateCase` 中必须把以下阶段作为可识别步骤记录：

```text
B
Setup
S0
Action
S1
Clean
B after Clean
```

每个阶段至少应记录：

```text
阶段名
执行结果
耗时
错误信息
```

---

### 16.3 每次运行生成独立报告目录

每次测试运行都必须生成独立目录。

目录推荐格式：

```text
test-reports/
└── 2026年5月18日14时38分59秒/
    ├── summary.md
    └── result.json
```

目录名中不使用冒号 `:`。

报告标题中可以使用完整时间格式：

```md
# 测试报告：2026年5月18日14:38:59
```

---

### 16.4 summary.md 内容要求

`summary.md` 至少包含：

```text
本次测试时间
总用例数
通过用例数
失败用例数
通过用例列表
失败用例列表
失败用例的失败阶段
失败用例的错误信息
失败用例的阶段执行结果
```

---

### 16.5 成功用例记录要求

成功用例只需简单记录。

推荐格式：

```md
## 通过用例

| 用例 ID | 用例名称 | 耗时 |
|---|---|---:|
| auth.login.success | 普通成员可以使用正确邮箱和密码登录 ORF | 4.20s |
```

---

### 16.6 失败用例记录要求

失败用例必须展开记录。

推荐格式：

```md
## 失败用例

### auth.login.success

**用例名称：** 普通成员可以使用正确邮箱和密码登录 ORF

**失败阶段：** S1

**耗时：** 5.30s

**错误信息：**

```text
Error: expect(page).toHaveURL(/\/bounties$/) failed
```

**阶段结果：**

| 阶段 | 结果 | 耗时 | 错误 |
|---|---|---:|---|
| B | 通过 | 0.80s |  |
| Setup | 通过 | 1.20s |  |
| S0 | 通过 | 0.40s |  |
| Action | 通过 | 0.90s |  |
| S1 | 失败 | 2.00s | URL 不符合预期 |
| Clean | 通过 | 0.60s |  |
| B after Clean | 通过 | 0.50s |  |
```

---

### 16.7 result.json 内容要求

除 `summary.md` 外，还应保存结构化结果：

```text
result.json
```

`result.json` 是本次测试运行的结构化事实记录。

它用于给 `summary.md`、CI、统计脚本或后续分析工具消费，不用于人工阅读排版。

`summary.md` 应从 `result.json` 渲染生成，避免两份报告表达不同事实。

`result.json` 必须以一次 Playwright 运行作为根对象。

一次运行中可以包含多个测试用例结果，不应每个用例单独生成一个 `result.json`。

推荐结构：

```json
{
  "run": {
    "startedAt": "2026-05-18T14:38:59.000+08:00",
    "endedAt": "2026-05-18T14:39:04.300+08:00",
    "durationMs": 5300,
    "total": 1,
    "passed": 0,
    "failed": 1
  },
  "cases": [
    {
      "id": "auth.login.success",
      "title": "普通成员可以使用正确邮箱和密码登录 ORF",
      "status": "failed",
      "durationMs": 5300,
      "failedStage": "S1",
      "error": {
        "message": "Error: expect(page).toHaveURL(/\\/bounties$/) failed",
        "stack": "..."
      },
      "stages": [
        {
          "name": "B",
          "status": "passed",
          "durationMs": 800
        },
        {
          "name": "Setup",
          "status": "passed",
          "durationMs": 1200
        },
        {
          "name": "S0",
          "status": "passed",
          "durationMs": 400
        },
        {
          "name": "Action",
          "status": "passed",
          "durationMs": 900
        },
        {
          "name": "S1",
          "status": "failed",
          "durationMs": 2000,
          "error": {
            "message": "URL 不符合预期"
          }
        },
        {
          "name": "Clean",
          "status": "passed",
          "durationMs": 600
        },
        {
          "name": "B after Clean",
          "status": "passed",
          "durationMs": 500
        }
      ]
    }
  ]
}
```

其中每个用例至少包含：

```text
测试用例 ID
测试用例名称
测试结果
总耗时
失败阶段
错误信息
阶段执行结果
```

其中每个阶段至少包含：

```text
阶段名
执行结果
耗时
错误信息
```

`result.json` 不应默认保存完整的 `setupState` 或 `actionResult` 业务对象。

只有当字段明确安全、不会泄露敏感数据，并且对失败排查有直接价值时，才允许额外记录。

---

### 16.8 playwright.config.ts 要求

`playwright.config.ts` 中应配置 reporter。

推荐包含：

```ts
reporter: [
  ["list", { printSteps: true }],
  ["html", { open: "never", outputFolder: "playwright-report" }],
  ["./e2e/_framework/state-case-markdown.reporter.ts"],
],
```

---

### 16.9 一句话约束

每次执行 Playwright 测试，都必须自动生成一份带时间戳的测试报告。

成功用例简要记录。

失败用例完整记录失败阶段、错误信息和各阶段执行结果。
